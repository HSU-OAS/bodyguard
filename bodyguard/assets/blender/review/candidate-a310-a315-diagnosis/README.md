## 검증·보존

`node bodyguard/assets/blender/review/candidate-a310-a315-diagnosis/evidence-check.cjs`는28 byte-exact gzip 사본·이전1090파일 SHA, 원래 전체 간선·계약·실제 stdout·실패·미실행·잘못된 전달과 수정 후 정확한 대응을 검사합니다. Python11파일 strict E/F/I·format과 [회귀 시험](../../test_native_y_budget.py)7개를 실제 통과했습니다. 시험은 성별 순서/관측 최대치의 독립성, 불변성, 공통 한도·부호·float32, 비정상 입력과 직접 잘못된 생성 거부를 다룹니다.

초기 patch의 formatted context 불일치는 native A315 전에 실제 파일을 확인하고 보완했습니다. gzip을 `sed`로 읽은 binary 출력은 검증이 아니며 실제 압축 해제 후 소스를 읽었습니다. 실행된 native helper·보고서를 사후 수정하지 않았습니다. 최초 증거 checker는 의미 검사를 통과했지만 staged diff 검사에서 마지막 빈 줄을 지적했습니다. [최초 checker 사본](initial-checker-before-eof-format.cjs.txt.gz)과 [기계적 EOF 정리 기록](eof-format-record.json)을 별도 보존하고 한 줄만 정리한 뒤 검사했습니다. 디버깅·리뷰·문서화 스킬로 A310의 증거 한계, A313의 잘못된 여성 전달, A315 실제 수정 PASS와 남은 형상 FAIL을 구분했습니다.
