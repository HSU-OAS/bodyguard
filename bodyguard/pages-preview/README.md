# 웹캠 추종 테스트 미리보기

GitHub Pages 교체 후보의 진입 화면은 승인된 Figma 홈(21:4)을 재사용한다. 공개 적용은 별도 배포 승인 후다. 첫 화면의 인체는 정지 시안이며, `웹캠 체험`은 별도의 `inspection.html` 검수 화면으로 이동한다. 실제 웹캠 입력과 개발 후보 아바타를 사용하되 자세 판정·시범 동작·로그인·기록 저장·서버 API는 제공하지 않는다. 실제 사용자 정확도, 의료적 타당성, 아바타 최종 품질과 출시 승인을 의미하지 않는다.

- 웹캠 영상·원시 좌표는 브라우저에서만 처리하며 제품 API로 전송하지 않는다.
- 홈에는 동작 선택·패널 접기·세 가지 후보의 호버 영상이 연결된다. API가 없는 공개 검수본에서 계정·기록·신체 분석을 사용 가능한 기능처럼 표시하지 않는다.
- GitHub Pages 하위 경로에 맞춘 파일만 제공한다. Blob Worker에 문서의 동일 출처 CSP를 상속해 SDK의 외부 통신을 차단한다.
- 기본은 lite 포즈·얼굴 모델과 CPU 추론이다. 손목·팔은 포즈 모델로 추적하고, 손가락 세부 동작은 `손가락까지 추적`을 선택했을 때 추가한다. 상세 모드는 처리 부하가 늘어난다. 미리보기 전용으로 최초 모델 준비 제한을 20초로 두며 프레임 응답·정리 제한은 기존 5초를 유지한다.
- 정면 맞추기는 첫 신선한 단일 신체·머리 입력 이후 요청한다. 제품의 신뢰도·촬영 범위·입력 만료 기준은 완화하지 않는다.
- 검수용 머리 표시 보완과 관찰 범위 노출은 빌드 시 명시된 코드 위치에서만 적용한다. 원본 제품 코드는 수정하지 않는다.
- 여성·남성 아바타는 Git의 지정 커밋 원본을 SHA-256 확인 후 읽는다. 모델 세 개도 지정 SHA-256을 검증한다.
- GitHub Pages의 파일 배포는 이 검수 화면에 한정하며 전체 서비스 배포·운영 DB·이메일 공급자를 포함하지 않는다.

## 빌드

Node 24와 pnpm 12.6.0을 사용한다. 먼저 `bodyguard/frontend`에서 `pnpm install --frozen-lockfile`과 `pnpm assets`를 실행한다. 저장소에서 아바타 지정 커밋을 조회할 수 있어야 한다.

```bash
node bodyguard/pages-preview/build.mjs /absolute/path/to/new-empty-output
```

출력 경로는 존재하지 않는 새 디렉터리여야 한다. `/bodyguard/` 하위 경로, HTTPS, 브라우저 카메라 권한, 필요한 모델 파일을 사용하는 환경에서만 검수한다. GitHub Actions의 수동 워크플로는 결과물을 Pages에 배포하며 일반 제품 배포를 하지 않는다.

테스트는 브라우저의 합성 입력과 실제 사람의 웹캠 입력을 구분해서 기록한다. 실제 사용자의 체형·조명·카메라별 성능은 미검증이다.
