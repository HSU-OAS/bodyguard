# BODYGUARD 첫 출시 실행 계약

상태: 1단계 준비 게이트 충족 / 2단계 실제 구현·검증 진행 중(전체 게이트 미통과) · 2026-10-05

최근 실제 증거: [A316–A322 아바타 새 전문 원본·전체 재검증](../assets/blender/review/candidate-a316-a322-review/README.md). 최신 얼굴–목 연결·남녀 통일 무의상 백색 요구에 맞춘 후보의 원본/GLB 각각118기술 변형·34렌더와 Chrome3개를 재실행했다. 외형 P2·실제 사람/시범/리타게팅·목표 환경 검증은 남아 있으며 후보 미채택·개발A37·PR9 미병합이다. 이 결과를 2단계나 전체1~6단계 완료로 확대하지 않는다.

현재 증거·미완성 항목은 [1단계 통과 검토](stage1-gate.md), 다음 Story 순서는 [2단계 실행 명세](stories/stage2-first-flow.md)에 있다. PR 병합을 단계 통과나 출시 완료로 간주하지 않는다.

## 출시 완료의 뜻

성별에 관계없이 스트레칭이 필요한 사용자가 노트북 웹캠 한 대로 가입, 동작 직접 선택 또는 신체 확인에 따른 추천, 두 3D 아바타를 보며 코칭, 결과와 기록 확인을 혼자 마칠 수 있는 HTTPS 웹이다. 내부 검증과 운영 준비를 마친 뒤 **전문가의 완성된 웹 사용·실용성 검토만** 남아야 한다. 전문가가 동작 기준이나 미완성 기능을 대신 설계하는 단계는 포함하지 않는다. 뷰티·미용은 CEO 결정에 따라 첫 출시 이후 별도 범위로 둔다.

의학적 진단이나 치료 효과를 주장하지 않는다. 원본 영상과 관절 좌표는 브라우저 밖으로 보내거나 저장하지 않는다. 확인이 어려운 동작은 성공으로 판정하지 않되, 제품 화면에 확인 불가 부위를 강조하는 색을 칠하지 않고 필요한 촬영 위치만 간결히 안내한다.

## 진행 방식

단계는 순서대로 통과시킨다. 각 단계 안에서는 서로 독립적인 Story를 병행할 수 있고, 새 남성·여성 Blender 아바타 제작은 **1단계부터** 시작한다. 매 Story는 `명세·수용 기준 → 결정적인 테스트 하네스 → 구현 → 로컬 검증 → PR 검토`로 진행한다. 하네스는 가짜 카메라·동작 픽스처·실패 조건을 재현하는 개발/테스트 전용 장치이며 출시용 판정 우회가 아니다.

| 단계 | 결과물 | 다음 단계 통과 증거 |
|---|---|---|
| 1. 계약·근거·가능성 | 기존 PRD·설계·작업표의 충돌 정리, 출시/후속 범위, 동작별 근거·주의점·카메라 관찰 가능성, 첫 Story 명세·하네스, 새 Blender 모델 착수 | 확정·검증 필요·사업 결정이 구분되고 첫 코칭 동작 후보의 출처·촬영 시험 계획과 아바타 시각 기준이 있음 |
| 2. 첫 완성 흐름 | 가입·로그인, 직접 선택, 검증된 대표 동작 하나의 기준/사용자 아바타와 세밀한 코칭, 결과 | 실제 노트북에서 남녀 아바타 외형·부드러움과 정상·오류·가림·권한 거부가 검증됨. 가림을 성공 처리하지 않음 |
| 3. 코칭 확장 | 검증된 동작 목록, 신체 확인과 근거를 설명하는 추천, 동작별 애니메이션·판정 | 출시 동작 **각각** 근거·촬영 조건·오류/가림 테스트와 실제 사용 시험을 통과함 |
| 4. 서비스 완성 | 기록, 계정 복구·탈퇴·삭제, 개인정보 안내, 접근성, 실패 복구, 확정된 부가 기능 | 처음 방문한 사람이 도움 없이 가입부터 코칭·기록 확인·데이터 관리까지 마침 |
| 5. 배포·운영 | HTTPS, 라이선스, 보안, 백업/복구, 관측·운영 절차와 실제 배포본 | 배포 주소에서 전체 흐름을 검증하고 운영상 치명적 결함이 없음. 서버·시크릿·운영 DB·배포·비용은 별도 CEO 승인 필요 |
| 6. 내부 출시 검증 | 다양한 노트북·조명·체형·촬영 범위의 오판정 시험, 사용성·성능·보안 회귀와 수정 | 위험한 오통과와 치명적 오류가 해결됨. 남은 필수 작업이 전문가의 실용성 검토뿐임 |

에픽은 사용자 가치의 분류이고 위 단계와 일대일 대응하지 않는다: E1 시작·계정, E2 동작 탐색·선택, E3 신체 확인·추천, E4 **현재 시제품을 대체하는** 남녀 Blender 3D와 두 화면, E5 세밀한 실시간 코칭, E6 결과·기록·데이터 관리. E4는 1단계에서 모델·리그·동작 기준을 시작해 이후 실제 브라우저에서 반복 검수한다.

## CEO 검토와 Git 권한

CEO는 기술 스택이나 일일 구현 방법을 정할 필요가 없다. CTO는 각 단계의 시연, 테스트 결과, 남은 위험과 완료 기준에 대한 증거를 보고하고 기준을 충족했을 때 다음 미완료 Story로 진행한다. CEO는 결과를 검토해 재작업 방향을 제시할 수 있다. 사진과 비교한 아바타 외형은 2단계 통과 증거에 포함한다. 중요한 범위·안전·개인정보·사업 결정은 실행 전에 권장안과 정확한 범위·비용·위험·복구 계획으로 별도 승인을 요청한다.

CEO의 2026-10-01 [운영 규칙](operating-rules.md)이 이전 건별 Git 승인을 대체한다. 1~6단계 범위 안의 Story 시작·명세·하네스·구현·검증·커밋·푸시·PR·리뷰 보완·다음 Story 진행은 사전 승인되었다. 필수 검증 통과·미해결 P1/P2 없음·최신 diff/충돌/체크 확인을 충족한 PR만 merge commit 병합한다. 최신 `origin/main`의 새 `codex/*`, 한 PR에 한 목적, `main` 직접 푸시 금지·브랜치 유지 원칙은 그대로다. 중요한 범위·안전·개인정보 변경과 비용·계정·시크릿·운영 DB·배포·출시는 별도 승인이다. 단계별 실제 완료 기준은 낮추지 않는다.

## 1단계 첫 Story: 출시 계약 정합화

범위: 기존 문서와 CEO의 최신 결정을 대조해 출시 필수/후속/검증 필요를 표시하고, 동작 근거·카메라 시험 및 아바타 품질 Story가 시작할 수 있는 수용 기준을 만든다. 이 Story 자체는 동작 임계값이나 의료 효과를 확정하지 않고, 제품 코드·운영 환경을 변경하지 않는다.

하네스/검증: 문서의 사용자 흐름에서 `직접 선택`, `추천`, `남녀 두 아바타`, `가림 시 거짓 통과 방지`, `기록`, `계정`, `뷰티 후속`을 각각 추적한다. 기존 확정 기능을 임의로 삭제하지 않았는지, 미정 수치를 확정처럼 쓰지 않았는지, 단계별 통과 증거와 Git/운영 승인 경계가 모순되지 않는지 점검한다. `git diff --check`와 문서 링크 검사를 통과해야 한다.

기존 PRD의 5분 자세 이탈 알림, 50분 착석 알림, PDF 리포트, LLM 요약, 변화 탐지는 삭제하지 않는다. 첫 출시 포함 여부는 기존 확정 사항과 비용·검증 가능성을 대조해 별도 결정으로 남긴다. 결정 전에는 후속으로 단정하거나 완료로 표시하지 않는다.

## 기존 문서와의 충돌 지도

아래 항목은 첫 Story에서 반드시 정합화한다. 기존 문서의 기술 시제품 설명은 그 시점의 사실로 남기되 출시 요구로 오해하지 않는다.

| 기존 위치 | 현재 충돌 | 적용할 출시 기준 |
|---|---|---|
| `prd.md` §1 | 앉아서 일하는 대학생·직장인만을 주 대상으로 적음 | 성별과 직업에 관계없이 스트레칭이 필요한 사용자 |
| `prd.md` FR-A-01~03, `design.md` §9, `tasks.md` P3 | 내 스켈레톤 + 정적 마네킹, 움직이는 아바타는 추후 | 남녀 외형 중 선택한 두 고품질 3D 아바타가 기준 동작과 사용자 동작을 표시. 기존 것은 시제품 |
| `prd.md` FR-U-04, `open-questions.md` Q-15 | 게스트에게 측정·스트레칭 허용 제안 | 공개 소개·미리보기만 게스트. 개인 신체 확인·코칭·기록은 로그인 후 |
| `prd.md` FR-M-05·FR-A-01 | 확인 불가 부위를 회색으로 강조 | 내부 판정은 보류하되 제품 아바타에는 확인 불가 색을 칠하지 않고 촬영 위치를 안내 |
| `prd.md` FR-S-01 | 8개 후보의 초기 각도·시간이 자동 통과 조건처럼 보일 수 있음 | 출처·올바른 수행법·주의점·웹캠 촬영 시험을 거쳐 동작별 `실시간 코칭 / 안내만 / 제외`로 분류. 수치는 검증 전 확정하지 않음 |
| `prd.md` FR-V, `tasks.md` P0~P7 | 추천과 직접 선택의 두 입구, 두 아바타의 연속 흐름이 없음 | 두 진입 경로와 결과·기록까지의 전체 웹 흐름을 수용 기준으로 삼음 |
| `prd.md` FR-N·FR-R, `constitution.md` P6 | 알림·PDF·LLM 요약·변화 탐지의 기존 확정 범위 | 삭제하지 않고 첫 출시 포함 범위를 별도 확인. 비용·시크릿이 필요한 것은 별도 승인 |

이 표가 PRD·설계·작업표 전체 수정의 대체물은 아니다. 1단계에서 각 원문 위치를 갱신하고, 남은 충돌을 표시한 뒤에만 정합화 Story를 완료한다.
