## 된 것

| 기능 | 상태 | 어떻게 확인했나 |
|---|---|---|
| 몸 33점 스켈레톤 (2D·3D) | 동작 | 사람이 직접: 상반신, 몸 기울이기, 화면에 들어오면 다리까지 |
| 손가락 21점과 제스처 | 동작 | 사람이 직접: 엄지척, 손가락이 손목에 붙음 |
| 필요한 관절이 화면 밖일 때 안내 문구 | 동작 | 사람이 직접 + E2E(가짜 카메라) |
| 둥근 얼굴: 머리 방향·눈 깜빡임·입 벌림 | 만듦 | 단위 테스트, 가짜 얼굴 상태로 2D·3D 확인. **사람 얼굴로는 확인 전 — 받는 사람이 처음 확인한다** |
| 디버그 패널 | 동작 | fps, 몸·손·얼굴 추론 시간, 포즈 모델 크기, 손가락·얼굴 켬/끔 |

자동 검사(2026-09-27): 단위 테스트 55개, E2E 1개, 타입 검사, Biome, 빌드 모두 통과. 맥(크롬)에서만 돌려 봤다.

## 알아 둘 것

- 둥근 머리는 측정 시작 뒤 얼굴이 처음 보인 **2초 동안의 방향을 정면**으로 삼는다. 그동안 화면을 보고 있어야 한다 (ADR-0017)
- 카메라 쪽으로 오가는 앞뒤 움직임은 정면 카메라에서 부정확하다. 목 전방 측정(M-4)과 같은 문제라 옆모습 정답지 실험(design §5.7)이 중요하다
- fps: 녹화에서 heavy + 손가락으로 26fps였다(몸 19.3ms, 손 14.1ms). 얼굴 모델을 더한 뒤로는 아직 재지 않았다
- 새 라이브러리를 처음 import하면 Vite가 의존성을 다시 묶으면서 열린 탭에 R3F 오류가 날 수 있다. 새로고침하면 사라진다 (ADR-0015)
- 제품 화면에는 카메라 영상을 보여주지 않는다. 지금 왼쪽 카메라 화면은 개발 확인용이다 (FR-V-02)
- 레포 루트의 `docs/`(차터·PRD·WBS)는 과목 제출물이다. 여기서 고치지 않는다

## 규칙 요약

자세한 건 `AGENTS.md`.

- `main`에 직접 푸시하지 않는다. 작업 브랜치 → PR → 상대방 리뷰 → 머지
- 커밋 메시지는 한국어 문장이고, 한 커밋에 한 가지 일만 담는다
- 영상과 관절 좌표를 밖으로 보내거나 저장하지 않는다
- `[미정 Q-nn]`, `[PO 제안]`은 확정이 아니다. 만들기 전에 서로 확인한다

## AI에게 처음 줄 말

```
이 폴더는 Bodyguard(웹캠으로 앉은 자세를 재는 웹 서비스)의 개발 폴더야. 팀원에게서 오늘 넘겨받았어.
나는 프런트엔드와 AI·데이터(포즈 파이프라인, 판정, 변화 탐지)를 맡았어.

1. AGENTS.md를 먼저 끝까지 읽고, 거기 적힌 규칙을 이번 대화 내내 지켜줘.
2. 그다음 docs/handoff.md, docs/tasks.md의 "진행 상황", docs/open-questions.md, frontend/README.md를 읽어줘.
3. 아직 코드는 고치지 말고 아래를 정리해서 알려줘.
   - 지금까지 만들어진 것, 실제로 확인된 것과 아직 확인 안 된 것
   - 내 컴퓨터에서 데모를 실행하는 순서 (필요한 설치 포함)
   - 내가 맡은 일에서 다음에 할 작업 3개와, 그 전에 정해야 하는 미정 항목(Q 번호)
4. 문서에 없는 건 추측하지 말고 "문서에 없음"이라고 말해줘.
```

정리를 받은 뒤에는 "데모를 실행해줘", "pnpm test와 pnpm test:e2e를 돌려서 결과를 알려줘"처럼 하나씩 시킨다.
