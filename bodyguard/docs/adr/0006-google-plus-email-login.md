# ADR-0006. 로그인은 구글과 이메일 가입, FastAPI에서 직접 만든다

상태: 확정 (2026-09-26) · 근거: 원문 33, 42

## 맥락
기록이 날짜별로 쌓이고 다른 PC에서도 이어지려면 사용자를 구분해야 한다.
Supabase Auth를 쓰는 안(PO 제안)과 직접 만드는 안을 두고 비교했다.

## 결정
- 구글 로그인과 이메일·비밀번호 가입을 둘 다 넣는다
- 인증은 FastAPI에서 직접 만든다
- 이메일 가입은 메일 인증이 필수다. 팀 공용 Gmail(앱 비밀번호, SMTP)로 인증 코드를 보내고 서버에서 대조한다
- 비밀번호 재설정도 같은 메일로 한다

## 근거
- 사용자가 둘 다 필요하다고 했다 (원문 33)
- 팀이 다른 프로젝트에서 Gmail로 인증 메일을 보내고 서버에서 대조하는 방식을 해 봤다 (원문 42)
- 외부 인증 서비스에 기대지 않는다. 무료 티어 일시정지 같은 걱정이 없다

## 결과
- 비밀번호 해시(argon2id), 코드 만료·시도 제한, 요청 횟수 제한을 직접 만든다 (design §13)
- 요청 횟수를 제한하지 않으면 팀 Gmail이 스팸 발송에 쓰여 정지될 수 있다
- 개인 Gmail의 하루 발송량(약 500통) 안에서 운영한다
- 구글 OAuth 동의 화면이 '테스트' 상태면 등록한 사용자(최대 100명)만 로그인할 수 있다
- DB에 `users`, `email_codes` 테이블을 둔다 (design §11)
