# S2.M1 — 목 옆 기울이기 관찰값 계산

2026-10-08 · 기준 main da32cf5 · D2-M 준비 · FR-M-01/02/07·FR-S-01·ADR-0012

## 목적과 경계

첫 후보의 실제 수행 라벨과 대조할 순수 이미지 평면 관찰값을 구현한다. 귀7/8·어깨11/12의 방향 차이, 귀-어깨 간격과 머리 중심의 어깨 축 상대 위치를 계산한다. 코0를 포함한 기존 머리·어깨 관찰 조건을 지킨다. 계산값은 경추 각도·목 전방·통증·손 압력·올바른 수행법·오류 분류가 아니다. Q-05/06과 실제 참여자 검증을 대신하지 않는다.

선분 방향은 7→8,11→12이며 y를 위쪽으로 잡은 영상 평면에서 부호를 정의한다. 상대 각도는 정규화 선분의 cross/dot에 atan2를 적용한다. 간격과 중심 위치는 **투영된 어깨 폭에 대한 무차원 비율**이며 cm/m·경추 길이가 아니다. 필드 이름에도 간격 단위를 적는다. 프레임별 파생값 역시 브라우저 임시 메모리에만 두며 기록/API/로그로 보내지 않는다.

[Google 공식 관절 목록](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker)은 33개 추정 위치와 관절 번호를 설명한다. [Web 결과 설명](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js)은 x/y를 영상 너비/높이로 각각 정규화한다. 그러므로 각도 계산은 원래 프레임의 가로·세로 비율을 복원해야 한다. 이 보정은 투영 기하이며 해부학적 각도 복원이 아니다.

[CUH 안내](https://www.cuh.nhs.uk/patient-information/neck-exercises-and-advice/)의 Mobility Image2를 기존 후보 설명과 대조했다. 숫자 처방은 비어 있으며 문헌만으로 웹캠 통과 각도·시간을 만들지 않는다. 다른 손 보조 스트레칭 변형과 혼합하지 않는다. 원문 이미지/코드 복제0.

## 수용 기준·검증 계획 (구현 전)

- 원래 generation/sequence/capture 시각과 동일한 한 사람·한 image 결과만 계산한다. confidence와 최대 관찰 나이는 호출자가 명시하며 출시 기본값을 만들지 않는다.
- generation/sequence는 보존하는 식별자이며 이 순수 함수가 계정 소유권·재검출 동일인·입력 정렬을 검증하지 않는다. 기존 source/controller의 현재 소유·순서 장벽과 실제 검증이 후속 연결의 선행 조건이다. 너비/높이는 CSS 표시 크기가 아니라 해당 추론 입력의 실제 캡처 크기다.
- 실제 캡처 너비/높이·입력의 좌우 반전 여부가 명확해야 한다. 비정상 크기/시각/점수·미래/만료 입력·필수 부위 가림/화면 밖·미검출/복수·퇴화 선분은 값을 내보내지 않는다.
- 귀와 어깨의 상대 선분 각도는 카메라 평면의 공통 회전에 불변이다. 영상 비율·이동·균일 축척·좌우 반전 복원과 해석 가능한 부호를 합성 픽셀 기하로 검증한다. 여유 있게 보이는 전신이나 관찰 못 하는 하반신은 머리·어깨 조건을 바꾸지 않는다.
- 원본 입력을 수정/보관하지 않으며 결과는 동결된 숫자/고정 상태뿐이다. DOM/SDK/Three/시계·저장소/로그/서버·타이머·판정 프로그램 의존성0. native/공개 consumer는 이 Story에서 추가하지 않는다.
- 단위 시험: 알려진 투영 기하와 숫자 경계·필수 관절별 가림·변형 불변성·동결·추정 한계. 전체 FE 회귀, Biome, tsc, production build/guard·공개 byte 동일·diff 검사를 실제 실행한다.
- 실제 사람/native 양성/임상 라벨·관찰자 비교는 미실행으로 구분한다. 실패 원본·시험 당시 HEAD/실제 소스 SHA와 미실행을 보존한다.
