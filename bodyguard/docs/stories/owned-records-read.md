상태: 좁은 로컬 구현·검증 완료, 조건부 PR 게이트 진행 중. 기준 main: `9882224cf78575ecbee5a051f6293048494bd130`.

## 문제와 범위

공개 웹의 기존 `/records` 목록·상세·기간 삭제는 로그인 화면 상태와 각 요청의 현재 쿠키를 함께 검증하지 않는다. 다른 탭에서 계정이 바뀌는 동안 이전 계정 화면이 새 계정의 기록이나 삭제 대상을 받을 수 있다. BroadcastChannel·focus 갱신만으로 요청 중 전환을 원자적으로 막을 수 없다.

- 기존 계정·세션 확인 방식(`/me → CSRF → /me`)을 기록 흐름에 적용하고, 실제 API가 요청 헤더의 기대 계정과 현재 쿠키를 같은 트랜잭션에서 비교한다. 헤더는 소유자를 선택하지 않는다.
- 기존 기록 API 호출과 데이터 형식·멱등성·서명 삭제·기간 cutoff·페이지 이동·키보드 흐름은 유지한다. 선택적 헤더 없는 기존 호출도 현재 쿠키의 소유 기록만 처리한다.
- 목록·상세 결과와 삭제 확인은 커밋된 로그인 authority에 묶는다. 계정 전환·취소·만료 후 늦게 온 응답은 표시하지 않는다.
- 401은 기존 로그인 갱신 경로를 유지한다. 403은 기록과 삭제 확인을 닫고 명시적인 계정 재확인을 요구한다. 409 삭제 대상 변경은 기존 재확인 경로를 유지한다. 삭제 결과가 불확실하면 성공으로 표시하거나 자동 재시도하지 않는다.
- 저장 API도 동일한 선택적 기대 계정 헤더를 검증한다. 기존 저장 클라이언트가 이미 보내는 헤더의 서버 검증 누락을 함께 닫는다. 새로운 기록 생산·실시간 코칭 공개는 하지 않는다.
