# S4.2 — 본인 수행 기록 목록·상세 화면

로컬 구현·검증 통과 / PR 게이트 진행 · 선행 main afc044b(PR #20) · FR-R-03 / FR-U-04 / NFR-08

## 사용자 흐름과 디자인 계약

내 시작/상단 기록 메뉴 → 최근 7일 수행 목록 → 기간 조회 → 다음/이전 페이지 → 개별 수행 상세 → 같은 기간 목록/내 시작으로 복귀한다. 로그인 본인의 실제 기록 API를 읽으며 화면은 가짜 기록을 만들지 않는다. 기록 저장은 실제 코칭 adapter의 후속 연결이다.

기존 백색 바탕·청록 강조·시스템 글꼴·48px 제어 높이·10px 둥근 모서리·얇은 경계를 유지한다. 주 작업은 기간 내 수행 확인이며 효과 점수·랭킹·임의 개선율/추이 차트를 넣지 않는다. 목록은 시각/동작 식별자/완료·중단·건너뜀/관찰 시간·반복의 비교 가능한 표, 상세는 시작/종료·수행 요약·규칙 버전이다. 미등록 동작 식별자는 새로운 출시 동작 안내로 연결하지 않는다.

완료는 수행 흐름 종료일 뿐 올바른 자세나 효과의 인증이 아니다. 시간/반복을 0에서 지어내지 않는다. 명확한 빈 기간, 로딩, 오류+다시 조회, 없는/타인 상세, 세션 재확인/종료를 처리한다. 카메라·원본 영상·좌표·브라우저 영구 저장은 쓰지 않는다.

## 구현 계약

- 기존 SessionGate/AuthProvider로 보호. /records 및 /records/:UUID. 읽기 401은 계정 재확인으로 개인 화면을 닫는다. focus/Back cache/계정 변경으로 남은 응답이 개인 화면을 되살리지 않는다.
- ISO 날짜 입력은 유효한 실제 날짜와 시작≤종료를 검사한다. 사용자의 브라우저 시간대 날짜를 aware UTC API 기간(start 포함/end 제외)으로 변환한다.
- 목록 page size20/offset≤10000을 지키며 조회 시작 시각을 고정해 현재 기간 페이지에 새 기록이 끼는 것을 줄인다. 새 조회는 페이지를 초기화한다. 상세 복귀는 기간을 유지한다.
- API 응답은 실제 생성 타입과 런타임 구조 검사를 사용한다. 원문 서버 오류/식별자로 HTML을 만들지 않는다. 인증 쿠키·no-store·15초 timeout·취소를 사용하며 실패를 빈 목록으로 숨기지 않는다.
- 날짜 필터 입력/페이지 변경/새 조회는 이전 기간/페이지 내용을 잠깐 보여주지 않는다. late response와 StrictMode 중복 effect를 취소·폐기한다.
- 단일 완료 화면뿐 아니라 키보드·포커스·폭 700px의 노트북 좁은 창·긴 식별자·대량/빈 목록을 검증한다. 모바일 지원 범위 추가 아님.

## 하네스와 통과 기준

1. 순수/API 계약: 잘못된 날짜·기간/ID·응답, HTTP 실패, timezone 기간 변환, fetch same-origin/no-store/취소.
2. DOM: 게스트/503 보호, 로딩→빈 상태/목록, 기간/페이지/상세/복귀, 없는 상세/오류/재시도, 원시 오류 비반사, late response/계정 재확인 때 개인 데이터 폐기.
3. 실제 격리 PostgreSQL·FastAPI·production Chrome: mock 메일로 가입, 실제 API에 명시된 합성 요약만 생성, 실제 목록·기간·페이지·상세·계정별 소유권·로그아웃/Back·오류 복구. 외부 통신 차단, camera0·storage0. 실제 운동/메일 공급자 검증으로 세지 않는다.
4. frontend 전체 회귀·Biome·typecheck/build·production 후보 차단·backend 정적 검사/관련 회귀·diff 리뷰.

실패/실행 결과·PNG와 report는 실행마다 다른 경로에 보존한다. 기존 아바타 증거는 변경하지 않는다. 운영 migration·배포·실제 참여자·아바타 수정은 이번 범위 밖이다. 기록 삭제/탈퇴/1분 요약·PDF·변화 탐지·LLM 부가 기능과 Stage2/3 코칭 의존성은 별도 미완료로 유지한다.

## 실제 구현·검증 결과

내 시작/상단 수행 기록 → 기본 최근7일 목록 → 로컬 날짜 기간 조회 → 다음/이전 페이지 → 상세 → 같은 기간 목록/내 시작을 실제 API에 연결했다. 새 페이지/기간은 이전 결과를 즉시 숨기고, 새 조회의 cutoff를 고정하며, 페이지 이동 완료 후 결과 제목에 키보드 초점을 준다. 실패는 빈 기록이 아닌 복구 상태이며 401은 계정 재확인으로 개인 화면을 닫는다.

API/DOM 초기 red는 미구현 모듈 import 실패와 로컬 날짜를 UTC로 변환한 요청의 잘못된 문자열 기대값 1건이었다. 테스트를 실제 timezone 계약에 맞춰 보완했다. 리뷰에서 타입이 문자열이 아닌 outcome·불가능한 캘린더 timestamp를 거부하도록 강화했고, 결과 제목의 공유 CSS 우선순위 경고를 정리했다. 기준을 완화한 것이 아니다.

최종 frontend 242건/20파일 통과, 별도 America/New_York API 계약15건(DST25시간 일 경계 포함) 통과, Biome73파일 경고0·TypeScript·Vite build·production 후보/미연결 엔진 문자열0·diff check 통과. 실제 격리 PostgreSQL18.6 backend 전체179건 통과, 의존성 deprecation 경고1건은 남았다. Ruff check/format20파일·mypy6소스 통과.

실제 production Chrome RW-01~06은 마지막 실행 모두 통과했다. 실제 가입/쿠키·API·SQL을 사용하며 메일과 요약만 합성 데이터다. 로딩/빈/상세/긴 식별자/기간/페이지/타인 상세404·계정 종료/Back/late response·읽기 오류 재시도를 확인했다. 카메라·모델 요청·브라우저 저장·외부 요청은0이다. [실제 report·PNG와 실패/보완 기록](../review/stage4-records/README.md)을 보존했다. 실제 운동·실메일·운영 검증으로 세지 않는다.

범위 리뷰: UUID 경로 제한·응답 필드/범위/출처 검사·React 문자 렌더링·same-origin/no-store·15초 timeout·취소·기존 계정 재확인 경계를 확인했다. scoped 미해결 P1/P2 없음. 서버 페이지는 snapshot이 아니므로 동시 과거 기록 저장/삭제 중에는 최신 재조회가 필요하다. 제품 동작명은 검증된 카탈로그/버전 연결 후 제공해야 하며 현재 식별자·규칙 버전을 임의 동작 안내로 대체하지 않았다.

이 Story는 기록 조회 화면이다. 기록 삭제/탈퇴·1분 자세 요약 대시보드·PDF/변화 탐지/LLM 범위 결정·실제 코칭 요약 생성·출시 동작명 매핑·Stage2/3 실측/아바타는 미완료다. 전체4단계와1~6단계 완료 아님. 다음 독립 구현은 합의된 본인 기록 삭제·계정 데이터 관리 계약/API다.
