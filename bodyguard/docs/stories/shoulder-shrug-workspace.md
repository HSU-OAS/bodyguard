# S3.C5 — 어깨 상승 표시와 두 아바타 실행 연결

2026-10-17 · PR162 merge `25429c004305de0393935f0b0bd470ecb0e0fd97`의 최신 main.

## 범위·화면 계약

S3.C4의 어깨 판정을 기존 두 아바타 실행 화면에 연결한다. 새 메뉴/디자인 개편 없이 기존 흰 공간의 왼쪽 사용자·오른쪽 Blender 단계 시범, 화이트/블루·둥근 컨트롤·초점/오류/종료·명시 재시도를 재사용한다. 어깨 동작명·양쪽 단계·짧은 오류 안내로 기존 목 실행/기록 계약을 깨지 않는다. 임상 프로필 기본값/공개 적격 승격은 없다.

현재9방향 rig만으로 재현하지 못하는 양쪽 어깨 상승은 원래 남녀 GLB의 정확한 clavicle→upperarm 연결과 골반 폭을 사용한다. 명시 시작/움직임 맞추기 이후 같은 세대의 새 준비 프레임으로 표시 기준만 잡고, 관찰된 골반 기준 어깨 높이 변화로 두 쇄골의 swing을 각각 구동한다. 관절/위치/스케일·geometry·정규/8가중치·원본/GLB/시범은 바꾸지 않는다. 이는 image-plane 표시용 재타기팅이지 실제 쇄골 회전 측정이나 임상 기준선/서버 저장이 아니다. 임의의 부족한 부위를 정답 자세로 복원하지 않는다.

## 수용 기준·하네스

1. 실제 남녀 보존 GLB에서 양쪽/한쪽 어깨 상승·복귀와 팔 방향을 독립 재현한다. 명시 요청 전/준비 확인 전·가림/다인/만료/다른 세대에는 어깨 표시 근거가 없다. 원래 노드/163관절·8가중치/전체 vertex 속성·원본/시범 독립성과 종료/새 세대 초기화를 확인한다. 단위 기하와 실제 GLB 결과를 구분한다.
2. 실제 실행 UI에서 준비→양쪽 수행/유지→복귀·결과, 보상 오류/표면·적응하는 단계 시범·일시정지/재개/취소·늦은 권한/숨김/401/자원 해제를 확인한다. 현재 same-frame 판정/시각/소유권을 유지하고 확인 불가는 타이머/성공/오류 색을 새로 만들지 않는다.
3. 원래 목 코칭/표면/기록 계약과 추천/직접 선택을 회귀 검증한다. 원래 build/고지·production guard·Biome·diff와 실제 Chrome 후보 화면을 검수한다. 생성 카메라/관절·시험 프로필·모의 계정/API와 실제 SDK 빈 장치 경로·실제 GLB/WebGL의 범위를 구분하고 실패를 보존한다.
