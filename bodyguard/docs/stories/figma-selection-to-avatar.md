# 피그마 동작 선택에서 시범 후보 연결

## 범위와 수용 기준

- 피그마 홈 개발 검수(`/dev/figma-home`)에서 사용자가 동작을 선택하고 `코칭 화면 보기`를 누른 경우, 해당 동작에 기존 시범 후보가 있으면 코칭 화면의 시범을 자동으로 연다. 이 클릭은 시범 후보를 요청하는 명시적 사용자 동작이다.
- 기존 직접 코칭 주소는 자동으로 3D 자원을 열지 않는다. 후보가 없는 동작·잘못된 동작·중복 요청은 임의 시범으로 대체하지 않는다. 사용자는 시범을 닫거나 다시 열 수 있다.
- 로그인 복귀 과정에는 동작 ID와 고정 값 `preview=1`만 허용하며 중복·임의 문자열은 버린다. 계정 정보나 신체 정보는 URL에 넣지 않는다.
- 카메라는 자동으로 켜지지 않는다. 판정·기록·추천을 공개하거나, 아바타 원본·애니메이션·성능 기준·운영 환경을 변경하지 않는다.

## 검증 기록

Figma HOME-01과 기존 동작 카드·코칭 화면 구조를 확인했다. 로컬 Chrome에서 가상 계정·모의 API로 `목 옆 늘리기 선택 → 코칭 화면 보기`를 실행했고, 오른쪽 시범 아바타 후보가 표시되고 카메라는 꺼진 상태인 것을 확인했다. 왼쪽 사용자 아바타는 카메라를 켜지 않아 나타나지 않았다. 이 시험은 실제 사람 추종·정확도·의학적 동작 검증이 아니다.

처음 단위 시험은 명시적으로 요청한 GLB 읽기까지 네트워크 요청이 없다고 잘못 가정해 실패했다. API 호출을 구분하는 검사로 수정하고 관련 테스트 51건을 다시 통과했다. 실제 시험 시 카메라 권한은 요청하지 않았다.

최종 재검증: 프런트엔드 전체 129개 파일·2,155개 테스트, TypeScript, Biome, 공개 빌드와 개발 전용 코칭 자원 제외 검사를 통과했다. 본 작업의 기본 공개 번들에는 개발용 동작 선택·코칭이 추가되지 않았다. 실제 사용자 카메라·추종·정확도는 검증하지 않았다.
