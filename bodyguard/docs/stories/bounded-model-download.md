# S3.C9 — 선택 모델의 제한된 동시 준비

기준 main `fb8635ad98debc009329b08ef3c3516666e92e37`, `codex/bounded-model-download`.
FR-M-02/07·NFR-07/08. 카메라 준비와 기본 Worker 코칭 자원의 시작 비용을 줄이는 기존 범위의 기술 보완이다.

## 확인한 경로와 권장안 — 구현 전

현재 `prepareOwnedModelAssets`는 몸→얼굴→손을 순서대로 읽고 검증한다. 세 요청의 초기 응답 지연이 누적된다. 선택된 고정 파일만 최대3개 함께 읽어 독립 대기를 겹친다. 모델 종류/heavy 기본값·원본 byte·SHA256·same-origin/credentials omit/no-store·SDK/CPU 복구·5초 Worker init/inference/cleanup과 전체30초 모델 준비 한계는 유지한다. 새 파일/외부 요청/캐시/스토리지/계정/API·시크릿·아바타/GLB/조형·판정/임상 수치·공개 UI 변경은 없다.

선택은 시작 시 복사하고 disabled 파일은 읽지 않는다. 최대 live 결과 buffer는 기존과 같은 선택 모델 용량의 합이며 동시에 읽는 응답/네트워크의 내부 메모리까지 같은 것으로 단정하지 않는다. 어느 읽기/검증 실패·취소·기한 초과도 전체 준비를 거부하고 나머지 선택 요청을 취소한다. 실패/늦은 반환은 Worker init·관찰·기록 권한을 만들지 않는다. 중복 자동 재시도와 다음 후보 모델 대체는 없다.

## 하네스·수용 기준

- R1: 모든 선택 파일 요청이 첫 응답 전 시작되고 결과가 역순으로 완료돼도 정확한 body/face/hands buffer에 연결된다. 선택이 바뀌어도 시작 시 선택을 유지한다. body만 선택하면1개, face/hands 선택은 각각 포함하고 최대3개다.
- R2: 변조/외부/잘못된 응답·지연·abort에서 준비를 거부하고 시작한 모든 reader/fetch의 신호를 회수한다. 늦은 각 반환의 body를 닫고 새 권한/추가 모델 요청을 만들지 않는다. 기존 deadline/바이트 상한·무결성·예외 문구 검사를 유지한다.
- R3: 실제 고정 원본/SDK/Chrome의 이전 source와 후보 source를 별도 출력에 보존한다. 세 모델 각각900ms 제어 응답 지연의 전체 준비 시간·요청 겹침을 비교한다. 기본/느린6초/취소/변조와 normal/CDP4×를 구분하며 각각 새 context를 사용한다. 속도 비율을 실제 네트워크/OS 부하/저사양 노트북으로 일반화하지 않는다.
- R4: 공개 모델 byte/SHA/전체 frontend·타입/Biome·원래 notice build/production guard·diff·작성자 리뷰와 최신 원격 HEAD/main/CLEAN/체크를 실제 통과한다. 초기 실패·기존 source/원본/이전 증거를 보존한다. 미해결 scopedP1/P2가 있으면 병합하지 않는다.

testing-strategy는 결정적 동시성/회수 unit → 원본 CLI → 실제 SDK 준비/첫 빈 추론/종료를 사용한다. debug는 실제 전후 비용을 분리하고 code-review는 메모리 상한·부분 실패·늦은 반환·동시 요청의 scope를 검토한다. 독립 리뷰/전문가 승인은 아니다.
