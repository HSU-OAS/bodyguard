# S6.14 — 첫 3D 렌더/SDK 비용 분리와 렌더 준비 보완

2026-10-09 · 최신 main600f930(PR97) · 비공개 성능/자원 수명, 공개 디자인 변경 아님

## 목적·가설

S6.13에서 Worker도 정상250ms/4×900~917ms RAF 공백을 보였다. 첫 3D 렌더 비용과 main SDK의 동기 처리 비용을 분리해야 한다. 과거 PR90 실패13건의 원인으로 단정하지 않는다.

FR-A-01/02/03·FR-M-01/02/07·NFR-07/08. 실제 같은3모델·A37 원본 남녀 GLB·640×480 카메라·main/explicit Worker를 유지한다. 기록은 단계별 첫3회 시작/끝 기술 시간만으로 제한하고 이미지·몸/얼굴/손 결과·행렬·계정은 접근/기록하지 않는다.

## 수용 기준 / 하네스

- [x] 기존 경로에서 첫 renderer.render와 main의 body/face/hands 메서드 비용을 나눠 계측했다. Worker 내부 SDK 시간을 main 메서드 시간으로 지어내지 않는다.
- [x] normal/4× CDP·남녀·main/Worker의 고정8조건과 준비 유무를 교차한16조건·fresh context·retries0을 실행했다. 준비 후5초 내 세 번째 delivery 관찰은 기존 nativeCloses/인증26건 gate나 실제 사람/노트북 검증으로 세지 않는다. 중간 대조군6047ms 실패도 보존한다.
- [x] renderer 소유자가 같은 두 모델의 shader와 첫 GPU 업로드를 ready 이전에 명시적으로 준비하도록 보완했다. shader만 준비한 첫 시도는 불충분했다. 기본 호출·모델/재질/조명/화질은 유지했다. 실제 브라우저에서 준비 유무를 대조했다.
- [x] 준비 취소·부분 실패·늦은 준비 완료·동기/비동기 오류 때 pair/SDK/카메라를 회수했다. 준비 성공만 ready가 되고 취소가 이전 세대를 재활성화하지 않는다. 명세→실행형 RED5건→구현→전체 FE1404 GREEN과 실제 Chrome 취소2건을 구분한다.
- [x] 최종 타입/Biome/FE·build/public guard·소스/원본/공개 byte 보존·diff·증거 검증과 작성자 리뷰를 실행했다. 첫/실패/최종 browser bundle과 fixture는 별도 디렉터리로 보존했고 최초 unit test 전체 스냅샷 부재는 검토 기록에 명시한다. 기술 증거103·소스13의 lossless/current 검증을 통과했다.

## 경계 / 다음 판단

실제 공개 구조·디자인 적용, 기본 thread/SDK 정책 변경, classifier·임상 수치·실제 동작/사람 정확도, 같은 부위 조형/GLB 변경, 외부 계정/비용/시크릿/운영 DB/배포/출시는 제외한다. 최소 텍스트·필수 안전 안내와 기존 승인 경계를 유지한다.

완전한 매끄러움·시작 P2 해결·D2/전체1~6 완료는 주장하지 않는다. 시간 분리와 실제 렌더 준비 보완을 입증해야 이 좁은 Story를 통과시킨다. 효과가 없거나 불리하면 실패로 남기고 원인 가설을 수정한다.

실행 결과·실패 구분·보존 자료는 [검토 기록](../review/native-first-render-isolation/README.md)에 있다. 공개 문구는 늘리지 않으며 아바타/움직임 중심, 짧은 제목·버튼·현재 코칭과 펼쳐 보는 설명·간결한 필수 안전 안내를 유지한다.
