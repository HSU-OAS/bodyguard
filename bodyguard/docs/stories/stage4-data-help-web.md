## 범위·현재 사실

PR #26 계정·탈퇴 웹의 실제 merge commit/main 포함·소스 브랜치 보존을 확인한 다음 독립 Story다. 사이트에서 처음 사용자가 카메라와 기록 처리, 계정 복구·기록 삭제·탈퇴 차이를 이해하고 기존 작동하는 화면으로 이동하도록 한다. 요청된 web-design-studio와 기존 화이트/블루 토큰을 사용한다. **웹**이며 별도 앱·기기 permission을 추가하지 않는다.

기술 안내의 근거는 현재 App/auth/records/withdrawal/API schema/db.py·실제 Chrome/SQL 증거다. 기존 안전 문구를 유지하고 새로운 질환/효과/각도/마사지 지침을 만들지 않는다. 카메라 실제 코칭은 아직 미연결, 출시 동작0, 합성 개발 기록은 운동/자세 검증이 아님을 명확히 구분한다. raw 영상/관절 좌표를 저장/서버 전송하지 않는 기존 계약을 바꾸지 않는다.

Q-26의 **법무 처리방침·동의는 막바지 별도 결정**을 유지한다. 이번 `/data`는 현재 기술 사실/관리 방법 안내이며 법정 처리방침·동의 획득 완료가 아니다. Q-17 보관/운영 백업·기한·사업자·연락처·국가·지원 담당·외부 제공사 계약을 임의로 만들지 않는다. 안내 화면만으로 개인정보/법무/출시 게이트를 충족했다고 표시하지 않는다. 새 수집/분석/동의/외부 서비스는 없다.

## 화면·디자인 계약

- 공개 `/help`: 현재 이용 가능한 가입/복구·기록 관리/삭제·계정 탈퇴와 카메라 준비중을 분리한다. 실제 화면으로 이동하는 링크와4~5개의 짧은 질문/답을 제공한다. 운영 연락처가 없어 가짜 문의 메일/접수 성공/답변 시간을 만들지 않는다.
- 공개 `/data`: 카메라/신체 정보의 브라우저 처리 계약, 현재 서버 계정·로그인/인증 보안정보·수행 요약의 범주, 관리/삭제 방법, 법무 문서 준비 상태를 구분해 안내한다. 이메일/구글 가입 식별정보·password hash와 보안 확인값은 코드 사실에 맞게 설명한다. “모든 보안 정보/운영 백업 즉시 전부 삭제”처럼 현재 코드/정책과 다른 약속을 하지 않는다.
- footer의 도움말/카메라·데이터 안내 링크로 게스트/회원 모두 접근한다. 본문을 읽는 것만으로 records API 조회·삭제/코드 발송·카메라 권한 요청이 없다. 기존 메뉴의 `/me` 확인은 일반 계정 상태 확인이고 신규 추적이 아니다.
- 블루1강조·백색/잉크·기존 system type/간격/radius/button을 재사용하며 새 외부 폰트/SDK/UI 시스템/장식3D를 추가하지 않는다. 제목→핵심 처리 사실→관리 링크→준비 상태 순으로 읽는다. 헤더/작은 창/긴 한글·키보드·오류 상태에서도 주요 내용을 유지한다.

2. DOM: 게스트/회원/계정 연결 실패에서 공개 안내 유지, footer 진입, 현재 기능과 준비 상태 분리, 지원/정책/운동 검증 완료 허위 문구0, 도움말을 읽는 동안 카메라/기록 조회/삭제/메일 POST/storage/외부 요청0.
3. 실제 production Chrome/API/SQL: 공개 소개→안내→가입 또는 복구→계정→기록 관리의 기존 흐름과 복귀, keyboard/FAQ·좁은375/768/desktop1440·실제 대비/reduced motion/overflow를 확인하고 PNG/report를 보존한다. 모의 메일/합성 기록은 실제 공급자/운동과 구분한다.

## 남는 게이트

법무 문서/사업자/보관·백업 정책은 별도 CEO 승인, 실제 SMTP/Google/HTTPS/운영은 별도 연결/승인이다.2단계 이월·코칭/아바타/실측·기록 생산·미정 부가 기능은 이 안내의 존재로 완료하지 않는다. 이후5→6 독립 구현/준비와 최종 통합을 이어가며 전체1~6 필수 게이트를 실제 닫아야 한다.
