# S6.12 — 응답 없는 코칭 Worker의 종료와 실패 복구

상태: 비공개 구현·실제 소유 흐름/로컬 검증·작성자 리뷰 완료, PR 게이트 진행. 기준 main `f26c7b901d4c31fdbf26c4fbebf360417c6cfab4`, `codex/native-worker-recovery`. 공개 적용·전체 출시 완료가 아니다.

## 한 목적과 근거

FR-M-02/07·FR-A-03·NFR-07/08. S6.11의 비공개 Worker 소유 경로에서 준비 또는 한 프레임 추론의 응답이 사라질 때 무기한 기다리지 않도록 한다. 정상 시작의 기존 5000ms 시험 게이트, 모델·판정·관찰 시각·공개 기본 경로는 변경하지 않는다. Worker가 오류 이벤트 없이 닫히는 경우를 실제 Chrome에서 먼저 재현한다.

## 수용 기준·하네스 계약 — 구현 전

1. 준비와 각각의 프레임 응답에 고정 5000ms 기술 한도를 둔다. 이 값은 임상 각도·운동 시간이나 시작 시험 제한을 완화하는 값이 아니다. 한 번에 하나의 프레임이라는 기존 소유 계약을 유지한다.
2. 한도 초과는 고정 오류로 실패시킨다. 잘못된·늦은 ready/result로 되살리거나 빈 정상 결과·main 자동 fallback·성공 기록으로 바꾸지 않는다. 유효 응답·중단·실패·폐기 시 응답 타이머를 해제한다.
3. 기존 native close 확인과 별도의 5000ms 정리 한도를 보존한다. 준비 factory는 정리 관측 후 실패하며 최악의 무응답 대기는 준비5초+정리5초다. 실행 중 분석 권위는 응답 한도에서 실패하고, 카메라/프레임/아바타/Worker를 기존 소유 수명으로 폐기한다. 정리 ACK 부재는 cleanup 실패로 표시하며 SDK 정상 종료라고 주장하지 않는다.
4. 단위 하네스에서 준비/추론 무응답, 한도 직전 응답, 새 프레임의 새 한도, 오래된 응답·취소·정상 정리·무응답 정리와 타이머 잔여0을 검증한다.
5. 실제 Chrome에서 시험 주입한 Worker `self.close()`를 준비 전과 실제 SDK 준비 후 추론 중에 적용한다. 기존 코드는 실패로 보존하고 수정 후 유한 종료·카메라 종료·오류/기록 경계를 실제로 확인한다. fault injection·가짜 카메라·빈 신체 입력은 실제 사람 또는 성능 증거가 아니다.
6. 실제 SDK 정상 연결/소유 계정 회귀, 전체 frontend/type/Biome/build/공개 경계·byte·diff, 작성자 리뷰를 통과한 범위만 PR 게이트로 진행한다. 기존 간헐적 시작 P2·아바타/실측·전체1~6 미완료는 별도로 유지한다.

## 제외·승인 경계

새 공개 UI/미승인 구조, 임계값·동작/추천·새 조형/GLB, 외부 SDK 통신 제품 정책, 영상/좌표/얼굴/손 원시값 저장·전송, 비용/계정/시크릿/운영 DB migration/배포/출시는 없다. 테스트는 브라우저 내부 메모리와 고정 상태·횟수·기술 시각만 사용한다. 기존 파일/실패 증거는 보존한다. 텍스트 최소화 원칙을 유지하고 새로운 사용자 안내 화면을 확장하지 않는다.

## 구현·실제 결과

응답 타이머와 단조 시각 deadline을 준비/각 프레임에 적용했다. 늦은 callback보다 늦은 응답이 먼저 처리돼도 정상으로 받지 않는다. 유효 응답/취소/실패/정리에서 해제하며 기존 native ACK·5000ms 정리·한 프레임·세대/시각·기본 main 경로를 유지한다.

실제 Chrome/SDK/API/격리 SQL에서 남녀 각각 준비 고장→기록0, 수행 고장→카메라 종료/본인 interrupted만 저장, 정상 중단/기록·준비 중 로그아웃·갱신/새 소유를 확인했다. 강제 종료의 cleanup 오류는 정상 close로 바꾸지 않는다. 전체 frontend1344·client22·실제 소유10·정적/build/공개 byte/guard를 통과했으며 [원본·실패·작성자 리뷰·한계](../review/native-worker-recovery/README.md)를 보존한다.

가짜 카메라/동작 gate·미완성 A37이며 실제 사람/물리 카메라/정확도0이다. 기존 간헐적 시작 P2·D2·공개 구조/SDK 정책·참여자/운영·전체1~6 완료 기준은 남는다. 타이머와 정리는 main 이벤트 루프가 실행돼야 동작하며 idle heartbeat가 아니라 요청별 유한 실패다.
