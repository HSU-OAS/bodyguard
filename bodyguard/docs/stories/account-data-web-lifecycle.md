# S6.21 — 탈퇴·재가입의 전체 계정 데이터 웹 검증

상태: 좁은 검증 구현·실제 회귀/증거/작성자 리뷰 완료 / 조건부 PR 게이트 진행. 기준 main `8ab7f151f0cc51d78b2d22c17650cc3d2e65e612` (PR110 실제 병합 확인).

## 범위

FR-U-02/04/05·FR-R-03·NFR-08. 기존 탈퇴 웹 시험은 수행 기록만 저장한다. 현재 저장 대상인 자세 기준선(활성·과거), 1분 요약, 알림 설정도 포함하여 취소·명시 탈퇴·동일 이메일 재가입의 데이터 경계를 검증한다. 기존 제품의 삭제 정책·인증·화면/문구·메뉴를 변경하지 않는다.

최신 CEO 지시 **아바타 보류·독립 웹 진행**을 따른다. 새 조형/변형 검증·미승인 화면 확장·판정/SDK 정책·새 의존성·운영 DB/배포는 제외한다. 법적 보존·백업 삭제·실제 공급자 연결을 이 시험으로 완료 처리하지 않는다.

## 하네스와 수용 기준

1. production Chrome·실제 FastAPI·새 소유 PostgreSQL18로 기존 탈퇴 6개 및 비밀번호 복구 5개를 실행한다. 기존 deadline/재시도·quota를 변경하지 않는다. 실패와 미실행을 보존한다.
2. 별도 계정 2개의 합성 수행 기록·과거/활성 기준선·1분 요약·서로 다른 알림 설정을 실제 API로 저장한다. 취소 후 본인 데이터와 타 계정 데이터가 값까지 동일하다.
3. 웹에서 코드·확인문을 명시 입력한 탈퇴만 204로 완료되며, 기존 세션은 401이고 본인 사용자/세션·4종 데이터 행은 실제 SQL에서 0이다. 타 계정의 데이터/설정은 그대로다.
4. 동일 이메일로 **실제 가입 화면**에서 재가입하면 새 사용자 ID이며 과거 기록·요약·기준선이 돌아오지 않고 알림은 기본값이다. 기존 계정 및 타 계정 경계는 유지한다.
5. SQL oracle은 시험 프로세스 전용이다. 사용자 입력/제품 endpoint 없이 고정 테이블의 count만 출력하며, 전용 역할/DB·소유 Unix socket·PG18·TCP 미개방을 검증하고 read-only transaction으로 읽는다. 잘못된 대상과 SQL 쓰기는 실제/단위 시험에서 거부된다. 제품에 넣지 않는다.
6. 카메라 호출·모델/SDK 요청·브라우저 영속 저장은 0, 해당 웹 요청은 localhost만이다. 소스/실행/증거 SHA·browser 버전과 실제/합성 구분을 기록한다. 제품 source 및 공개 bundle byte는 기준선과 같아야 한다.

## 증거와 출시 기준

메일함·코드·복구 토큰·쿠키·개별 API bodies는 소유 scratch에만 두고 공개하지 않는다. 공개 증거는 검토한 합성 화면·고정 count/boolean·실행 로그와 SHA이다. 이전 파일/실패는 보존한다. 소유 시험 DB는 정상 종료하되 디렉터리를 삭제하지 않는다.

이는 기존 웹 데이터 처리의 회귀이며 실제 사람/운동 정확도·시범/최종 아바타·기존 시작 P2·공개 코칭 구조/SDK 개인정보 승인·Docker/HTTPS/공급자·법무/운영·D2/전체1~6의 미완료를 해소하지 않는다. 좁은 Story의 검증/리뷰를 통과한 뒤에만 기존 조건부 PR 병합 규칙을 적용한다.

## 결과

전체 데이터의 취소 보존·본인 탈퇴/타인 보존·동일 이메일 웹 재가입과 두 빈 기록 화면을 실제 확인했다. 최종 탈퇴7·복구5·SQL23·frontend1481·타입/정적/build/guard가 통과했다. 동시 로컬 검사 중 private reader 시간 초과1개와 초기 DB/setup/경로/포맷 전 정적 검사 실패는 보존하며 최종 성공으로 지우지 않는다. 제품/config187개와 production bundle은 byte 동일하다. [실제 화면·흐름·실패·검토·범위](../review/account-data-web-lifecycle/README.md),91개 원본/압축 SHA 및 현재 소스12개 확인이 완료됐다. scoped 원격 diff/HEAD/CLEAN/체크를 다시 확인한 뒤 조건부 병합을 적용한다.
