# S2.5b — 코칭 진행·중단 엔진의 독립 구현

2026-10-05 · 최신 main 4a00bb2에서 시작. S2.5 전체 완료가 아니라 실제 코칭에 필요한 순수 진행 엔진을 독립 준비한다.

## 목적과 경계

FR-S-02/03/04, FR-M-07, FR-A-03, FR-U-04, NFR-07에 따른 유지·반복·복귀·일시정지·중단·건너뜀을 구현한다.
브라우저 프레임을 세는 것과 올바른 운동을 판정하는 것은 분리한다. 이 엔진은 검증된 동작별 판정기의 분류를 소비할 뿐, 관절 각도·압력·효과를 판단하지 않는다.
관찰되지 않은 구간, 지나간 프레임·중복 응답, 타이머 callback만으로 수행을 늘리지 않는다.

- 순수 TypeScript, 카메라/DOM/MediaPipe/Three/API/저장소 의존0. 기존 판정·카메라·아바타 파일은 변경하지 않는다.
- 계획의 유지시간·반복수·회당 유지시간·프레임 유효성 간격은 호출자가 명시해야 한다. 출시 기본값·시제품 8종의 가설 수치 복사0.
- 승인된 판정과 정상 관찰을 받은 target 샘플 사이의 시간만 누적한다. 정상적 조건 이탈/일시정지 후 이미 확인한 유지시간은 보존하되 비관찰 시간을 더하지 않는다.
- 반복은 시작 → 목표(필요하면 회당 유지) → 확인된 복귀 순서로만 증가한다. 가림/복수 추정/대상 전환/시간 공백은 진행 중 반복을 해제하고 새 시작 확인을 요구한다.
- 두 방향/여러 단계는 계획 순서대로 수행한다. 앞 단계의 늦은 프레임이나 버튼 반복으로 다음 단계를 자동 통과하지 않는다.
- 준비에 계정 확인·동작 검증·기준/내 아바타 준비가 필요하다. 시작 버튼 뒤에만 카메라 요청 effect를 내며 늦은 ready는 해당 generation의 자원 해제 effect만 낸다.
- 완료/중단/건너뜀 결과와 단계별 완료/미완료를 구별한다. 원시 좌표·영상·피드백 각도·계정 식별자·추적 epoch는 결과에 넣지 않는다. 결과 객체를 서버/저장소에 쓰지는 않는다.
- 외부 입력의 ready boolean은 인증이나 동작 검증을 증명하지 않는다. 실제 계정 API/동작 검증/두 모델 adapter가 확인해야 하며 UI나 테스트에서 임의로 true를 넣어 공개하는 것은 금지한다.
