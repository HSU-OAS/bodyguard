## 범위·근거·화면 계약

기존 추천 탭의 대기 문구를 개발 웹에서 실제 카메라 확인→명시 촬영 조건 확정/자원 정리→부위·관찰 범위에 맞는 3D 후보→기존 수행 안내로 연결한다. 기존 `CameraPreparation`의 단일 copied slot/세대·소유 수명주기와 `cameraFraming`, 제작된 `MotionPreview`의 hover/focus/재생, 기존 상세/촬영 안내를 재사용한다. 새 메뉴/전체 디자인 개편은 없으며 화이트/블루·기존 카드/버튼/초점/최소 문구를 유지한다.

추천 이유는 **사용자가 고른 부위와 실제 확인한 촬영 범위**다. 체형 이상·질환/효능·치료 필요성·점수/순위를 추론하지 않는다. 이 첫 필터가 최종 개인별 신체 분석/추천 전체를 대체하지 않는다. 실제 코칭 후보3종 중 관찰 가능한 것만 보여주며 안내만4종은 기존 직접 선택에 보존한다. 몸통의 자동 후보가 없으면 카메라를 불필요하게 켜지 않고 직접 선택을 제공한다. 기존 공개 출시 적격0과 임상/아바타/판정 gate는 그대로다.

2026-10-17 [NHS Flexibility](https://www.nhs.uk/live-well/exercise/flexibility-exercises/)의 목 스트레칭은 반대 손으로 어깨를 안정시키는 변형이며, 현재 손을 쓰지 않는 후보와 동일하지 않다. 해당 페이지의 유지/반복을 현재 변형의 기본값으로 옮기지 않는다. [NHS Sitting exercises](https://www.nhs.uk/live-well/exercise/sitting-exercises/)의 상체 비틀기도 골반 유지가 전제다. 정면 관찰만으로 이를 확인했다고 주장하지 않는다. 두 자료는 일반 수행 설명이지 카메라 측정값→개인별 치료 동작의 대응 근거가 아니다. 기존 환자용 자료/실패 링크와 수치는 보존한다.

## 수용 기준·하네스

1. 부위 선택만으로 후보를 만들거나 카메라를 켜지 않는다. 실제 단일 인물·필수 관절·같은 capture 세대/순서/시각·신선도를 확인한다. 상반신/가림·두 사람·만료/변조/역행에서는 근거 없는 후보가 생기지 않는다. 필요한 부위보다 전신이 더 보이는 것은 허용한다.
2. 명시 확인 때 현재 입력으로 snapshot을 만들고 해당 카메라/SDK 정리 완료 후 표시한다. 정리 실패·늦은 권한·숨김/pagehide·계정/목적 교체·나가기에는 결과를 폐기하며 자동 재시작하지 않는다. 이 snapshot이 다음 코칭의 새 촬영 검사를 면제하지 않는다.
3. 남녀 제작 미리보기·동작명·짧은 이유·기존 안내 링크를 제공한다. 근거 없는 임상 순위/정답 각도/운동량·자동 코칭/운동 기록·기준선 저장·원시 데이터/브라우저 저장을 추가하지 않는다. 공개 bundle/기본 공개 추천에는 후보가 들어가지 않는다.
4. 순수 정책·실제 React/소유 수명주기+모의 capture DOM, 실제 Chrome/생성 관절·실제 미리보기와 실제 SDK 빈 가짜 장치 경로를 구분한다. 일반 전체 회귀·원래 타입/고지/build·공개 격리·Biome·diff/리뷰를 검증하고 실패/소스를 보존한다.
