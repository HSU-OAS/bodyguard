# S2.2 — 공개 시작·계정 화면

2026-10-01 · 로컬 구현·검증 통과, PR 게이트 검토 중. 선행 S2.1은 [PR #6](https://github.com/HSU-OAS/bodyguard/pull/6)으로 main 병합. [단계 계약](stage2-first-flow.md), [운영 규칙](../operating-rules.md)을 따른다.

## 범위·수용 기준

FR-U-02/03/04, FR-M-01, NFR-08. 공개 소개, 이메일 가입 → 코드 확인, 로그인, 보호된 `/start`, 로그아웃을 실제 S2.1 API에 연결한다. Google·복구는 S2.6, 선택·코칭은 S2.5, 추천은 3단계다. 미완성 기능의 작동 버튼·가짜 결과는 만들지 않는다. 기존 측정 시제품은 `/dev/measure`의 development 전용으로 격리하고 production에는 진입·번들 포함을 허용하지 않는다.

- AC-01: 공개/가입/로그인/보호 경로 직접 방문과 인증 후 내부 목적 복귀. 복귀는 현재 구현된 `/start`만 허용하며 외부 URL·인코딩 우회를 거절한다.
- AC-02: 가입 요청만으로 인증되지 않는다. 코드 6자리 확인, 오답/만료/재발송/429·네트워크 오류·중복 제출을 처리한다. 이메일/비밀번호/코드/CSRF/세션을 URL·웹 저장소·로그에 남기지 않는다. 가입 입력은 메모리만 사용하므로 새로고침 시 안전하게 다시 가입을 시작한다.
- AC-03: `/me` 확인 전 개인 UI가 보이지 않는다. 401만 게스트로 판정하며 서버/네트워크 오류는 차단·재시도 상태다. 로그아웃 시작 시 개인 UI를 즉시 가리고, 실패를 성공으로 표시하지 않으며 재시도한다. 늦은 응답·이탈·탭 간 변경으로 지난 사용자가 부활하지 않는다.
- AC-04: 모든 계정 POST는 실제 쿠키·CSRF 계약을 사용한다. 가입/로그인/접속에서 카메라 요청·추론·3D 로드 0. 개발 시제품은 출시 코칭 우회 경로가 아니다.
- AC-05: 실제 레이블/자동완성/키보드/초점/오류 안내, 좁은 노트북 창에서도 가로 넘침 없는 폼. 동작 설명·개인정보 문구는 비진단·카메라 명시 시작 원칙을 유지한다. 법무 동의는 4단계에서 별도 사업 승인 후 확정하며 현재 폼을 출시 승인으로 간주하지 않는다.

## 디자인 계약

사용자 과제는 서비스 이해 후 안전하게 계정으로 들어가는 것이다. 공개 화면은 한 가지 주 행동 `시작하기`, 계정 화면은 한 폼, 보호 화면은 실제 계정 상태만 보여준다. 따뜻한 백색 바탕·짙은 잉크 글자·청록 주 행동, 1px 구분선, 시스템 한글 글꼴. 제목 44/32px, 본문 16px, 8px 간격 배수, 컨트롤 48px·10px 모서리. 주 행동은 채움, 보조는 테두리/링크; 장식 아이콘·숫자·효과 보장·인증 배지·가짜 차트는 없다. 키보드 초점은 고대비 테두리, 상태는 문장으로 설명한다. 현재 아바타는 CEO 참조 품질 미달이므로 최종 제품처럼 영웅 이미지에 쓰지 않는다. 전체 제품 미리보기는 S2.4~5 실제 렌더로 추가한다.

## 실행형 하네스

- B-01: Playwright + 실제 로컬 Uvicorn·PostgreSQL. 가입/메일 코드 확인/보호 진입/로그아웃/로그인/재접속/미인증 직접 접근. 시험 메일은 테스트 프로세스가 만든 격리 임시 파일로만 전달하며 웹 outbox API·production 우회가 없다.
- B-02: 브라우저 네트워크 중단·요청 지연, 재발송 대기·오답, 폼 새로고침·키보드·세션 확인 오류. 인증 성공 응답을 stub으로 만들지 않는다. 경계값/경쟁은 S2.1 실제 DB 테스트와 프런트 상태 단위 검사로 구분한다.
- B-03: 늦은 `/me`와 로그아웃·이탈, 탭 간 로그아웃, 인증 저장소/카메라 요청 0. production `/dev/measure` 차단. 개발 가짜 카메라 회귀는 별도 실행하며 실제 사람 검증으로 표시하지 않는다.
- 시각: 실제 Chrome에서 공개·가입·인증·로그인·보호·오류 화면, 1440px/좁은 데스크톱 창 검사. 모바일 지원·실제 이메일·HTTPS·실제 자세 판정·최종 아바타 검증은 이 Story 증거가 아니다.

메일 전달만 시험 프로세스가 대체했다. 상태 경쟁의 Vitest fetch 응답·난수/시간 경계 테스트는 모의 요소로 표시하며 브라우저 재발송 60초는 가상 시간이 아니다. 실제 Gmail/Google/복구/코칭/사람 촬영/최종 아바타/HTTPS/운영 DB/배포/출시·법무 동의는 하지 않았다. 현재 Starlette TestClient의 httpx 호환성 경고 1개와 개발용 Three/MediaPipe 경고는 검사 실패가 아니며 실제 촬영·SDK 갱신 Story에서 추적한다. UI는 전문가/치료 효과·가짜 미리보기·미구현 작동 버튼을 만들지 않았다.

자체 `engineering:code-review`로 보안·경쟁·예외·성능·접근성을 검토하고 위 레이블/재발송 문제를 해결했다. 미해결 P1/P2는 없다. 최종 remote diff/HEAD/CLEAN/체크는 PR 병합 직전 다시 확인한다. S2.2 완료와 **2단계 전체 미완료**를 분리한다. 다음 S2.3 실제 관찰과 독립 S2.4 조형 준비를 진행한다.
