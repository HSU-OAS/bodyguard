# S3.B2 웹캠 촬영 기준 연결

2026-10-12 · 최신 main `0c8d1726b36fc36f3935de2111937fdccd5006a1` · 구현/검증 진행 중

CEO는 참여자를 제외하고 완성품 제작을 계속하라고 지시했다. 참여자 없는 소프트웨어의 실제 작동 흐름을 먼저 연결하며, 사람 정확도·최종 아바타·운영 검증을 완료했다고 표시하지 않는다. 본 Story는 FR-M-03/07·FR-U-04의 촬영 기준 데이터 생산→명시 확인→기존 본인 기준선 API 저장이다. 실제 신체 분석·맞춤 추천/코칭의 다음 연결에 필요한 기준값을 생산한다. 기존 API client만 준비해 둔 상태를 더 많은 fixture로 반복하는 Story가 아니다.

## 범위와 화면 계약

기존 개발 코칭 화면의 카메라 입력 확인 아래에 기존 버튼·여백·화이트/블루 표현을 재사용한다. 새 탭·공개 코칭·디자인 개편은 없다. `카메라 확인 → 입력 확인 → 3초 기준 수집 → 화면상 어깨선/관찰 변동 확인 → 교체 동의 → 기준 저장`이 사용자 흐름이다. 실패/끊김은 다시 수집, 저장 실패는 같은 ID로 명시 재시도한다. 원시 영상·좌표를 state/로그/저장소/API로 전달하지 않는다.

촬영 기하가 있는 현재 한 사람의 코·귀·어깨만 같은 기존 추론 slot에서 소비한다. 중복 capture/추론은 없다. 3초는 PRD의 수집 길이이며 신뢰도0.5/신선도1초는 기존 기술 관찰 경계를 재사용한다. 어깨선은 영상 종횡비·반전이 반영된 **이미지 평면 축 각도**다. 목 전방·몸통 굴곡·경추 각도로 바꾸지 않는다. 좌우 어깨 순서에 따른 ±180도는 축 각도 circular mean으로 처리한다. 보관하는 값은 scalar sum/count/range뿐이다.

`review`는 수집 초안이 나왔다는 뜻이지 자동 보정 승인·정자세 인증이 아니다. 임의의 임상 각도/안정성 임계값을 채택하지 않는다. 관찰 변동은 사용자에게 보여주며 흔들렸다면 다시 수집하도록 안내한다. 기존 FR-M-03의 자동 안정성 판정·절대 어깨 경고·최종 올바른 기준 안내는 아직 완료가 아니다. 저장은 client-reported 어깨 기준만, 목/몸통은 null이고 기존 활성 기준 교체를 명시 확인한다. 과거 기준은 기존 API 정책대로 보존한다.

## 수용 기준과 하네스

| 계약 | 검증 |
|---|---|
| 3초 전에는 저장할 초안0, 새 수집 전 입력은 버림 | 순수 수집 unit: 경계·타임스탬프·중복/역순·세대·실제 영상 비율/반전 |
| 가림·불완전/복수 사람·화면 밖·NaN·오래된 입력은 수집 실패 | 합성 관절 fixture unit; 사람 정확도를 입증하지 않음 |
| 현재 입력이 끊기면 이전 값을 채워 통과시키지 않음 | 입력 없는 tick와 gap 경계 unit/React |
| 명시 교체 확인 없이는 POST0, 명시 저장은 whitelist 어깨 집계 DTO만 | 실제 React/AuthProvider·기존 baseline client에 제어 API 응답 |
| 저장 실패 후 동일 ID 재시도, 자동 재시도/이중 클릭 없음 | held write·503·성공·동일 입력 비교 |
| 계정/동작/페이지·숨김/중지 후 수집/저장 늦은 결과 폐기 | React 경계/실제 Chrome 흐름; 401/403이면 카메라 회수·재저장 차단 |
| 기존 카메라/worker lifecycle과 공개 제품 경계 유지 | 관련/전체 frontend·타입·Biome·원래 build/production guard, 실제 Chrome 기존 카메라 준비 회귀 |

UI 검증은 노트북 크기와800px·키보드/초점·긴 오류 상태를 대상으로 한다. 앱·모바일 기능을 만들지 않는다. 가짜 카메라·합성 관절·제어 계정/API를 실제 사람/외부 공급자 검증으로 표시하지 않는다.

## 제외 및 완료 경계

Blender/GLB/외형 수정·아바타 검증 사이클·동작 자동 정답/오류 classifier·공개 추천/코칭·SDK 통신 변경·새 API/DB migration·메일/OAuth·Docker/HTTPS·운영/배포/출시0. 아바타 제작 보류 해제는 별도 질문으로 요청했고 답변 전 재개하지 않는다. 실제 참여자 시험은 CEO 결정으로 이월하되 미실행 기록을 보존한다. 본 Story 통과는 전체1~6 통과나 출시 후보 선언이 아니다.

## 결과

- 카메라 입력 확인 아래의 실제 React 화면에서 3초 수집→초안 확인/동의→저장, 저장 실패→동일 ID 재시도, 끊김→재수집, 카메라/계정/동작 종료→초안/늦은 저장 폐기를 연결했다. 미완성 두 아바타 영역과 공개 코칭 차단은 그대로다.
- 순수 수집24개/React10개를 포함한 전체 frontend **1931통과/107파일**, 타입·원래 notice build·production guard·diff 통과. 전체 Biome는 통과하며 기존16 info가 남는다. 새 script의 template info는 보완하고 scoped 검사에서 신규 진단0을 확인했다.
- 실제 Chrome155의 화면 시험은 초기6흐름 통과 후 과거 기준선 경계를 추가했다. 최종7흐름을 별도 디렉터리에서 실행해 failure=null/외부 요청0/물리 카메라 호출0/페이지 오류0을 확인했다. 입력/API는 합성이며 실제 SQL/신체/SDK 양성 판정의 증거가 아니다. held POST가 서버에 도착한 뒤 동작을 바꾸고 늦은 응답을 해제하는 경계를 실제로 확인했다. [화면/원본 결과](../verification/camera-reference-capture-20261012/)의 `browser-final.json`과 `final-*` 이미지가 최종 버전이다.
- 기존 실제 SDK·heavy/얼굴/손 Worker·native 가짜 장치 회귀8흐름 통과. 카메라/worker 종료·native CSP 외부 fetch 차단·합성 권한 거부/지연·계정401 회수를 확인했다. 기존 시작P2나 실제 사람/권한 popup 문제 해결로 확대하지 않는다.
- 첫 전체 실행의 기존 기록 시험8실패는 UTC fixture의 기본 시간대 누락이었다. 별도 PR148(`6e43a6a`→`73467fb` merge commit)에서 보완/검증했고, 최신 main 포함 후 위 전체 시험을 재실행했다. 원래 실패를 보존한다. 이 Story의 첫 타입/포맷 오류와 보완 결과는 초기 실행 tool output에 남으며, 별도 원문 파일이 없는 출력을 파일 증거로 주장하지 않는다.
- 직접 정확성·보안·성능·수명 diff 검토: 한 slot/기존 타임스탬프만 사용, scalar만 보관/명시 저장, 원본 좌표/영상 전달·새 classifier·운영0. 권한 오류는 같은 committed authority의 route remount에서도 회수 유지. 검토에서 취소 시험의 POST 도착 확인 누락을 보강했다. 또 과거 ID 재시도의 inactive200을 현재 기준 교체처럼 표시하는 P2를 1실패/9통과로 재현하고, 이력만 확인됐음을 표시/추가 쓰기 차단하도록 보완해34통과했다. 첫 추가 Chrome 시험은 aria-disabled 버튼의 Playwright pointer action에서 timeout으로 반려했고 실제 키보드 Enter 재입력 시험으로 수정해 최종7흐름 통과했다. 원본을 보존하며 독립 외부 리뷰 실행이라고 표시하지 않는다. 최종 diff에서 이 좁은 변경의 미해결 P1/P2 없음. 기존 시작P2/이월 문제는 별도다.
- 새 검증은 원래 source/GLB 파일을 건드리지 않으며 최종 아바타를 공개하지 않는다. 실제 카메라 정자세·안정성 채택·추천/판정·최종 아바타/운영·전체1~6은 아직 미완료다.
