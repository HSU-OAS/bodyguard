# S6.24 — 업로드·본인 조회·확인 삭제의 연속 기록 흐름

2026-10-10 · 시작 main `665c914e2befc3fcfca04366c0eaf6ee225eef3c` · `codex/record-data-journey` · 실행 전 계약.

FR-R-01/03/06·FR-U-04/05·NFR-07/08. 이미 구현한 분 집계/소유 업로드, 실제 AuthProvider/대시보드 조회, 공개 자세 기록 화면의 상세·삭제를 한 흐름으로 검증한다. 새 제품 UI/정책/producer를 만들거나 기존 Draft51 전체를 완료 처리하지 않는다. 기존 설치와 깨끗한 checkout을 재사용하되 브랜치는 최신 main에서 새로 만들었다.

## 수용 기준과 실행 하네스

1. 실제 Chrome의 비공개 React AuthProvider 안에서 기존 집계·업로드·조회 코드를 사용한다. 관찰 전 전송0, 합성 2분 관찰→실제 batch 저장→본인 일 조회2분→기존 공개 기록 상세의 null/시간을 확인한다. 가짜 fetch/직접 SQL insert를 정상 저장 경로로 대신하지 않는다.
2. 공개 화면에서 삭제 대상2건 확인→취소는 삭제0/조회2건이다. 다시 명시 확인→실제 삭제2건→공개 빈 목록/대시보드0분을 확인한다. 다른 계정 기록은 보존한다.
3. 실제 저장201 뒤 응답 단절은 uncertain이다. 명시 같은 내용 재시도200으로 한 행만 유지한다. 실제 삭제200 뒤 응답 단절은 불확실 안내/자동 재삭제0이며 명시 재조회와 대시보드가 빈 실제 결과를 확인한다.
4. 삭제 preview 뒤 같은 기간에 새로 업로드한 분은 cutoff 밖이므로 기존 확인으로 삭제하지 않는다. 계정 교체는 비공개 조합의 원래 uploader/조회 수명을 닫고 이후 다른 계정에 이전 분을 저장하지 못한다. 실제 수락 후 늦은 upload 응답도 새 계정 상태를 덮어쓰지 못한다.
5. 전용 새 PostgreSQL 역할/DB/소켓과 loopback API·설치 Chrome·합성 계정/메일을 사용한다. 카메라·SDK·3D·외부 요청·브라우저 영구 저장0을 검사하고 원본 report/실패와 실행 입력 SHA를 보존한다. 실제 사용자 수행·의료 정확도·공급자·완성된 하나의 공개 코칭 흐름은 이 시험의 범위가 아니다.
6. tsc/Biome/runner Ruff·전체 frontend·production build/private guard·공개 JS/CSS byte 불변·실제 native5건을 검증한다. 테스트 전용 변경이므로 불필요한 제품 변경/인위적인 RED를 만들지 않는다. 작성자 scoped 리뷰·최신 main/diff/HEAD/CLEAN/체크·미해결 P1/P2 없음 뒤 하나의 목적 PR을 merge commit으로 병합하고 브랜치를 보존한다.

비공개 probe는 테스트 페이지에 별도 실제 AuthProvider root를 연결한다. 공개 앱의 기존 provider를 대체하거나 그와 하나의 root라고 주장하지 않는다. 수명 연결은 하네스 조합이며 공개 측정 producer 적용 완료가 아니다. 관찰/기록은 합성이고 실제 신체 촬영/올바른 자세 인증은 아니다. 삭제는 이 Story 소유 격리 DB의 합성 기록에만 실행한다.
