# S6.20 — 현재 기록 웹의 실제 HTTP·SQL 회귀

상태: 좁은 시험 계약 보완·실제 회귀/증거 검토 완료 / 조건부 PR 게이트 진행. 기준 main `1d87ad421995587f7bea024f33fc2ee5b75af26d`.

## 범위와 발견

FR-U-02/04·FR-R-03·NFR-08. PR109가 기록 화면 안내를 줄였지만 기존 `integration.spec.ts`의 WEB-I01은 제거된 긴 문구를 찾는다. 합성 API 시각 시험은 실제 가입·API·SQL·삭제·로그아웃 회귀를 대체하지 않는다. 최신 main의 새 `codex/web-http-records-regression`에서 이 독립 웹 계약을 보완한다.

제품 화면/메뉴·버튼·구조·문구·인증/API/DB 스키마·timeout·재시도는 바꾸지 않는다. 미완성 코칭 공개·아바타 제작/검증·SDK 개인정보 정책·새 의존성/CI·운영 작업은 제외한다. 최신 CEO 선택 **아바타 보류·독립 웹 진행**을 유지한다.

## 하네스와 수용 기준

1. 수정 전 WEB-I01/02를 기존 production Chrome·실제 FastAPI·새 소유 PostgreSQL18에서 실행한다. 실패 원문/소스/결과를 보존하고 어느 단계가 실행되지 않았는지 구분한다.
2. WEB-I01의 안전 안내와 RW03의 날짜 오류 계약을 현재 짧은 문구에 맞춘다. 안내 생략·느슨한 일치·timeout 확대는 하지 않는다. 기존 가입→탐색 준비→기록 상세→취소/명시 삭제→계정→로그아웃의 요청·SQL·권위 검사와 잘못된 날짜→복구 흐름을 유지한다.
3. WEB-I01/02와 기록 조회/삭제11개를 실제 HTTP·SQL에서 통과한다. 기존5초 expect/30초 case·재시도0, 가림/동작 성공 우회0. 회귀 실패가 추가되면 좁은 원인을 조사하며 정상 반복으로 기존 시작 P2를 닫지 않는다.
4. source/dist/실행 도구·결과의 SHA와 실제 browser 버전, 성공/실패, 네트워크·카메라·저장 경계를 기록한다. source 변경은 해당 시험 계약만이며 공개 bundle은 기준선과 byte 동일해야 한다.
5. 타입·정적 검사·필요한 회귀·production guard·diff 검토 뒤에만 조건부 PR 게이트를 진행한다. 필수 검증이 실패하면 해당 Story 완료/병합으로 표시하지 않는다.

## 실제와 합성, 보존

브라우저/HTTP/FastAPI/SQL·쿠키/CSRF/로그아웃은 실제다. 신규 DB는 `/private/tmp/bodyguard-auth-test.*` 전용 Unix 소켓·역할/DB `bodyguard_test`·host reject·TCP 미개방이며 기존 DB를 쓰지 않는다. 메일함·계정·저장한 수행 요약·일부 장애/서버 시각은 합성이다. 실제 Gmail/Google·참여자/물리 카메라/운동 정확도·배포 검증이 아니다.

이전 원본·검증 증거를 보존한다. 새 실행마다 고유 결과 경로를 쓰며 raw 오류·로그·소스는 소유 scratch에, 공개 증거에는 합성 화면·검토된 로그/수치·원본 SHA만 남긴다. 쿠키·코드·메일함·원문 API bodies/사용자 영상·좌표를 게시하지 않는다. 시험 DB는 소유 PID/경로를 확인한 뒤 정상 종료하고 디렉터리를 삭제하지 않는다.

## 남은 출시 조건

기존 초기 지연 P2·출시 적격 동작0·실측/참여자·최종 아바타/시범·공개 코칭 구조/SDK 정책 승인·Docker/HTTPS/공급자·법무/운영·D2 및 전체1~6 기준은 그대로 미충족이다. 이 Story는 현재 독립 웹 회귀만 검증한다.
