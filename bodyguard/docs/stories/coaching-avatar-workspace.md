# S2.W1 코칭 화면과 같은 입력의 두 모델 연결

2026-10-16 · main8675f72(PR151 실제 merge/tree·브랜치 유지 확인) · codex/coaching-avatar-workspace · FR-A-01/02/03·FR-M-02/07·FR-V-01/03

## 구현 전 계약

기존 로그인 전용 /dev/coaching의 단일 공간/좌우 배치·구도/성별 설정과 카메라 확인→입력 확인을 실제 renderer/owned pair에 연결한다. 한 카메라/Worker/복사 slot만 사용한다. 프레임의 원래 generation/sequence/시각을 그대로 전달하고, 촬영 범위·기준 수집에도 같은 입력을 전달한다. 영상/좌표를 React state·로그·저장·네트워크로 넘기지 않는다.

현재 전문 Blender 후보는 외형 P2/Draft다. 불변2be0ebe의 SHA 고정 남녀 GLB를 Vite 개발 서버에서만 읽기 전용으로 제공한다. 제품/public 폴더에 복사하지 않고 production에는 route/모델/개발 renderer가 포함되지 않는다. 일반 코드가 미완성 모델을 출시 에셋으로 채택하는 변경이 아니다.

왼쪽은 기존 사지/몸통 방향 표시, 오른쪽은 시범 미연결 비교 모델이다. 자동 정답·오류 색·시간/횟수·추천·검증된 운동 시범을 지어내지 않는다. 머리/손의 세밀한 정렬 및 실제 시범/판정은 별도 필수 미완료로 남는다. 이 연결만으로 완성 코칭을 선언하지 않는다.

## 화면 계약

기존 화이트/블루·글꼴·간격·둥근 버튼과 메뉴를 그대로 쓴다. 하나의 흰 canvas의 좌우 모델을 전신에서는 공통 카메라, 상반신/상세에서는 두 근접 viewport로 렌더하며 카드/테두리/방 배경을 새로 만들지 않는다. 전신은 발끝과 뻗은 팔까지, 상반신/자세히는 명시한 표시 구도만 변경한다. 구도가 실제 카메라 입력·판정 범위를 바꾸지 않는다. 키보드 설정·초점·loading/error/중지 상태, canvas 설명을 제공한다. SDK/카메라와 모델은 사용자 명시 시작 이전에 요청하지 않는다.

## 수용 기준·하네스

- 같은 복사된 observation을 기존 촬영 범위/기준 수집과 모델이 소비한다. 모델은 원래 세대가 다른 프레임을 받지 않으며 늦은 최초 로딩에 이전 프레임을 큐로 보관하지 않는다.
- 중지/숨김/페이지 이탈·계정/동작/성별 교체는 즉시 관찰을 끊고, Worker/카메라와 늦은 모델 준비/renderer를 정리한 뒤 다음 준비를 허용한다. 실패는 구분해 안내하며 자동 카메라 재시작0.
- 같은 SHA·여덟 가중치/독립 리그를 유지한다. 모델 누락/변조·WebGL 실패/손실·늦은 반환은 미완료/오류로 처리하며 정상 시범/코칭으로 통과시키지 않는다.
- unit/DOM에서 연결·취소·소유권·표시 구도·오류를 확인한다. 실제 Chrome에서 합성 입력+전문 GLB의 좌우 움직임/구도·남녀·중지/복구와 기존 카메라/기준 수집 회귀를 확인한다. 합성 양성/실제 SDK blank 미검출과 사람 정확도를 구별한다.
- 관련/전체 frontend·타입·Biome·원래 assets/build/production guard·diff, 실제 화면의 노트북1440/800px·키보드/오류/빈 상태를 검증한다. 실패/미실행도 기록하고 P1/P2가 남으면 병합하지 않는다.

## 제외·의존성

결과: [실제 화면·9흐름/기준7/native8/취소5·실패·보존](../review/coaching-avatar-workspace/README.md). 전체1941/타입/Biome/build/guard는 통과했다. 사지/몸통과 비교 모델 표시만 연결됐으며, 두 차례 SDK 준비/정리 실패의 원인 미확정 P2 때문에 Draft/미완료·병합 금지로 보존한다. 재실행 성공을 원인 해결로 표시하지 않는다.

새 디자인/메뉴 확장·모델 외형 수정/채택·공개 출시 동작·임상 임계값·정답 시범/오류 코칭·얼굴/손 정렬의 검증·실제 참여자·공급자·Docker/HTTPS·비용·계정·시크릿·운영 DB·배포/출시0. 기존 승인 해제 기록을 운영 규칙에 반영하되 별도 운영 권한으로 확대하지 않는다. 원본/실패/기존 Draft는 보존하며 전체1~6 완료는 미입증이다.

## 2026-10-16 추가 수용 기준 — 표시용 머리·손 정렬

CEO의 1~4단계 우선 완성 요청에 따라 기존 검수 공간의 누락된 머리·손 표시를 연결한다. 새 메뉴·제품 공개·정답 판정은 추가하지 않는다. 이전 SDK 실패/외형 P2와 원본·검증 증거는 보존한다.

- 사용자가 `움직임 맞추기`를 명시적으로 누른 뒤 받은 새 단일 신체 프레임에서만 표시 기준을 복사한다. 자동 정상 자세 추정·개인별 의학적 기준선·서버 저장이 아니다.
- 얼굴 회전과 양손 손바닥의 표시 기준을 독립 확인한다. 없는 입력은 보정값을 지어내지 않고 다시 맞출 수 있게 한다. 이미 받은 프레임이나 모델 로딩 중 프레임을 보관하지 않는다.
- 같은 관찰의 머리·손/손가락은 왼쪽 모델에만 전달한다. 오른쪽 비교 모델은 움직이지 않는다. 가림·복수 신체·오래된 입력은 새 관찰로 인정하지 않는다.
- 중지·계정/화면/성별 변경·취소·WebGL 실패 때 표시 기준과 세부 driver를 폐기한다. 기존 카메라/SDK·모델 소유권과 명시 재시작 경계를 유지한다.
- 합성 단위/DOM 시험과 실제 GLB/Chrome 표시 시험을 분리한다. 실제 사람 정확도·최종 아바타·올바른 시범/교정·출시 기준은 이 작업으로 통과 처리하지 않는다.
