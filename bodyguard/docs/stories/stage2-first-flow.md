# 2단계 — 첫 완성 흐름 실행 명세

2026-10-01 · **검토안 / 구현 전** · 선행: [1단계 통과 검토](../stage1-gate.md).

목표: 공개 소개 → 가입·로그인 → 동작 직접 선택 → 카메라 준비 → 기준/내 아바타 코칭 → 결과. 추천은 3단계, 기록 목록·데이터 관리 확장은 4단계다. 첫 결과 화면을 기록 서비스 전체의 완성으로 표시하지 않는다. [출시 계약](../release-plan.md)의 계정·고품질 두 아바타·세밀한 코칭·오판정 방지 요구를 축소하지 않는다.

## Story 순서

| Story | 구현 범위 | 완료 증거·의존 |
|---|---|---|
| S2.1 계정·세션 API | 이메일 가입 요청·코드 확인·로그인·본인 조회·로그아웃, 로컬 PostgreSQL과 권한 경계 | [상세 명세](stage2-account-api.md)·[하네스 계약](stage2-account-harness.md)의 실제 API/DB 검사. 실제 메일 발송 완료와 구분 |
| S2.2 공개 시작·계정 화면 | 소개·이메일 가입/인증/로그인, 보호된 시작 화면·원래 목적 복귀·접근성 | S2.1 실제 API로 E2E. 접속·로그인만으로 카메라 0회, 개발 데모의 제품 경로 우회 금지 |
| S2.3 첫 동작 실제 촬영 | #1 목 옆 기울이기의 특징·시작/복귀·보상·가림·복수 인물·시간/임계값 검증 | [동작 근거](../motion-evidence.md)를 사람이 실제 수행. 튜닝/검증 데이터 분리. 실패하면 재선정·CEO 범위 확인 |
| S2.4 남녀 아바타 첫 출시 후보 | 사진 대비 조형·의상·관절 표현, 축·변형, 웹용 최적화·권리·두 모델 비교 | [제작 계약](../avatar-production.md)의 실제 브라우저 컷. S2.3 근거 없이 시범 각도·유지시간 확정 금지 |
| S2.5 첫 코칭·결과 연결 | 목록/상세·직접 선택, 준비·두 아바타·관찰 가능한 세밀한 피드백·중단·결과 | S2.3·S2.4 통과 전제. 정상/오류/가림/추론·자산 실패·중단·탭 이탈. 완료·중단·건너뜀 구분 |
| S2.6 구글 로그인·복구 | OAuth, 비밀번호 재설정, 기존 세션 무효화·안전한 복귀 | 실제 공급자와 모의 시험 분리. 묵시적 계정 합치기 금지. 연결 정책은 상세 Story에서 검토 |
| S2.7 통합 게이트 | 실제 가입부터 선택·두 아바타·코칭·결과·로그아웃 | 남녀/정상/오류/가림/권한 거부/세션 만료를 실제 노트북에서 확인. 가짜 카메라·메일만으로 통과 금지 |

기본 실행은 표 순서다. S2.3 관찰 준비와 S2.4 조형은 독립적으로 준비 가능하지만 시범 확정·코칭 공개는 실측에 의존한다. 외부 계정 연결을 기다리는 동안 이미 승인된 독립 작업은 진행 가능하다. 새 Story는 CEO 승인 후 최신 main의 새 codex/* 브랜치에서 시작한다.

공통 게이트는 먼저 고정하고 **다음 S2.1만 상세화**했다. 나머지 상세 명세·실행형 하네스는 이전 결과를 반영해 해당 Story 시작 직전에 작성한다. 한 PR에 2단계 전체를 넣지 않는다.

## 화면 계약

| 화면 | 버튼·기능 | 상태·예외 |
|---|---|---|
| 공개 시작 | 로그인·가입, 소개·공개 미리보기 | 카메라 없음. WIP 모델을 완성 제품처럼 광고하지 않음 |
| 계정 | 이메일/비밀번호, 코드·재발송, 로그인·구글·재설정 | 입력/전송/성공/만료/재시도/요청 제한. 미구현 버튼을 작동하는 것처럼 표시하지 않음 |
| 보호된 시작 | 직접 고르기·추천 입구·로그아웃 | 세션 확인 중 개인 UI 먼저 노출 금지. 추천은 3단계 연결 전 시작 불가 |
| 동작 상세·준비 | 수행 과정·주의점·출처, 남녀 외형, 시작·뒤로 | 해당 동작의 필수 관절만 요구. 세션/자산 확인 후 사용자가 시작해야 카메라 요청 |
| 코칭 | 기준 동작 / 내 움직임, 수행 단계·핵심 수정 안내·일시정지·중단 | 촬영 안내 우선. 영상·디버그·확인 불가 색 없음. 불확실한 자세의 성공/오류를 지어내지 않음 |
| 결과 | 완료/중단/건너뜀, 수행 요약·다시 선택 | 미수행 구간을 완료·효과로 만들지 않음. 기록 목록은 4단계 |

내비게이션은 시작·동작 선택·계정 상태 중심이다. 추천·기록·설정 등 출시 필수 기능은 삭제하지 않되 미완성 페이지를 가짜 차트/결과로 채우지 않는다. 목적 복귀는 내부 허용 경로만 사용한다.

## 공통 하네스·통과 기준

| 게이트 | 검증 | 반드시 막을 것 |
|---|---|---|
| 인증 | 실제 API/DB, 만료·위조·다른 계정·CSRF, 화면 직접 진입 | 오류 때 개인 기능을 게스트에게 여는 폴백 |
| 동작 | 순수 TS 시간 포함 재생 + 실제 사람 관찰 | 가림/화면 밖/복수 인물/추론 정지/대상 변경/자산 실패의 성공·타이머 누적 |
| 프레이밍 | 상반신/전신/어깨 가림/얼굴 누락/조명·사선 | 더 많이 보이는 것을 오류로 처리하거나, 필요한 부위 누락을 성공 처리 |
| 카메라 | 늦은 권한 응답·play 실패·시작 중 취소·재시작·이탈·세션 만료 | 뒤늦은 스트림 누수, 지난 프레임/응답으로 상태 부활 |
| 아바타 | 남녀 정면/측면/3/4·좌우 시작/진행/복귀·관절 확대·GLB 재가져오기·두 화면 | 참조 품질 부족, 침투/찢김, 좌우/거울 반전, 루프 끊김 |
| 성능 | 실제 장치·브라우저·전원·모델·두 아바타 조건 | 인식 15fps·피드백 1초 기존 목표 미달, 평균값으로 끊김·지연 숨기기 |
| 개인정보·접근성 | 요청/로그/저장소, 키보드·레이블·초점·읽기 순서 | 영상/좌표 유출, production 테스트 우회, 핵심 접근성 누락 |

현재 landmarker.ts의 numPoses: 1은 두 사람 배제를 입증하지 못한다. S2.3에서 복수 포즈/대상 전환과 성능을 함께 검증한다. 아바타의 세밀한 보간은 세밀한 측정 증거가 아니다.

목은 손으로 당기지 않는 자료 기반 변형을 먼저 시험한다. 사진의 손–머리 접촉을 동작 정답으로 복사하지 않는다. 통증은 자기보고로 중단하며 카메라가 통증·압력을 검출한다고 주장하지 않는다.

## 단계 종료와 권한

화면 시연·테스트 실행 결과·Blender/GLB/권리·실측표·수정·남은 위험을 묶어 제시한다. 지금 표는 **검증 계약이지 통과 기록이 아니다**. 일반 사용자/다장치 회귀·HTTPS 배포·보안·운영 준비는 5~6단계에 남는다.

Gmail/Google 계정·시크릿·실제 외부 발송, 서버·운영 DB·배포·비용은 CEO 별도 승인 후 작업한다. 연결이 없으면 실제 연결 시험은 미검증으로 남기고 S2.7 통과를 요청하지 않는다.
