## 사용자 흐름과 디자인 계약

로그인 사용자가 `/records`의 현재 조회 기간에 해당하는 **전체 페이지의 본인 스트레칭 기록**을 삭제한다. 삭제는 조회와 분리한 보조 작업이다. 기간 변경 전의 확인값이나 일부 보이는 행만으로 삭제하지 않는다. 기존 백색/청록·타이포·간격을 재사용하며 삭제 확인에만 절제된 경고 색을 쓴다. 원본 영상·점수·아바타·계정 탈퇴는 이 화면 범위가 아니다.

1. 조회 기간과 연결한 `이 기간 기록 삭제`를 눌러 서버 미리보기를 요청한다. 이것만으로 삭제하지 않는다.
2. 확인 영역에 정확한 기간·서버 대상 수·전체 페이지 범위·복구 불가를 표시한다. 취소와 명시적 `기록 삭제`를 분리한다.0건은 삭제 불가이며 목록으로 돌아갈 수 있다.
3. 확인을 누를 때만 메모리의 서명 전체와 확인문을 전송한다. 중복 클릭은 차단한다. 삭제 성공의 실제 삭제 수를 안내하고 목록을 다시 읽는다.
4. 만료/대상 변경409는 확인값을 폐기하고 다시 미리보기를 선택하게 한다. 자동으로 새 서명을 받아 삭제하지 않는다.403은 재확인 안내,401은 기존 세션 재확인으로 사적 화면을 닫는다.
5. 통신 실패는 삭제 결과를 알 수 없을 수 있으므로 성공/실패 건수를 추정하지 않는다. 목록 재조회·대상 재확인으로 복구한다. 무조건적인 삭제 자동 재시도는 없다.

## 경계와 접근성

- 확인값은 메모리에만 존재한다. 저장소/URL/분석/로그에 넣지 않는다. 화면 이탈·로그아웃·기간 변경 시 폐기하며 늦은 응답은 새 화면에 적용하지 않는다.
- 대기/확인/삭제 중/결과/오류/0건을 각각 표시한다. 취소·기간 변경은 삭제 실행 전 안전하게 가능하고, 실행 중에는 결과가 확정되지 않았다는 안내를 유지한다. Abort는 서버 삭제 취소 보장이 아니다.
- 확인 영역의 제목으로 포커스를 안내하고 취소 후 진입 버튼/결과 후 목록 제목으로 복귀한다. live 상태, 키보드만의 확인/취소, 긴 문구와 좁은 화면을 검증한다.
- 같은 origin·쿠키·메모리 CSRF·no-store·15초 timeout을 재사용한다. 응답은 runtime 타입·기간/수/지문/서명/만료 일관성을 검사한다. 오류 원문을 화면에 넣지 않는다.
