# S6.11 — 코칭 추론의 브라우저 내부 Worker 분리

상태: 비공개 Worker 구현·실제 연결/로컬 검증·작성자 리뷰 완료, PR 게이트 진행. 기준 main `202486d4d0e11d1f812c021aa63d30ffe3b2707a`, `codex/native-worker-inference`. 공개 적용·전체 출시 검증 완료가 아니다.

## 한 목적과 근거

FR-M-02/07·FR-A-03·NFR-07/08. 보존된 PR90 실패에서는 몸·얼굴·손 첫 추론이 메인 스레드에서 4018.9ms를 점유했다. SDK 준비·환경 부하 등 간헐적 전체 시작 실패의 원인은 아직 확정되지 않았다. [Google Web 가이드](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js)는 동기 추론의 UI 차단을 명시하고 Worker 분리를 설명한다. 이 Story는 확인된 UI 차단 경로를 분리한다. 기존 13건 실패와 PR90/91을 해결 처리하거나 시험 제한을 늘리는 변경이 아니다.

## 수용 기준·검증 계약 — 구현 전

1. 비공개 코칭에서 명시적으로 선택한 Worker 경로만 준비·추론한다. 기존 기본 경로·모델·GPU→CPU 순서·얼굴/손 설정·판정·시각은 유지한다. Worker 미지원/실패를 성공·빈 몸·자동 main fallback으로 숨기지 않는다.
2. Worker는 고정 동일 출처 파일이며 카메라는 버튼/소유 세대 이후 main에서만 요청한다. 한 decoded VideoFrame의 복사본을 동일 Worker에 transfer하고 세 SDK가 같은 입력과 원래 시각을 사용한다. 이미지는 외부 통신·로그·영구 저장·스크린샷으로 내보내지 않는다.
3. 한 번에 한 프레임만 처리한다. 결과의 body/head/hand는 기존 복사·유효성·가림·선행 판정 경계로 전달한다. 세대/요청/시각이 다른 응답이나 중단 후 결과는 사용하지 않는다. 카메라·frame·SDK·Worker의 정상/실패·준비 중 취소·진행 중 취소·재시작을 검사한다.
4. 중단은 main의 카메라와 피드백 권위를 즉시 철회한다. Worker close 확인 뒤 종료하고, 정리 실패/정해진 기술 정리 한도 초과는 고정 cleanup 오류로 보고한다. 결과의 늦은 완료를 성공이나 새 소유자로 승격하지 않는다. 실제 SDK 종료와 Worker 종료를 서로 구분한다.
5. 실제 Chrome의 가짜 카메라·실제 SDK로 세 모델 준비·첫/연속 추론·main의 UI heartbeat·종료를 확인한다. 기존 동기 경로와 제한된 대조를 구분하고 통제하지 못한 성능 인과/실제 사람 정확도를 주장하지 않는다. 필요한 기존 native/소유 수명 회귀, FE/type/Biome/build/공개 경계·byte·diff와 작성자 리뷰를 실행한다. 미달이면 Draft/미완료를 유지한다.

## 제외·승인 경계

새 공개 화면/미승인 구조, 올바른 동작·classifier/임계값·새 조형/GLB, SDK 외부 계측 제품 정책, 영상/좌표 저장·전송 정책 변경, 비용/계정/시크릿/운영 DB migration/배포/출시 없음. Worker 내부 메모리 전달은 서버 업로드가 아니다. 현재 UI 기본 선택이나 SDK 외부 통신을 승인으로 간주하지 않는다. 테스트 영역의 차단 정책은 시험 경계일 뿐이다. 실행 결과·실패·미실행은 따로 보존한다. 전체1~6·D2·실제 촬영/동작/외형·기존 시작P2는 미완료다.

## 구현과 실제 사용자 흐름

비공개 adapter에 `inferenceThread: 'worker'`를 명시한 경우만 몸·얼굴·손을 한 Worker에서 처리한다. 기본 main 경로는 유지한다. 이전 모델/VIDEO 옵션과 GPU→CPU 시도 순서, 원래 프레임 시각, body/head/hand 복사·판정 보류·소유 세대 경계를 재사용한다. 닫기 확인/기술 정리 한도와 native 정리 오류는 성공으로 바꾸지 않는다.

실제 Chrome·SDK·FastAPI·격리 PostgreSQL에서 남녀 각각 로그인→두 기존 GLB 표시→중단→본인 `interrupted` 기록 저장, 준비 중 로그아웃→이전 재개/저장 차단, 실행 중 동일 계정 갱신→기존 Worker 종료→명시적인 새 시작을 확인했다. 준비 취소는 실제 모델 fetch를 시험에서 지연시킨 사례이며 정상 시작 성능 근거가 아니다. 카메라/메일/동작 gate는 합성, 실제 양성 신체 결과·사람/물리 카메라·전문가 검증은0이다. A37 외형은 미완성이고 원본/GLB는 수정하지 않았다.

실패 원본·최종 검증·한계와 작성자 리뷰는 [증거](../review/native-worker-inference/README.md)에 기록한다. 예전 PR90의13건 실패는 별도로 유지한다. 새 경로 통과만으로 간헐적 시작 P2·제품 외부 통신 정책·노트북 정확도/성능·1~6단계 완료를 선언하지 않는다.
