# S4.D4 — 기존 회원·복구 화면 문구 최소화

상태: 제한된 제품 문구 수정·로컬 검증 통과 / 조건부 PR 게이트 전. baseline `0cdacb03972c16ac7b3ddcd914172d444141dfa1`, `codex/account-minimal-copy`.

CEO의 텍스트 최소화 결정 안에서 기존 공개 웹의 내 계정·비밀번호 복구 화면만 정리한다. 새 메뉴/페이지/코칭 구조, 아바타, 인증·API·DB·개인정보 정책, 운영 변경은 없다. 기존 시안 구조 승인과 전체 1~6 완료를 뜻하지 않는다.

## 수용 기준·하네스

1. FR-U-03/04/05·FR-N-03·NFR-08: 중복 소개와 보조 설명을 줄이되 기존 제목·버튼·필드 이름·링크 목적지를 유지한다. 내 계정의 기간별 조회·삭제, 1분 시간·부위별 편차, 알림 미연결, 본인 확인·계정/기록 삭제 범위는 계속 명확하다.
2. 비밀번호 복구의 일회용·30분·15~128자·한글/공백, 가입 여부 비공개, 조건부 요청 접수, 처리 중/오류/재시도·제한 시간·완료/새 링크 안내를 유지한다. 세션 종료·카메라 미사용 안내는 입력 영역 안에서 항상 표시한다. 기존 aside는 850px 이하에서 숨겨지므로 필수 안내를 그곳에만 남기지 않는다.
3. 구현 전에 실제 컴포넌트를 쓰는 새 happy-dom 수용 시험을 실패시킨다. 문구 예산(공백 제외, 대상 설명 문단만: 계정110자/초기 복구120자)은 중복 제거 기준이며 안전 내용을 생략하는 이유가 아니다. 기존 인증·비밀번호 회귀와 전체 frontend/type/정적 검사·production build/후보 기능 공개 차단을 실행한다.
4. 실제 production Chrome에서 원본·수정본의 화면/문구 수를 비교한다. 1440/1024/800px 창, light/dark 선호·동작 감소·키보드, 정상 요청·오류/재시도·429·처리 중 이탈·유효/잘못된 링크·불일치·완료/포커스·로그아웃을 확인한다. API는 이 Story의 브라우저 UI 시험에서 결정적 synthetic HTTP 응답이다. 실제 메일 전달·SQL·시크릿·참여자 검증으로 세지 않는다.
5. 원본 소스/PNG/실패와 최종 소스 SHA·결과를 보존한다. 검토 시 레이블·상태 의미·핸들러/API/라우트 불변과 보안 안내 가시성을 직접 확인한다. 미해결 scoped P1/P2가 없고 최신 diff/HEAD/충돌/체크를 다시 확인한 뒤 조건부 병합한다.

## 디자인 계약

주 작업은 계정의 필요한 항목 선택과 이메일/새 비밀번호 입력이다. 기존 메뉴·섹션·2열/좁은 창 1열·화이트/블루·시스템 한글·타입 스케일·간격·둥근 버튼·초점/상태 스타일을 재사용한다. CSS/새 디자인 시스템을 추가하지 않는다. 중복 소개를 빼고 설명은 한 문장으로 줄인다. 아이콘 전용 버튼이나 안전 안내 접기를 추가하지 않는다.

`web-design-studio`로 기존 구조를 유지하며 실제 화면을 비교한다. UI UX Pro Max의 form 검색 결과에 따라 표시된 필드 레이블과 로딩→성공/오류 피드백을 유지한다. 별도 코칭 구조 승인 없이 공개 코칭 UI를 확장하지 않는다. testing-strategy로 모의 프로토콜/UI와 실제 공급자 검증을 구분하고 code-review로 인증·중요 안내·오류 상태 회귀를 점검한다.

## 결과

[실제 화면·흐름·실패·미실행 조건](../review/account-minimal-copy/README.md). 넓은 창의 계정 본문31.2%·복구 요청19.1%·새 비밀번호20.9% 감소, 800px에서는 없던 보안 안내가 다시 보인다. 회원/복구23·전체1439, 실제 production Chrome 전후 각각14화면/7흐름과 공개 후보 기능 차단·타입/정적/build를 확인했다. API는 이 브라우저 시험에서 합성이며 실제 공급자/메일/SQL 검증이 아니다. 전체 구조/아바타·1~6 통과는 아니며 기존 원본/실패·별도 승인 경계를 유지한다.
