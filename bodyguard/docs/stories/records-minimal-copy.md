# S4.D6 — 기존 수행 기록 화면의 문구 정리

2026-10-10 · baseline main `a466528` · `codex/records-minimal-copy` · FR-R-03/FR-U-04/05/NFR-08

CEO의 최신 답변 **“아바타는 보류하고 독립 웹 작업 진행”**을 적용한다. 아바타 Draft #108의 원본·반려·미실행 증거는 보존됐으며 새 제작/검증 사이클을 시작하지 않는다. 이 Story는 기존 웹의 수행 기록 조회·상세 설명만 다듬는다. 단계 전체 완료나 코칭 구조 승인이 아니다.

## 디자인 계약

사용자 주 작업은 기간별 기록을 조회하고 상세로 이동하는 것이다. 기존 화이트·블루 토큰, 16px/1.25 타입 스케일, 8px 둥근 조작부, 날짜 필드·주 조회 버튼·기록 표·상태별 영역을 재사용한다. 새 메뉴/카드/페이지·아바타·장식 효과나 CSS를 추가하지 않는다. 중복 소개는 없애고 필요한 상태/복구 설명은 한 문장으로 줄인다. 표의 필드, 버튼, 링크·접근 가능한 이름과 데이터 값은 유지한다. 삭제 확인은 별도 위험 행동이며 문구·범위·복구 불가 안내를 줄이지 않는다.

`web-design-studio`/frontend-design으로 직접 기존 컴포넌트·토큰·라우트를 읽고 전후 production 화면을 비교한다. UI UX Pro Max의 `error clarity recovery` UX 검색은 오류의 다음 행동과 role=alert를 유지하는 근거다. 새 디자인 시스템·외부 폰트·모션은 필요하지 않다. 좁은 노트북 창을 확인하되 모바일 앱/모바일 전용 코드는 만들지 않는다.

## 수용 기준·하네스

1. 기록 목록·상세의 소개/보조 문구 중복을 줄인다. ‘완료’는 수행 종료일 뿐 자세 정확성·효과를 보장하지 않는다는 안내를 항상 보인다. 상세의 요약 저장/영상·관절 좌표 미저장 의미를 유지한다. 기존 주요 필드·버튼·링크·API·핸들러·CSS는 그대로다.
2. 로딩/빈 기간/읽기 실패와 재조회/상세 없음/잘못된 기간/페이징·좁은 창·긴 동작 식별자를 검증한다. 실패를 빈 기록으로 보이거나 이전 결과를 재사용하지 않는다. 날짜 오류 문구는 오늘도 선택할 수 있는 기존 검증과 일치한다.
3. 구현 전 happy-dom 수용 시험을 실패시켜 이전 문구를 구별한다. 기존 기록·삭제·API 회귀, 전체 frontend·typecheck·Biome·production build·후보 UI 공개 차단을 실제 실행한다. 문구 예산은 대상 설명의 중복 방지용이지 안전 안내 제거 이유가 아니다.
4. 실제 production Chrome의 원본/최종 화면을 1440/1024/800px에서 저장한다. 상세와 복귀, 빈 화면·503 재시도·404·날짜 오류·페이징, 삭제 미리보기/취소·키보드 초점·dark 선호/reduced-motion·로그아웃을 확인한다. HTTP 응답은 결정적 합성 데이터이며 실제 SQL/공급자·실제 수행 정확도 검증이 아니다. 카메라/SDK/GLB·외부 요청·브라우저 영구 저장은0이어야 한다.
5. 실패한 시험·원본/최종 source/PNG/실제 보고서를 보존한다. 실제 diff·보안·정확성·성능·유지보수와 디자인 상태를 작성자 검토하고 미해결 scoped P1/P2 없이 최신 HEAD/CLEAN/체크 확인 후 조건부 merge commit 병합한다.

## 제외 및 남은 의존성

공개 코칭 구조 대규모 변경·동작 카탈로그 승인·판정/추천 정확도·아바타 제작·카메라/SDK·DB/API 변경·실제 참여자·공급자 연결/시크릿/운영 DB/배포/출시는 하지 않는다. 아바타 외형 P2, 동작별 실측·시범·승인 코칭 구조·운영 조건과 1~6단계 완료 기준은 그대로다. 외부 승인을 기다리는 동안 독립 웹 작업을 진행한다.

## 실제 결과

[전후 화면·사용 흐름·실패·미실행 범위](../review/records-minimal-copy/README.md)를 보존했다. 기존 목록/상세의 본문은12.8%/13.4% 감소, 날짜 오류 안내를 기존 동작과 일치시켰으며 삭제/개인정보 의미를 유지했다. 실제 production Chrome의 원본·최종 각각18화면/7흐름은 합성 HTTP 시험이다. 전체 frontend1481개·type/정적/build·공개 후보 기능 차단과150개 증거 source/bytes를 실제 대조했다. 첫 하네스의 두 실패와 서식 실패를 보존했고 미실행 항목을 성공으로 표시하지 않았다. 조건부 PR gate 전이며 1~6단계 통과를 뜻하지 않는다.
