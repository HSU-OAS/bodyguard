# S4.1 — 본인 스트레칭 수행 기록 API

구현·로컬 검증 진행 · 선행 main 2005b7c · FR-R-03 / FR-U-04 / 출시 계약 4단계

## 범위와 경계

로그인한 본인의 스트레칭 세션 요약을 저장·목록/상세 조회하는 API와 새 로컬 DB migration을 구현한다. 첫 화면용 빈 목록도 실제 API로 제공한다. 원본 영상·좌표·자유 입력 신체 설명·진단·사진은 받지 않는다. 기존 계정 세션/CSRF/no-store 경계를 재사용한다. 운영 migration·배포는 실행하지 않는다.

기록은 수행 흐름의 완료/중단/건너뜀을 뜻한다. 의학 효과·자세 정확성 검증 또는 서버가 운동을 직접 관찰했다는 인증이 아니다. 코칭 adapter가 미완성인 동안 제품 UI는 가짜 기록을 쓰지 않는다.

## CTO 구현 계약

- 본인 소유권은 검증된 쿠키 세션에서 결정. payload/query의 user_id 금지.
- 한 세션에 클라이언트 생성 UUID, 동작/규칙 버전 식별자, 시작/종료 시각, 완료/중단/건너뜀, 관찰된 수행 시간·반복 요약만 받는다. 실제 필드/상한은 구현 전 타입과 시험에 고정한다. 측정 원시값·효과 점수·성공률을 새로 저장하지 않는다.
- 세션 ID 재전송은 같은 본인·같은 내용이면 같은 기록으로 반환, 다른 내용이면 충돌. 다른 계정의 ID 존재 여부를 공개하지 않는다.
- GET 목록은 제한된 페이지와 시작/종료 기간으로 조회. 최신 순서를 시각+ID로 안정화. 상세는 본인만 조회하며 타인의 기록과 없는 기록은 같은 응답.
- 새 migration은 기존 계정·세션·복구·Google 데이터를 보존하고 사용자 삭제의 연계 삭제를 명시한다. 기존 migration 수정 금지.
- API 타입은 실제 OpenAPI로 생성한다. 읽기/쓰기 오류 응답에 payload·민감값 반사 금지.
- 계정 삭제·기간 삭제 화면 및 API는 후속 별도 Story. 본 Story가 서비스 전체 완료가 아님.

## 하네스 수용 기준

기존 전용 PostgreSQL18 test_database 보호 장치를 사용한다. mock 메일은 실메일과 구분한다.

1. 게스트/만료/재설정된 세션의 읽기·쓰기 거부.
2. Origin/CSRF 없는 쓰기 거부. 읽기는 캐시되지 않음.
3. 본인 빈 목록→요약 저장→목록/상세. 타 계정 조회/소유권 위조 거부.
4. 동일 재전송·동시 요청의 단일 기록, 충돌/다른 계정 ID 처리.
5. 잘못된 기간·시간 순서·음수·과도한 크기·원시 좌표/영상/unknown 필드 거부.
6. migration upgrade 및 격리 DB rollback/복원 검사, 기존 데이터 보존.
7. pytest·Ruff/mypy·OpenAPI 생성·frontend 회귀/build·diff check.

명세/하네스 계획은 실제 검증 완료가 아니다. DB 접속은 허용된 격리 DB인지를 읽기 검증한 뒤 실행한다. 코칭 결과 생산·실제 사람 수행·운영 DB·배포는 미실행이며 후속/최종 통합 의존성을 유지한다.

## 실제 구현과 검증 기록

- 본인 쿠키 세션의 POST 저장 / GET 기간별 목록 / GET 상세를 구현했다. 같은 ID·같은 내용의 재전송은 200, 최초 저장은 201, 내용 충돌은 409다. 다른 계정은 같은 ID를 독립적으로 쓸 수 있고 타인 상세 조회는 404다.
- 완료/중단/건너뜀은 client-reported 수행 요약이다. 동작 식별자는 검증된 공개 동작 목록이나 정확성 인증을 의미하지 않는다. 시간 상한 24시간·관찰 시간 상한 24시간·반복 상한 10000·시계 오차 허용 5분은 입력 제한이지 임상 기준이 아니다.
- 목록 기본 20/최대 100, offset 최대 10000, 종료 시각 내림차순+ID 내림차순, start 포함/end 제외다. 동시 새 기록 삽입 중 페이지의 고정 snapshot을 보장하지 않으며 후속 화면은 조회 기준 기간을 고정한다.
- 새 0004 migration은 사용자 삭제 시 기록도 삭제한다. 기록이 있는 downgrade는 백업/복구 계획 없이 거부한다. 실제 실행은 소유한 격리 PostgreSQL18.6뿐이며 운영 migration은 미실행이다.
- 최초 시험은 미구현 테이블로 collection 실패했다. 구현 후 전체 backend 회귀는 기존 head/table 기대값 3건 실패를 기록했고, 새 migration을 반영한 뒤 178건 통과했다. 이후 계정별 같은 ID·폐기된 자격증명 사례를 추가했고, 폐기 세션 쓰기 응답을 기존 CSRF 계약의 403으로 정정하여 재검증한다.
- 실제 OpenAPI 타입 생성·Biome·frontend 215건·TypeScript/Vite build 및 production 후보 목록/미연결 엔진 비노출 검사는 통과했다. 최초 frontend 회귀는 비밀번호 완료 화면 포커스 검사 1건 실패였다. 별도 React 효과가 포커스를 옮길 때까지 기다리는 assertion으로 보완했으며 기준은 유지했다.
- API 구현은 기록 화면·실제 코칭 기록·사람 시험·전체 4단계 완료가 아니다. 후속 Story에서 빈 목록/기간/상세/오류/세션 종료 화면을 실제 API와 연결한다. Stage2 이월 문제와 Stage3 실제 코칭 연결은 최종 통합의 필수 의존성으로 유지한다.
- 추가 보완 후 최종 전체 pytest 179건 통과, 기록 전용 19건 통과, Ruff check/format(20파일)·mypy(6소스)·diff check 통과. Python3.14의 의존성 비동기 함수 deprecation 경고 1건은 남았으며 실패/skip은 아니다. 실메일·실제 사용자·브라우저 기록 화면 시험으로 세지 않는다.
- 로컬 diff 리뷰: 요청 소유권·잠긴 세션·credentials version·Origin/CSRF 재사용, 파라미터 SQL·목록 상한·인덱스, 동일 ID 동시 INSERT의 단일 저장, rollback 거부를 확인했다. scoped 미해결 P1/P2 없음. 삭제 화면/운영 요청 제한·보존 정책/실측 연결은 후속 및 최종 출시 게이트에서 검증해야 한다.
