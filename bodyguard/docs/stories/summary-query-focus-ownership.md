# S4.R9 — 자세 기록 조회의 키보드 초점 유지

기준 main `4489b5bcad71d3d8b6084066e288468d169aba8f`, `codex/summary-query-focus-ownership`.
FR-R-03·FR-U-04/05, 출시 계약4·6. 공개 자세 기록의 기존 기간/페이지/실패 복구 흐름을 보완한다. 새 화면·버튼·문구·CSS·API·저장/권한 정책은 추가하지 않는다.

## 구현 전 문제·권장안

현재 페이지/기간 변경은 응답이 끝나면 결과 제목으로 초점을 옮긴다. 대기 중 사용자가 날짜나 다른 요소로 이동해도 이 boolean 요청은 유지되어 늦은 응답이 사용 중인 초점을 빼앗는다. 이전 전체 회귀의 SW10 초점1실패는 별도로 보존하며, 이번 문제와 같은 원인이라고 단정하지 않는다.

조회 변경 이후 새로운 키보드/포인터/트랙패드 스크롤/초점 이동이 있으면 자동 결과 초점 인계를 포기한다. 계속 기다리는 경우에만 결과의 해당 DOM commit에서 제목으로 인계한다. 문서 비활성·account/key 교체·unmount에서는 초점 권한을 넘기지 않는다. 입력값·요소를 저장하거나 서버로 전송하지 않는다. 기존 auth·요약 검증/재시도·삭제 권한·URL/날짜·빈 상태를 유지한다.

## 수용 기준·하네스

- F1: 지연된 정상/오류 응답 중 날짜/다른 요소로 이동하거나, 같은 요소에서 새 키/포인터/휠 입력이 있으면 그 초점을 보존한다. 실제 공개 App/라우터의 결정적 지연 DOM 시험으로 먼저 RED를 보존한다.
- F2: 추가 입력 없이 페이지/기간 변경을 기다리면 정상·빈 페이지·오류·명시 재조회에서 결과 제목으로 인계한다. 최초 목록과 클릭 상세의 기존 제목/초점을 바꾸지 않는다.
- F3: 새 기간/페이지·계정/문서 이탈·비활성 조건에서는 이전 인계와 요청이 다른 화면의 초점을 변경하지 않는다. listener는 cleanup에서 제거하고 결과 동기 인계는 새 사용자 입력을 기다리며 블로킹하지 않는다.
- F4: 원래 production build의 실제 Chrome/키보드/제어 HTTP에서 수정 전후 늦은 응답의 초점 및 기존 페이지/기간/오류 복구를 검증한다. 합성 계정/기록/API이며 실제 사람 코칭·실제 인증 SQL·OS 접근성/VoiceOver 전체 검증으로 세지 않는다.
- F5: 관련/전체 frontend·타입/Biome·원래 notice build/production guard·diff·source/실패 SHA·작성자 리뷰와 최신 원격 HEAD/main/CLEAN/체크를 실제 확인한다. 미해결 scoped P1/P2가 있으면 병합하지 않는다.

debug는 늦은 응답과 사용자 초점 이동을 분리한다. testing-strategy는 결정적 DOM 경계와 실제 Chrome 흐름을 구분하며 code-review는 초점 탈취/중복 listener/늦은 요청·소유권·입력/레이아웃 불변을 검토한다. 작성자 리뷰이며 독립/전문가 리뷰는 아니다.

## 상태·완료 경계

구현·좁은 로컬 검증 완료. [실제 화면·RED/보완·최종 Chrome7·전체 frontend・작성자 리뷰와 한계](../review/summary-query-focus/README.md)를 보존했다. wheel 누락을 리뷰에서 추가 재현해 passive capture listener로 보완했고 정상 대기 인계는 layout commit에서 수행한다. 기존 요청/소유권/API와 디자인 원본은 유지한다. 병합은 최신 diff/HEAD/main/CLEAN/체크·리뷰 게이트 후에 진행한다.
