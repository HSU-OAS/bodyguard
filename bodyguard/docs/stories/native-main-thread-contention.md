# S6.13 — native 시작과 화면 스레드 경합 분리

2026-10-09 · 시작 main fc70b9d(PR96) · 비공개 원인 조사, 제품 수정/시작 P2 해결이 아님

## 문제와 가설

PR90의 최종26건 중13건은 준비 뒤5초 내 native 반환3개를 받지 못했다. PR91의 정상 재실행은 이 실패를 해결한 증거가 아니다. 카메라→SDK→아바타 준비와 main의 동기 SDK 실행이 화면을 함께 막는지 분리한다. Google의 [공식 Web 안내](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js)는 동기 detectForVideo의 UI 스레드 차단과 Worker 대안을 설명한다. 이는 PR90 원인 확정이 아니다.

FR-M-01/02/07·FR-A-01/03·NFR-07/08. 현재 native 리소스/모델 lite·얼굴·손·남녀 원본 GLB·같은 카메라 설정을 유지한 비공개 시험을 사용한다. 기존 main 기본값과 공개 UI/최소 문구·개인정보/SDK 정책은 바꾸지 않는다.

## 수용 기준 / 하네스

- [x] 현 main과 기존 explicit Worker를 동일한 실제 native 리소스 ports·두 GLB 렌더링 경로에서 비교한다. 계정/API/임상 gate가 없는 낮은 수준의 분리 시험이며 원래 PR90 통합시험의 대체가 아니다.
- [x] 실제 Chrome·가짜 카메라, 새 context마다 normal/CPU throttling의 제한된 교차 순서를 사전에 고정한다. 재시도0. CDP CPU slowdown을 실제 OS 부하·다장치 실측으로 표시하지 않는다.
- [x] 기술적 상대시간만 남긴다: 준비 단계, 준비 뒤 첫/세 번째 delivery, 렌더·RAF 수/최대 공백, 종료/고정 실패 코드. 결과 좌표·영상·스크린샷·얼굴/손 수치·계정은 로그/파일/서버로 내보내지 않는다.
- [x] 세 번째 delivery의 준비 후 상대시각이5초 이내인지 확인한다. 숫자/관찰 시점/모델/화질을 낮추거나 timeout·retry로 성공을 만들지 않는다. 계측 delivery는 기존 nativeCloses가 아니므로 동일 기준 통과라고 주장하지 않는다. Node의 대기 종료/브라우저 응답 지연으로 총 계측 구간은5초보다 길 수 있어 렌더 수를 FPS로 환산하지 않는다.
- [x] 카메라·Worker·SDK·아바타·렌더러를 회수하고 외부 요청을 차단한다. 새로 생성한 dependency link만 정리한다.
- [x] 정상·느린 조건의 실제 결과와 설명 가능한 범위를 함께 남긴다. 원래 실패 재현/최종 소스 통합26건·실제 참여자/장치가 없으므로 시작 P2와 D2/전체1~6 미완료를 유지한다.

## 제외 / 다음 판단

공개 구조/제품 디자인 적용·회원 흐름 변경·판정/임상 수치·기본 thread 변경·모델/GLB/조형·SDK egress 정책·외부 계정/시크릿/운영/배포/출시는 제외한다. UI의 최소 텍스트 원칙과 기존 원본/실패 증거를 보존한다.

차이가 없으면 본 가설을 원인으로 채택하지 않는다. 차이가 있어도 CDP 조건의 main/Worker 경합만 입증하며 과거 간헐적 실패와의 인과는 별도다. 이후 실제 재현과 필요한 통합 게이트를 충족한 응집된 수정만 진행한다.

## 실행 결과와 다음 작업

[실제 비교·실패/한계·무결성](../review/native-main-thread-contention/README.md). 준비→실제 SDK→두 기존 GLB 렌더→관찰 delivery→종료를 확인했다. 공개 코칭·정확한 자세·동작 성공 판정은 없다.

최초8건 이후 계측의 준비/재생 구간 혼합을 작성자 리뷰에서 보완하고 동일 고정 순서8건을 재실행했다. 기존 시간 기준을 완화하지 않았다. 최종 main의 최대 재생 RAF 공백은 정상817~900ms/4×1733~1750ms, Worker도250ms/900~917ms다. Worker에서도 공백이 있어 부드러움 완료 기준은 미충족이다. SDK·첫 GLB 렌더 비용을 각각 분해한 원인 확정이나 개선율/FPS 주장이 아니다. PR90 실패13건은 재현되지 않았고 원래26건은 미실행이다.

다음은 첫 렌더와 첫 SDK 처리의 시간을 따로 대조하는 제한된 조사다. 정상 재실행만 추가하지 않고 설명할 수 있는 기술 구간을 분리한다. 제품 경로 전환·SDK 정책은 별도로 검증하며, 참여자/공개 구조/운영 승인 의존성과 독립이다.
