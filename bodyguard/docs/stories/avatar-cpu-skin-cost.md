# S2.P1 여덟 가중치 CPU 변형 비용 보완

2026-10-16 · 시작 main285e289 · codex/avatar-cpu-skin-cost · FR-A-03/04·NFR-07

## 구현 전 계약

실제 Chrome155.0.8059.80/Apple M4에서 불변 PR150 후보의 두 독립 아바타를 열고 CPU 프로파일을 수집했다. 첫 남성 준비/초기 정확한 전신 검사는3575.8ms였고 WebGL context 생성2479.6ms가 가장 컸다. 이후 짧은 합성 재생은 약16.7ms 간격이었지만 과거의 시작/프레임 P2를 해결한 것으로 보지 않는다.

공유 CPU skin 경로는 모든 정점마다 두 가중치 세트를 위한 중첩 배열을 새로 만들었다. 이 반복 할당만 제거하며 여덟 가중치·현재 geometry/뼈 행렬 조회·Vector3/Vector4·bind 변환·정확한 전신 구도와 독립 복제는 유지한다. 모델/관절/재질/리깅 정확도를 줄이지 않는다. GPU context 초기화의 원인 해결은 이 변경의 완료 기준이 아니며 별도 미완료로 명시한다.

## 하네스와 수용 기준

- 모든 여덟 influence의 현재 뼈/역행렬과 bind를 직접 합산한 독립 oracle을 쓴다. 서로 다른 정점·다중 축 회전/비균일 scale·위치/방향 벡터, 늦은 뼈 변경/attribute 교체와 두 복제의 독립성을 검사한다. 기존 잘못된 입력 거부/자원 정리/셰이더 검사를 유지한다.
- 동일 GLB SHA·관절/삼각형 수를 보존한 실제 Chrome에서 수정 전/후의 정확한 전신 CPU skin 계산 비용을 비교한다. 첫/모든 샘플을 보존하며 GPU context cold/warm 차이를 CPU 개선으로 보고하지 않는다.
- PR150의 비공개 검수 조회 보완을 재사용한다. 진행 조회는 저비용 sequence만 읽고, 처음/움직임 뒤의 정확한 전신·원본 불변·8가중치·방향 오차와 같은10초 조건은 유지한다. 별도 카메라/제품 route/공개 모델 적용은 없다.
- 관련/전체 frontend·타입·Biome·원래 build/production guard·diff, 실제 Chrome 남녀 리그를 검증한다. 실패도 원본으로 보존하고 미해결 P1/P2가 있으면 병합하지 않는다.

## 결과

같은 Chrome 페이지의 독립 ABBA에서 남성86.75→83.90ms/여성88.15→83.80ms의 CPU 전신 계산 감소를 확인했다. 모든 원문/느린 샘플과 초기 GPU 생성2479.6ms를 별도 보존하며 초기 P2 해결로 확대하지 않는다. 관련40/전체1932·타입/Biome/build/guard·A37 남녀/owned 자원 남녀가 통과했다. [실제 작동·실패·작성자 리뷰·미완료](../review/avatar-cpu-skin-cost/README.md). 새 아바타 외형 적용/제품 공개0, 최신 PR 게이트를 거쳐 다음 필수 연결로 진행한다.
