# S3.C10 — 버리는 얼굴·손 추론의 생략

기준 main `c57c1a331ae4f264138e72dc6c797aaf23950243`, `codex/body-gated-worker-inference`.
FR-M-02/07·FR-A-03·NFR-07/08. 아바타 보류와 기존 판정 기준을 유지하는 입력 처리 보완이다.

## 구현 전 확인·권장안

Worker와 body-face/body-hand 영상 adapter는 몸이 없거나 복수·불완전·비유한 좌표이면 얼굴·손 후보를 이미 버린다. 그런데 버릴 후보를 계산하는 SDK 호출은 계속한다. 이 기존 single-body 구조 검사를 **호출 전에** 적용한다. 새 가시성/인체·자세 임계값이나 사람 일치 판단을 만들지 않는다. 유효 몸이면 기존 같은 프레임·시각의 몸→얼굴→손 복사/호출을 유지한다.

몸 검출·선택 모델/heavy 기본값·얼굴/손 초기화·GPU→CPU 복구·30초 준비/5초 Worker 한계·몸 결과와 프레임의 회수는 바꾸지 않는다. 해당 프레임의 얼굴 null/손 빈 배열, disabled 필드 생략을 유지한다. 같은 초기화 자원에서 다음 유효 몸의 후보 계산을 재개한다. 필요 없는 SDK 호출이 던지는 오류 때문에 미검출 몸의 처리까지 실패하지 않도록 한다. 유효 몸의 실제 SDK/정리 오류는 기존 실패로 남긴다.

## 명세·하네스 수용 기준

- G1: 세 경로에서 몸 없음/복수/누락 world/짧은 image 또는 world/비유한 좌표는 얼굴·손 호출0. 기존 몸 결과 복사·null/빈 후보·한 번 회수는 유지한다. 합성 unit의 검출 정확도를 실제 사람 정확도로 세지 않는다.
- G2: 같은 owner에서 유효→미검출→유효를 처리하며 후보가 사라졌다 복구된다. 모델 재초기화/보간 추정/옛 후보 재사용 없이 기존 프레임·시각을 전달한다.
- G3: 생략 경로의 얼굴/손 오류는 실행하지 않는다. 유효 몸의 오류, abort/retirement·진행 중 추론 종료 barrier·close 실패 격리는 그대로다. 초기 RED와 실패 결과를 보존한다.
- G4: 동일한 비공개 blank-frame 하네스와 고정 원본/heavy+얼굴+손을 사용한 실제 Chrome/SDK에서 수정 전후 출력 모양·첫/후속 입력·정리를 확인한다. normal/CDP4×는 따로 기록하고 인위적 빈 입력·왕복 시간임을 명시한다. 실제 촬영·유효 사람의 복구·다장치·임상/전체 성능 통과로 일반화하지 않는다.
- G5: 관련·전체 frontend, 타입/Biome, 원본 asset 검증, 원래 notice build/production guard, diff·작성자 리뷰·최신 원격 HEAD/main/CLEAN/체크를 통과한다. 원본·GLB·공개 UI/API·스토리지·운영은 변경하지 않는다. scoped P1/P2가 남으면 병합하지 않는다.

testing-strategy에 따라 호출/실패 경계는 결정적 unit, SDK 호환·출력·종료는 실제 브라우저로 분리한다. debug는 같은 하네스 전후를 비교하고 code-review는 유효 입력 손실·초기화/회수·모델 선택·추론 지연의 범위를 점검한다. 작성자 검토이며 독립/전문가 검토는 아니다.
