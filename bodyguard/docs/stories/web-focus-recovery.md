# S6.8 — 보호 화면의 비동기 초점 복구

상태: 로컬 구현·필수 검증 완료 / 조건부 PR 게이트 · 2026-10-08

## 사용자 가치 / 근거

가입·로그인 후 시작, 탐색, 계정 화면을 키보드로 이용할 때 계정 확인이 끝난 실제 화면에서 이어갈 수 있어야 한다. FR-U-04/05, 출시 계약4·6단계, [웹 디자인의 상태·접근성 계약](../web-design.md)을 따른다. 화면 구조·색상·문구·판정이나 인증 정책은 바꾸지 않는다.

최신 main9f2e76f(PR #61 실제 merge)에서 시작한다. S6.7의 정상 profile은 시작 제목의 초점 false를 기록했지만, 그것만으로 제품 결함이나 과거 지연 원인을 확정하지 않는다. 지연된 합성 계정 응답으로 DOM·실제 production Chrome의 별도 재현을 먼저 수행한다.

## 수용 기준

| ID | Given / When / Then |
|---|---|
| F01 | 시작·탐색·계정을 직접 열고 계정 응답이 늦으면 / 확인 뒤 / 현재 화면 제목으로 초점이 이어진다. |
| F02 | 계정 확인 실패 또는 로그아웃 실패 상태에서 / 명시 재시도 후 / 확인 중·성공 또는 실패의 현재 제목으로 이어진다. 개인 화면을 추정으로 열지 않는다. |
| F03 | 확인 중 사용자가 남아 있는 헤더 링크나 본문으로 초점을 옮기면 / 응답 뒤 / 살아 있는 그 초점을 빼앗지 않는다. |
| F04 | 공개 로그인·복구·도움말의 입력이나 FAQ를 이용하면 / 계정 상태만 바뀌어도 / 초점과 입력을 보존한다. |
| F05 | 문서가 초점을 갖지 않으면 / 초기·비동기 전환 뒤 / focus 호출로 브라우저 창을 활성화하지 않는다. |
| F06 | 기록·알림 설정·탈퇴 등 화면 자체가 초점을 관리하면 / shell 갱신 뒤 / 기존 담당 컴포넌트의 초점을 덮지 않는다. |
| F07 | 실제 Chrome에서 / 기존5000ms 조건·재시도0으로 / 재현과 경계 검사를 기록한다. 원본 실패·기존 파일을 보존한다. |

주소 끝 슬래시·대소문자도 Router가 같은 보호 화면으로 연결하는 경우 F01을 적용한다. 제목 문구·메뉴·화면 구성은 바꾸지 않는다.

## 하네스 / 필수 검증

- happy-dom: 지연 응답·재시도·로그아웃·공개 입력 보존·살아 있는 링크/본문·문서 비활성·페이지 담당 경계. 시간 확대 없이 결정적인 Promise를 사용한다.
- production Chrome: 실제 React/Router/CSS, 합성 계정 응답은 명시한 시험 주입만. 카메라·모델·외부 통신·브라우저 저장0, 오류0. 원본·수치·실행 소스 SHA와 소유 자원 정리를 기록한다.
- 전체 DOM, typecheck, Biome, production build와 개발/미검증 producer 차단, 문서 링크·diff 검사. API·SQL·운영 검증으로 세지 않는다.
- 작성자 diff 리뷰 후 미해결 scope P1/P2 없음·최신 main/exact HEAD/CLEAN/체크 확인일 때만 조건부 PR 병합한다.

## 제외 / 남은 기준

미승인 디자인 구성 확장·아바타·실측·코칭 공개·SDK 정책·인증 API·운영 DB/계정/시크릿/배포 변경은 없다. 실제 시작 지연 P2의 원인·실제 참여자·Docker/NGINX/TLS·provider와 전체1~6단계 통과는 이 Story로 완료하지 않는다. 같은 아바타 부위의 새 수정 사이클도 시작하지 않는다.

## 구현 / 실제 결과

Shell의 pathname만 보던 효과는 같은 주소에서 계정 확인 제목이 실제 화면 제목으로 교체되는 전환을 놓쳤다. 보호된 시작·탐색·계정만 계정 phase도 추적하며, 사용자 선택이 살아 있으면 보존하고 제거된 대상만 현재 제목으로 복구한다. 문서가 비활성이면 focus를 호출하지 않는다. 기록 등 기존 담당 페이지의 경계는 유지한다.

리뷰에서 주소 변형 누락과 Biome의 불필요 dependency 경고를 발견했다. 주소 변형은 실제2건 RED 후 Router 조건과 일치시키고, 이전 path/phase를 함께 비교하여 효과의 조건과 dependency를 일치시켰다. 경고를 억제하거나 기존5000ms를 늘리지 않았다.

실행·수치·원본 SHA·작성자 리뷰·미실행 항목은 [증거](../review/web-focus-recovery/README.md)에 있다. 후속 정상 회귀는 과거의 제품 시작 지연 원인이 해결됐다는 증거가 아니다.
