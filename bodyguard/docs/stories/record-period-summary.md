# S4.R10 — 기존 자세 기록 화면의 일·주 집계 연결

2026-10-11 CEO 승인 · 시작 maine7f513af8fae106cbaa69aab4065b3f311b121a3(PR146 병합) · codex/record-period-summary

## 사용자 가치와 범위

FR-R-03/06·FR-U-04·NFR-08: 로그인한 사용자가 기존 /posture-records 화면에서 날짜와 일/주를 고른 뒤 실제 저장된 전체 기록을 조회한다. 기존 집계 API/strict parser/useOwnedDashboard를 재사용한다. 현재 페이지20개를 기간 전체로 오해시키지 않는다. 새 메뉴/route/디자인 개편·카메라/판정/아바타·운영 변경은 없다. Draft51·과거 시작P2와 실패/원본은 보존한다.

## 화면 계약과 수용 기준

1. 기존 제목·기간 목록·상세·삭제·복귀는 유지한다. 목록 아래가 아닌 기간 조회 근처에 '일·주 기록 요약'의 날짜·단위·명시 조회를 둔다. 기존 white/blue 토큰·48px 제어·8px 모서리·표/초점 스타일을 재사용한다. 새 차트/색 점수/의학 판단은 없다.
2. 기본 날짜는 기존 종료 날짜, 집계 시간대는 기존 목록과 같은 브라우저 IANA 시간대로 명시한다. 주는 서버 계약의 월요일 시작이다. 유효하지 않은/미래 날짜는 요청하지 않고 수정 경로를 제공한다.
3. 조회만 GET 본인 집계를 연다. 날짜/단위 편집은 옛 결과를 즉시 폐기하며 새 명시 조회 전 자동 요청하지 않는다. 목록의 새 요청·삭제/불확실/계정 회수·pagehide/unmount에도 이전 집계를 보존/자동 재개하지 않는다. 늦은 성공/401/403은 새 계정·결과를 덮어쓰지 않는다.
4. 전체 분/측정 시간·수행/중단/건너뜀과 부위별 평균/측정 시간/이탈 비율을 저장된 값 그대로 표시한다. 기준선/버전/방법/단위가 다른 행은 섞지 않는다. 보정 전/null은 —이며 정상/0점/임상 효과 인증이 아니다. 알림 수는 임의의 0으로 만들지 않는다(출시 후).
5. 초기/대기/빈/오류/명시 재조회를 제공한다. 기록이 없는 기간과 부분 측정은 분리한다. 403은 기존 계정 재확인 경로로 보내 목록/삭제 권한도 회수한다. 조회 결과가 입력/다른 작업의 초점을 빼앗지 않는다.

## 하네스와 필수 검증

실제 App/router/AuthProvider를 사용하는 결정적 DOM 시험을 구현 전 RED로 작성한다. 전체 기간21개 vs 목록20개·일/주·부위 분모·null/기준·빈/오류/재조회·편집/늦은 응답·403·기존 기록 흐름을 검사한다. 실제 production Chrome→loopback FastAPI→새 소유 PostgreSQL의 합성 계정/기록에서 정상·오류·다른 계정·삭제 후 집계·키보드/좁은 노트북 화면을 실행한다. SDK/카메라/사람·메일 공급자·운영/HTTPS 시험은 아니다. 관련/전체 frontend·원래 build/Biome/production guard·diff와 작성자 리뷰를 실행한다. 실패/미실행은 구분하고 과거 시작P2를 성공 재시험만으로 닫지 않는다.

## 제외/게이트

비용/계정/시크릿·운영 migration·외부 공급자·Docker·배포·출시·CI·아바타/실측/권리·임계값·신체 분석/추천 승격 변경0이다. 네 부가 기능은 ADR-0019 후속이며 그 외 전체1~6 기준은 유지한다. scoped 필수 검증/미해결P1/P2 없음·최신 main/diff/HEAD/CLEAN/체크(없으면 없음) 확인 후 사전 승인 조건부 merge commit, 브랜치 삭제0이다.
