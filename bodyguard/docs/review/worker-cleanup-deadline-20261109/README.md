# Worker 정리 응답의 시간 경계

2026-11-09 · 시작 main `c913a4d3` · 기존 SDK 종료 지연 P2는 미해결

추론 응답과 마찬가지로 Worker 정리 ACK에도 기존 5초 기한을 단조 시계로 적용한다. 메인 스레드가 바빠 타이머 콜백보다 기한이 지난 ACK를 먼저 처리하더라도 정상 정리로 받아들이지 않는다. 기한 전 정상 ACK는 기존과 같고 타임아웃이나 종료 정책은 늘리지 않았다.

모의 Worker에서 시계를 따로 움직여 타이머 콜백을 지연한 상태의 4,999ms 정상 종료와 5,000ms·5,001ms 실패를 검사한다. 수정 전에는 뒤의 두 검사가 실패했고 원문은 당시 터미널에만 남아 있다. 수정 후 전체 129파일·2,172개 테스트, 변경 파일 Biome, TypeScript, Vite production build와 production guard가 통과했다. [전체 로그](full.log.gz) · [빌드 로그](build.log.gz).

별도 개발용 어깨 후보 PR #163의 브라우저 시험 runner에 이번 변경된 Worker owner 소스를 Vite transform으로 주입하고 Chrome 156·빈 가짜 카메라·실제 SDK/Worker/GLB로 시작, 일시정지, 재개, 중단을 1회 확인했다. 52개 요청과 응답, 외부 요청·쓰기·페이지 오류 0이었다. 테스트는 SDK Worker에 고정 진단 로그를 추가했고, 시험 종료 시 계산된 주입 파일 SHA는 `daec71928a333ccf03ba94ab3e2612a8237e0689b9d03dd35e26683e88975f15`이다. 실행 전후 동일성의 별도 기록은 없다. [집계](native.json) · [로그](native.log.gz) · [실행 runner](native-runner.mjs). 이 runner의 나머지 fixture는 #163 브랜치의 `0a463a51`을 사용한다.

이 수정은 지연된 응답의 판정만 보완하며 실제 SDK의 간헐적인 `close()` 지연이나 노트북 초기 속도를 해결했다고 주장하지 않는다. 실제 사람·물리 웹캠·자세/손 정확도와 최종 아바타는 검증하지 않았다. 운영 배포·공개 활성화는 하지 않았다.
