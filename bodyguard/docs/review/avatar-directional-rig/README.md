# 실제 남녀 리그 방향 연결 검증

기존 Blender 유래 A37 모델 두 개에 서로 다른 합성 사지 방향을 전달했다. 부모 전체 변환행렬을 사용해 관절 방향을 맞추고, bone 길이·위치·배율·mesh·가중치는 수정하지 않는다. **실제 카메라 추적·운동 정답·완성 외형·출시 코칭이 아니다.**

## 실제 화면과 사용자 가치

남녀 각각 독립된 두 skeleton의 팔·다리 방향8개가 입력을 따라 움직인다. 관측이 사라지면 이전 관측과 합치거나 정답 자세로 보정하지 않는다. 표시용 보간과 실제 관측의 유효 범위는 별개다. 모델 길이·비례를 바꾸지 않으며 단일 방향으로 알 수 없는 축 비틀림·목·체간·손은 생성하지 않는다.

발끝까지 보이는 [남성 기술 화면](accepted-male-after.png)·[여성 기술 화면](accepted-female-after.png)은 **미완성 A37의 비공개 합성 검증 화면**이다. 제품의 승인된 코칭 디자인이나 최종 아바타 미리보기가 아니다. 얼굴/목·손/관절 표면 마감 P2는 그대로다. 신체 좌표계 정확도·지연·현실 가림은 실제 참여자 검증이 필요하다.

## 검증·실패 구분

- 최초 red: 모듈 없음으로 수집 실패, 동작 시험0개. 첫 unit6통과/4실패는 Quaternion callback 속성 비교와 하네스의 부동소수 기대값 오류였다. 수치 성분 비교로 수정했으며 기존 결과는 보존했다.
- 첫 Chrome: 남성 준비 실패, 여성 미실행. 실제 원본 root의 미세한 비균일 scale을 발견했다. 허용 오차 증가/GLB 배율 정규화 없이 **affine inverse**를 구현했다. 양수 비균일 배율 red11통과/1실패→green25통과, 원래 음수/0/비유한 변환 거부는 유지했다.
- 작성자 리뷰: cloned skeleton의 GPU texture 미해제와 반복 dispose를 새 red26통과/1실패로 재현했다. clone 소유 skeleton texture/geometry/material의 멱등 해제와 source 비해제를 보완했다. rest bounds가 움직이는 사지를 자르지 않도록 검수용 skinned mesh culling을 끈다. 목표 노트북 성능 합격의 대체물이 아니다. 리뷰 green27통과.
- 첫 실제 화면에는 발끝 잘림이 있었다. 실제 skinned 정점을 투영하는 경계 검사를 추가한 framing red를 보존하고, 직교 카메라의 상대 구도를 수정했다. 남녀 전신·동작 후 경계가 통과했다. 실제 Chrome154/GLTFLoader/WebGL 사용, 방향 입력은 합성이다.
- 전체 frontend792통과·타입/Biome/build/공개 guard를 실행했다. 첫 asset 준비는 sandbox DNS에서 실패했고, 기존 동일 버전 로컬 모델5개를 사용해 원래 준비/build 명령을 완료했다. SDK/카메라를 실행하거나 승인 대기 통신 정책을 바꾸지 않았다.
- 기존 공개 JS/CSS는 PR63 출력과 byte 동일, 공개 GLB0. API 변경0이므로 backend·SQL·실제 가입/메일/Google 검증을 이번 실행으로 세지 않는다.

원본 로그/실패/실제 실행 source SHA·GLB SHA·검수 이미지·공개 출력은 [summary.json](summary.json)에 나열한다. 전신 각도 오차는 **합성 렌더 방향의 수학적 오차**이며 사용자 자세의 정확도·정답 허용 각도가 아니다. 50ms 반감기/250ms 유효기간/15° 합성 변형은 기술 fixture의 명시 입력이지 임상 기준이 아니다.

## 보존과 검토

PR9 source `25a9bd6c7392890e3b5d5d6ae1046bb7087d56ad`에서 GLB 두 개를 임시 추출해 Git blob와 byte 동일함을 검사했다. 새 GLB/Blender 조형0·기존 후보 worktree 수정0이다. 기존 후보 worktree의 추적 파일1959개가 삭제 상태였으므로 원인이나 복구 권한을 가정하지 않았다. Git에 보존된 파일·원격 PR9의 source를 기준으로 진행했다. 이 Story가 기존 로컬 삭제를 승인하거나 일으킨 것은 아니다.

graphify의 기존 그래프는 legacy skeleton/face 경로만 보여 최신 authored GLB 연결은 실제 코드를 직접 대조했다. testing-strategy/code-review를 사용해 계층 수학·가림·세대/시간/해제·원본 격리와 공개 차단을 검토했다. 독립 에이전트/전문가/Figma 검토는 수행하지 않았다. 수정 범위에서 남은 P1/P2는 발견하지 않았지만 제품의 D2-A/M/T/I/P·SDK/디자인/실측/외부/운영·전체1~6 필수 기준은 미완료다.
