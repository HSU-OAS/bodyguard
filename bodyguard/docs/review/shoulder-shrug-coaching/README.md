## 이번에 구현한 것

목 전용 판정 다음으로 어깨 으쓱의 같은 프레임 관찰과 실제 판정 코드를 추가했다. 골반선과 촬영 종횡비/반전을 기준으로 양어깨 높이·머리 위치/방향·몸통 기울기·위팔 방향을 계산한다. 귀–어깨 거리 감소만 성공으로 취급하지 않는다. 명시 검수 프로필에 따라 시작·양측 상승·유지·복귀, 머리/몸통/팔 보상·한쪽 상승·과범위를 분류한다.

판정은 기존 실제 `createCoachingSession`/자원 controller/진행 엔진에 연결하는 adapter를 통해 전달한다. 현재 동작/프로필/세대/단계가 같아야 하며 외부 getter가 중간에 세션을 바꾸면 전달하지 않는다. 같은 오류 영역의 중복 표시는 합치고 원시 지표/좌표는 피드백이나 기존8필드 결과 DTO에 들어가지 않는다.

**새로운 어깨 실행 화면이나 완성된 어깨 코칭을 제공한 것은 아니다.** 화면·새 Blender/GLB·리깅·공개 목록은 변경하지 않았다. 다음 작업은 실제 남녀 GLB의 양측 어깨 상승 표현과 두 아바타 실행 UI/표면 오류·단계 시범 연결이다. 현재 사지/몸통/머리 방향 rig만으로 그 상승이 충분히 재현된다고 주장하지 않는다.

## 실패와 작성자 리뷰

1. `scoped-a`: import 순서 오류2. 해당 import만 정렬하고 scoped/전체 검사를 다시 통과했다.
2. `build-a`: 예외를 던지는 시험 getter의 추론 반환 타입이 void여서 원래 TypeScript 빌드가 실패했다. getter의 실제 image 반환 타입을 명시했고 원본 시험 소스 gzip/로그를 보존했다. 행동 기대를 바꾸거나 타입 검사를 우회하지 않았다.
3. 작성자 P2/`roundoff-red-a`: 매우 큰 정규화 값에서 시작/목표 band 사이 간격이 비교 함수의 상대 반올림 오차보다 작아도 프로필이 허용됐다. 해당 큰 값의 실패를 재현한 뒤, 같은 수치 크기를 반영하는 분리 검증을 추가했다. 임상 허용오차를 확대한 것이 아니다. 실패 `thresholds.ts` gzip/로그와 보완 후 실제 재실행을 보존한다.
4. 리뷰 중 첫 오류 영역 중복 시험이 두 오류의 동시 발생을 실제로 만들지 않는 것을 확인해, 머리/몸통 보상을 동시에 같은 영역에 매핑하는 입력으로 시험을 바로잡았다. 해당 첫 통과를 중복 제거 입증으로 사용하지 않는다.
