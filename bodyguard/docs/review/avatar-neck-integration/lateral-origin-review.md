# 전문 원본 대조 작성자 리뷰

2026-10-10 · engineering:code-review · [실제 결과](lateral-origin/README.md) · 전문가/외부 리뷰 아님

## 실제 범위

`inspect_lateral_origin.py`의 factory-startup/disable-autoexec 실제 exit0와 보고서/로그, fixed-list collector와 Story 계약을 검토했다. 원본 A318의 국소 점 배치와 현재 부분 후보의 연결·skin/좌표를 분리해 비교한다. 저장/저작·실제 사람·제품 UI 변경0이며 4개 증거를 보존했다. 후속 저작 결과와 독립 재열기/외형 검증은 이 대조의 완료로 대체하지 않는다.

## 검토

- 보안/개인정보: 알려진 전문 에셋만 읽고 인체 촬영 자료·카메라·SDK·로그 좌표 정책을 바꾸지 않는다. 두 원본 SHA, male/female body/rig snapshot 불변을 실제 확인했다. 사용자 장면·설정·계정·비용 변경0.
- 정확성: ID 유일성, 회전과 winding을 구분한 6개 면 대응, 같은 world/그룹과 9점 raw skin/one-ring을 확인했다. 좌표 변화와 원래 정상 연결을 구별하며 6면의 원인을 전체 원인이나 정확한 중간 단계로 확장하지 않는다. “원래 입력”과 “전문 원본”을 명시적으로 구분한다.
- 경계/유지보수: private BMesh는 finally에서 free, source mesh에 to_mesh/save를 쓰지 않는다. frozen report SHA와 알려진 face/ID를 대조한다. 새 collector는 고정 파일명·regular file/실경로·raw/gzip SHA·source exact·wx를 강제한다. byte 감사와 native 실행을 혼동하지 않는다.
- 성능: 대조는 개발용 별도 native 프로세스이며 공개 웹 런타임에 추가되지 않는다. 전문 원본 6면/9점의 제한된 결과만 보존한다. 읽기 중 snapshot/면 순회 비용은 실시간 성능으로 주장하지 않는다.

## 판정

대조 범위의 새 P1/P2는 발견하지 않았다. PR #108의 **기존 외형 P2는 미해결 → Request Changes / Draft 유지 / 병합하지 않음**. 새 아바타·GLB/전체변형/Chrome·실측·전체1~6 완료가 아니다. 최종 커밋/푸시 전 보존 byte·정적·링크·diff와 후속 실제 제작 결과를 별도로 확인한다.

## 실제 검증

새 Python2개 Ruff check/format --check, collector2개 Biome check, 관련 Markdown8개/로컬 링크334개 누락0, git diff --check와 origin/main 전체 diff --check는 실제 exit0였다. 새4/8개와 이전12/39개 collector --check는 byte 감사exit0이며 native 재실행이 아니다. 두 collector의 중복 archive는 실제 exit1/EEXIST로 거부했고 해당16개 보존 파일의 전후 fingerprint `38e9891fc5b2e166583a387a98c3e82b781c4c9575ff5eb776cfd4729d539201`은 같았다. 새 native는 대조0/저작1이며 제품 build/DOM/API/SQL·실제 사람/카메라/GLB·변형/브라우저는 이번에 실행하지 않았다.
