# 세 모델의 실제 delegate 확인 — 별도 계측 실행

2026-11-09 · 테스트 전용 · 실제 사람·정확도 검증 아님

[앞선 CPU 우선 비교](../allcpu-20261109/README.md)는 실제 fallback 여부를 기록하지 않았다. 이에 시험 중에만 SDK 생성 시도·성공·fallback의 고정 문자열과 모델 생성 순서 1=신체, 2=얼굴, 3=손을 기록하는 [진단 엔진](diagnostic-engine.ts.txt)을 만들고 별도 실행했다. 로그는 영상·좌표·에러 원문을 수집하지 않는다. 테스트용 코드는 실행 후 되돌렸고 SDK 모델, 응답/종료 기준이나 공개 제품은 바꾸지 않았다.

- [실제 Chrome/빈 가짜 카메라 코칭](ui.json)에서 두 세대 모두 모델 1·2·3의 `create-success CPU`가 기록됐고 시작·일시정지·재개·종료가 완료됐다([원문](ui.log.gz), [runner](ui-runner.mjs)).
- [공개 스쿼트 영상](video.json)에서 세 모델 모두 CPU 생성 성공이 기록됐고 45프레임 처리와 정리가 완료됐다([원문](video.log.gz), [runner](video-runner.mjs)). 부모의 추론 응답 시간 중앙값 약 126.4ms, p95 약 139.4ms, 최대 약 346.7ms였다. 얼굴 방향은 0프레임에서 확인돼 이 영상으로 얼굴 정확도는 평가하지 못했다.

이 두 실행은 한 기기·한 영상 및 빈 카메라에서의 별도 계측 결과다. 이전 실행에도 fallback이 없었다고 소급할 수 없으며, 실제 사람의 자세/손/얼굴 정확도, 장시간 또는 다른 노트북의 성능과 기존에 재현된 Worker 오류의 근본 해결도 입증하지 않는다. 사용자에게 출력되는 판정 또는 출시 동작은 변경하지 않았다.
