# 손 CPU 후보 결합 코칭 시작·일시정지 반복

2026-11-09 · 실제 Chrome/Worker/SDK/GLB, 빈 가짜 카메라 · 실제 사람 정확도 검증 아님

Draft #163에 [PR #189](https://github.com/HSU-OAS/bodyguard/pull/189)의 손 CPU 우선 코드만 임시 적용하고, 기존 `scripts/test-neck-workspace-native.mjs`의 어깨 경로를 네 번 순차 실행했다. 시험 종료 뒤 임시 코드는 원래대로 되돌렸다. [a](repeat-a.json) · [b](repeat-b.json) · [c](repeat-c.json) · [d](repeat-d.json), 같은 이름 `.log.gz`는 각 실행 원문이다.

첫 실행은 Worker 준비 후 첫 추론이 5초 제한을 넘겼고, Worker 종료 확인도 5초 안에 도착하지 않아 `cleanup-error`가 발생했다. 준비 화면 확인은 30초 후 실패했다. 고정 이벤트만 수집해 어느 SDK 내부 작업이 느렸는지는 확인하지 못했다. 이후 세 실행은 시작·일시정지·명시적 재개·중단을 완료했고 각 두 세대의 clean ACK를 받았다. 네 실행에서 외부 요청·쓰기·페이지 오류는 0건이었다. 빈 카메라에서 동작 성공이나 기록이 발생하지 않도록 검사했다.

**첫 실패로 손 CPU 우선만으로 간헐 첫 추론·종료 문제가 해결됐다고 할 수 없다.** 뒤의 세 통과도 오류를 지우지 않는다. 실제 사람·물리 웹캠·손 추적·동작 정확도와 다른 기기·장시간 사용은 시험하지 않았다. 출시 적격 동작은 0개이며 두 PR은 Draft를 유지한다.
