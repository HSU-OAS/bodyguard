# 신체·얼굴·손 CPU 우선 비교 — 시험 전용

2026-11-09 · 한 노트북 · 실제 사용자·출시 검증 아님

손과 신체만 CPU로 실행해도 종료 실패가 재현된 [이전 시험](../bodyhandcpu-20261109/README.md)에 이어 세 모델을 모두 CPU 우선으로 초기화하고 생성이 실패할 때 기존 GPU fallback을 사용하는 [임시 코드](workerNativeEngine.ts.txt)를 시험했다. 모델 파일·기능·5초 기한과 개인정보 경계는 바꾸지 않았다. 코드 SHA-256 `c14bd15b9d0307e07d5328195b3d0a7a74c6dd6083364b0db65f2aa6efe8d753`이며 이 코드는 실행 후 되돌려 제품에 적용하지 않았다.

## 시작·정리

실제 Chrome/Worker/세 SDK/GLB와 빈 가짜 카메라에서 어깨 코칭 시작·일시정지·재개·중단을 네 번 순차 실행했다([a](allcpu-a.json), [b](allcpu-b.json), [c](allcpu-c.json), [d](allcpu-d.json)). 네 실행 모두 두 세대의 Worker clean ACK를 받았고 카메라·아바타를 정리했다. 외부 요청·쓰기·페이지 오류는 0이었다. 진단 helper가 고정 자원 이벤트를 수집했다. 다른 기기·부하·장시간에서의 안전성이나 이전 설정의 실패가 해결됐다는 증거는 아니다.

## 공개 녹화 영상 응답 시간

같은 공개 스쿼트 영상을 가상 카메라에 넣어 CPU/CPU/CPU 조합 B를 두 번, 신체 GPU·얼굴 GPU·손 CPU 조합 A를 두 번 순서대로 실행했다([B1](timing-b1.json), [B2](timing-b2.json), [A1](timing-a1.json), [A2](timing-a2.json)). 각 실행은 45프레임을 처리하고 카메라와 Worker를 정리했다. [시험 runner](video-runner.mjs)는 부모의 `owner.detect` 시작부터 응답까지의 경과시간만 집계하며 원시 영상·좌표는 저장하지 않는다.

| 조합 | 두 실행의 중앙값 | 두 실행의 p95 | 두 실행의 최댓값 |
| --- | --- | --- | --- |
| B: 전부 CPU | 약 124.1·125.1ms | 약 132.6·133.7ms | 약 353.5·345.7ms |
| A: 신체·얼굴 GPU, 손 CPU | 약 119.1·121.0ms | 약 135.2·134.6ms | 약 1467.9·775.6ms |

한 기기·한 영상·각 45프레임의 짧은 순차 시험이다. 촬영 프레임은 재생 시점에 따라 일치하지 않을 수 있고 실행 순서·부하는 통제하지 못했다. 수치는 절대적인 기기 성능이나 프레임별 동등성·정확도가 아니다. 얼굴 방향은 이 표본에서 0개이므로 얼굴 추적의 정확도나 성능을 평가하지 못했다. A/B 간 신체·손 출력의 실제 정답이나 정확도 차이는 측정하지 않았다.

앞선 두 설정의 간헐 첫 추론·정리 실패, 세 모델 CPU 설정의 실제 사람 자세/손/얼굴 정확도와 다른 노트북의 장시간 성능은 미해결이다. 이 탐색만으로 CPU 우선 방식을 채택하거나 출시 적격 동작을 열지 않는다.
