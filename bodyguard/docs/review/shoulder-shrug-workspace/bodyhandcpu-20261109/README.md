# 신체·손 CPU 우선 시험 — 미채택

2026-11-09 · 임시 코드·공개 녹화 영상·빈 가짜 카메라 · 실제 사용자 정확도 아님

[신체 모델 첫 추론이 응답하지 않은 진단](../handcpu-stage-20261109/README.md)에 이어, 손뿐 아니라 신체 모델도 CPU 우선·GPU 재시도로 시작하는 [임시 엔진](workerNativeEngine.ts.txt)을 같은 어깨 후보 화면에 적용해 시험했다. 얼굴 모델은 GPU 우선이며 모델 파일·응답/종료 기한·판정 기준은 그대로다. 임시 엔진 SHA-256 `2f3e7cd501e7cc90957d6a208d3193e56e69104695a66b54261c028abf02d264`은 아래 실행 결과의 `before`/`after`와 일치한다. 이 엔진은 제품 코드에 반영하지 않았다.

1. 실제 SDK/빈 가짜 카메라 어깨 화면의 시작·일시정지·재개를 네 번 순차 시험했다. [첫 실행](bodycpu-a.json)은 첫 추론은 반환됐지만 일시정지 후 Worker 종료 확인이 기존 5초를 넘어 `cleanup-error`가 발생했다. [b](bodycpu-b.json)·[c](bodycpu-c.json)·[d](bodycpu-d.json)는 각각 두 세대 clean ACK를 받았다. 실패 시 내부 어느 모델의 종료가 지연됐는지는 이 기록으로 알 수 없다.
2. 같은 엔진으로 [공개 스쿼트 녹화 영상](public-video.json) 45프레임을 처리하고 카메라·Worker를 종료했다. 한 영상의 처리 성공이며 실제 사람·정확도 시험이 아니다.
3. 테스트 중에만 SDK 추론 시작/종료와 각 자원 종료의 고정 이벤트를 출력하는 [진단 runner](stage-runner.mjs)로 [a](cpustage-a.json)·[b](cpustage-b.json)·[c](cpustage-c.json)·[d](cpustage-d.json)를 실행했고 네 번 모두 시작·정리가 완료됐다. 이 네 진단에서 이전 `bodycpu-a`의 오류가 재현되지 않았기 때문에 어느 자원이 느렸는지는 여전히 미확인이다. 같은 이름 `.log.gz`에 고정 이벤트·원문이 있다.

신체·손 CPU 조합도 첫 시험에서 종료 실패가 있어 **간헐 P2의 해결책으로 채택하지 않았다.** 4회 진단의 통과가 이전 실패를 지우지는 않는다. 카메라 영상·관절 원시 좌표를 저장하거나 외부로 전송하지 않았다. 성능·모델별 실제 사람 정확도·여러 기기·전문가 검토는 남아 있다.
