# S6.4 — 기록 기간 입력 복구

## 실제로 달라진 흐름

잘못된 날짜 주소로 들어온 뒤 유효한 날짜를 입력했을 때 최초 URL 동기화가 입력을 다시 지우지 않는다. 최초 URL은 state initializer가 이미 반영했으므로 중복 초기화만 건너뛴다. 실제 기간·페이지·뒤로가기·명시 재조회는 기존 초기화를 유지하며 미제출 날짜로 조회 결과가 바뀌지 않는다. 디자인·문구·버튼·API·인증/소유권 정책은 바꾸지 않았다.

## 원인·실패 보존

Draft [PR #51](https://github.com/HSU-OAS/bodyguard/pull/51)의 전체 회귀에서 기록 기간 복구가 한 번 실패했고 단독 재실행은 통과했다. 재실행 성공을 해결로 간주하지 않았다. 현재 main의 동일 기록 화면 소스에서 mount 후 초기 effect 전 native 날짜 이벤트를 넣어 시작/종료 입력과 StrictMode 유무4건의 유실을 결정적으로 확인했다. 기존23건과 경로·삭제 회귀2건은 통과했다. 보완을 제거한 최종 RED는4실패/25통과였고, 동일 하네스로 보완 후29통과다.

최초 시험에는 act 설정/중첩 경고가 있었다. 이 결과도 보존했고, native DOM 이벤트·직접 React root·await act로 시험 설정을 분리한 뒤 경고 없는 RED를 다시 확보했다. 초기 진단은 실행 시작 source 포착이 없어 증거에 `captureSourceAtStartVerified=false`로 구분했다. 최종 RED와 모든 정식 GREEN은 source194개를 실행 전후 실제 포착했다. PR #51의 옛 결과와 시작 지연 원인은 이 Story로 완료 처리하지 않는다. 해당 브랜치가 이 보완을 반영한 뒤 재검증해야 한다.

## 실제 검증과 한계

[숫자·source/원본 SHA 증거](summary.json)의 `scopeGatesPassed`는 **로컬 수정 범위 검증**이며 PR 병합 또는 전체 단계 완료를 뜻하지 않는다.

- 실행 source commit `33f690c6a4a29cc83da243ee76ba63fb293264c6`: 전체693·동일29·type/Biome/build/production guard 통과. 설정/lock/의존성 변경 없음.
- 실제 설치 Chrome·빌드된 웹·HTTP API·격리 PostgreSQL18에서 SW-W01~04 통과: 본인 기록/상세/페이지/뒤로가기/삭제 취소·확인, 응답 단절 후 재삭제하지 않음, 다른 계정 쿠키403/행 보존, 대상 변경409·조회 장애 복구·잘못된 날짜 수정. 기존 timeout/expect 제한 변경0·예상4/실패0/재시도 통과0/skip0.
- 계정·메일·요약 값·장애 순서는 합성이다. 실제 신체·웹캠·임계값·전문가·외부 메일/Google·TLS·배포 검증이 아니다.
- 원본 로그/XML·소스 snapshot·Chrome report/PNG는 private 경로에 보존하고 계정/쿠키/원시 DOM은 공개하지 않았다. 전체 source SHA가 실행 전후 같고 최종 작업 파일과 같음을 발행 도구가 검증했다. 기존 실패 원본은 덮어쓰지 않았다.
- 격리 DB만 사용했고 시험 후 소유 PostgreSQL을 종료했다. DB 파일·증거는 삭제하지 않았다. 운영 DB·시크릿·계정/비용·배포0.

## 작성자 리뷰

`engineering:code-review` 기준으로 최종 diff와 관련 URL/owner/abort/삭제 확인 수명을 직접 재검토했다. 외부/독립 리뷰어 검토가 아니다.

- 보안: API/CSRF/기대 소유자·abort·late 결과 guard는 그대로이며 새 통신/저장/카메라 권한이 없다.
- 정확성: 최초 경로 중복 초기화만 차단한다. `from/to/key`의 실제 변경에서 ref를 먼저 갱신하고 기존 입력·invalid·선택 초기화를 수행한다. key는 페이지·revision을 포함한다. mount/StrictMode/두 날짜/뒤로가기/페이지/삭제 확인 회귀가 이를 확인했다.
- 성능/유지보수: ref1개·상수 비교만 추가한다. 의존성/시간 제한/인증 상태를 우회하지 않는다. 판정·아바타·공개 코칭 연결은 추가하지 않는다.

이 수정 범위의 미해결 P1/P2는 없다. 최종 main/diff/exact HEAD/CLEAN/체크를 확인하기 전 병합은 미실행이다. SDK 통신 정책 별도 승인·디자인 구조 승인/텍스트 최소화 적용·아바타/실측·운영/참여자·전체1~6단계는 미완료다.
