# S6.19 — 로그인 소유 첫 추론 준비

실제 로그인 소유 흐름에서 준비용 첫 입력을 버리고 다음 새 입력으로 재생하는 통합을 검증한다. 준비 중 권한을 잃으면 늦은 결과로 재생·판정·기록이 되살아나지 않아야 한다. 공개 코칭·최종 아바타·출시 후보판의 완성 선언이 아니다. [Story](../../stories/owned-native-warmup.md).

## 실제 흐름과 경계

Chrome155.0.8059.40·native SDK1.0.1·Three0.186.1·AuthProvider/useRecordedCoaching·실제 FastAPI/API·새 소유 PostgreSQL18.6 Unix 소켓 시험 DB를 사용했다. 실제 카메라/사람/메일은 아니다. 기존 A37 남녀 GLB와 authored plan·관절·오류/긍정·phase는 합성 시험 자료이며 출시 동작0과 기존 외형 P2를 유지한다.

준비용 read1의 body/face/hands와 frame 회수 후 처음 running이 열린다. 당시 evaluator/observe를 통한 진행·live render·수행 적립·기록0이다. 같은 native 소유 source의 다음 입력은 새 stamp이며 같은 입력/시각을 body/face/hands에 전달한다. 생성한 긍정 입력도 준비 때는 버리고 이후 live 입력만 현재 코칭에 전달한다.

실제 native 결과 반환 뒤 TEST Promise 장벽을 걸어 logout/server401/pagehide/unmount를 보냈다. 권한은 즉시 폐기되고 차용 입력의 회수 전 SDK close는0이다. 장벽 해제 후 camera/frame/source/SDK/GLB 회수·GPU memory baseline을 확인한다. refresh 때 이전 cleanup을 기다리고 명시적 새 준비·시작만 새 소유 source를 연다. 실제 SDK hang/하드웨어 고장 시험이 아니다.

기존 오류 강조·가림/복수/미검출 해제·교정 시범 변경·pause/resume/새 세대·본인 중단 기록 화면과 API 조회도 준비 opt-in에서 확인한다. 생성한 오류/긍정을 actual SDK 사람 검출/올바른 자세/임상 효과로 표시하지 않는다. 중단 기록은 기존 client-reported이며 원시 영상·좌표나 준비 결과를 서버에 저장하지 않는다.

## 실패·리뷰 보완 보존

중복 제거 대조의 후속 note는 최초 정적 검사에서 import 뒤 공백/formatter2오류로 실패했다. 원본 source와 실패 receipt/log를 notes/에 보존하고 표면 형식만 수정해 정적 검사·954항목 대조를 다시 실행했다. 이 후속 note는 973항목 색인 외에 별도로 보존한다.

문서 패치 두 번은 표제/전체 문단의 context 불일치로 실패했고 파일 변경 전에 거부됐다. 본문/표제를 확인해 재적용했다. 실행 회귀나 제품 실패로 합산하지 않으며 원문은 대화에만 있다.

최초 남성 준비6건은5통과/1실패다. 생성 입력을 미리 켠 새 positive 시험이 blank 전용 running helper의 unavailable 기대값과 충돌했다. 실제 첫 ready receipt는 read/close/frame/close 각1, evaluator/render0이며 native blank 검출0·이후 생성 입력6/evaluator5·적립0이었다. 기본 helper의 unavailable 기대는 유지하고 새 positive 시험만 명시적으로 available을 요구했다. timeout·모델·판정·제품 제한은 변경하지 않았다. 최초 source와 private binary·원문 report·실패 context를 보존한다.

작성자 리뷰에서 opt-in의 live3 대기가 두 개 poll에 나뉘어 최대 대기 경계가 느슨해질 수 있음을 발견했다. **단일 기본5초 poll**에서 native close4(준비1+live3)를 요구하도록 강화했다. 기본은 같은 단일5초 close3이다. 최초·보완 전·단일 deadline source와 그때의 report/bundle을 각각 보존한다. 이를 실제 추가 브라우저 실패나 기존 시작 P2 해결로 표시하지 않는다.

경로 조회의 존재하지 않는 임시 파일/폴더·도구 이름·zsh glob 오류는 대화 출력에만 있다. 별도 실행 receipt 없는 조회를 회귀 실패/통과로 세지 않는다. 최초 source-before-format과 실제 실행한 source-initial, 기대값 보완 source-reviewed, 단일 deadline source-strict를 구분한다. 사전 소유 설치본을 자체 복사해 잠긴 실제 Node CLI를 사용했고 pnpm 설치를 통과했다고 주장하지 않는다. private dispatcher는 현재 workdir와 허용 build/Playwright만 실행한다.

## 최종 검증 상태

단일 deadline source의 기본26·준비 기존30·새 준비 경계12, **최종68건**이 실제 Chrome/API/격리 SQL에서 통과했다. 각 실행은 retry0/skip0/flaky0·기존60초 test/단일5초 poll·제품 rate limit을 유지했다. source-strict의 두 실제 입력 source hash를 매 분할 전후 대조했다. 이전 실행들도 실패/성공 그대로 별도 보존하며 최종68로 중복 합산하지 않는다. 첫 native 비용 이동을 로그인 소유 흐름에 연결한 경계 검증이지 기존 시작 P2 해결/성능 비교가 아니다.

전체 FE1479/74파일·타입·Biome294파일(기존 다른 스크립트의 info15, 새 변경 파일0)·assets/public build/guard는 실제 통과했다. 공개 JS354600/CSS31199의 byte/SHA는 main과 같고 비공개 warmup/ready receipt가 공개 bundle에 없는지 추가 guard로 확인했다. 새 Blender 원본/GLB/변형·외형 제작0이다.

처음 수집한 압축 증거889356285 byte에는 Vite의 동일 public SDK/모델 복사본이 반복 포함됐다. 첫 archive를 별도 소유 임시 경로에 그대로 보존하고 내용 주소형 중복 제거로 모든 시험별 이름·SHA/압축 SHA·byte를 유지했다. 최초954항목의 원문/압축 SHA가 모두 새 색인에 존재함을 실제 대조했다. 최종973항목·현재 source18의 압축/길이/SHA/current 검증이 통과했다. 이는 증거 크기 보완이며 실제 시험/판정/출시 기준을 완화한 것이 아니다. 수집기만 수정했으므로 browser fixture/test의 strict hash는 그대로다. 이후 전체 FE/타입/정적/build/guard를 실제 재실행했다.

SDK는 현재 문서 기준 CSP 차단 시도를 남긴다. 라우트 observer의 external0은 **외부 통신 시도0이 아니다**. 현재 document 카운터는 기록 페이지 이동 때 초기화되어 모든 문서의 시도 부재를 증명하지 못한다. 실제 남은 SDK 제품 정책/Draft36 P2는 닫지 않으며 승인 없이 CSP를 완화하지 않는다.

실제 사람·물리 웹캠·목표 노트북·Chrome154의 실제 Auth/API/SQL 조합·Worker 로그인 warmup·전체 backend unit suite는 이번 미실행이다. 기존 시작 P2·최종 외형/시범·정확한 classifier/임계값·공개 코칭 구조/SDK 정책 승인·Docker/TLS/운영과 D2/전체1~6 기준은 여전히 미완료다. 준비 비용을 이동한 결과를 전체 시작 시간 개선이나 부드러움 승인으로 표시하지 않는다.

공개 구조·문구/최소 텍스트·기본 thread/모델/화질·신체 판정·원본/GLB/조형·API/개인정보/운영 정책은 변경하지 않는다. 원시 카메라/배열/행렬/몸 per-frame 값은 보존하지 않는다. PNG는 authored 아바타 canvas와 합성 계정의 본인 중단 기록 화면뿐이며 최종 디자인/아바타 미리보기가 아니다.
