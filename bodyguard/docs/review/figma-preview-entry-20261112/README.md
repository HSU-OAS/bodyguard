# Figma 공개 진입 화면 검수 — 2026-11-12

## 설계와 구현

[Figma 홈 21:4](https://www.figma.com/design/8f6TiE81S5Cu2bjgTuHFeZ/BODYGUARD-%C2%B7-UI-%EC%84%A4%EA%B3%84?node-id=21-4)의 고해상도 디자인 컨텍스트와 실제 스크린샷을 MCP에서 읽었다. 코드와 스크린샷을 기준으로 기존 FigmaHomePage를 재사용했다. 이미지/SVG 12개를 새 빌드에서 원본과 SHA-256 대조해 바이트 동일함을 확인했다. Figma에 표시된 primitives 연결은 이 저장소에 대응 컴포넌트가 없어 기존 버튼·링크 컴포넌트로 유지했다.

홈은 정지 시안, 세 동작의 영상은 Blender 검수 후보다. 완료된 아바타·시범·판정으로 표시하지 않는다. 첫 화면은 카메라를 요청하지 않는다. 동작 선택 후 웹캠 체험에서 동작명·보기 범위를 적용하고, 기존 런타임을 사용한다. 계정·기록·신체 분석 메뉴는 이 정적 검수본에서 비활성이다. 일반 제품 빌드의 보호된 경로와 API는 수정하지 않았다.

## 실제 검증

- `release/`의 최종 홈·검수 대기 화면과 `browser.json`이 실제 Chrome 결과다. 1440×960, 1024×768에서 확인했다. 좌우 패널의 Figma 좌표·폭·높이를 대조했고 가로 넘침이 없었다.
- 패널 토글, 후보 동작 영상의 실제 호버 재생/정지, 모션 감소 시 자동 재생 보류, 동작 선택과 검수 화면 이동 및 보기 범위를 확인했다. 홈 검수 중 카메라는 시작하지 않았다.
- 초기 `initial/` 화면의 세 썸네일이 fieldset 배경에 가려진 실패를 보존했다. 배경을 투명하게 바꿔 최종본에서 Figma 그림을 확인했다. 첫 홈 빌드는 형제 디렉터리의 react-dom import 해석 실패가 있었으며, 기존 설치 경로 alias로 수정했다.
- `final/`은 썸네일 보완 뒤 화면이며, `release/`는 동작명·보기 범위 전달까지 포함한 최종 화면이다. 이전 결과를 최종 증거로 덮어쓰지 않았다.
- FigmaHomePage·MotionPreview 회귀 2개 파일 12개 통과. Biome와 TypeScript 검사 통과. 별도 공개 빌드와 일반 제품 프로덕션 빌드 통과. Figma 자산은 CSS에 대용량 data URL로 넣지 않고 로컬 정적 파일로 배출했다.
- 남녀 후보를 실제 Worker·MediaPipe·WebGL과 사전 녹화 Chrome 가상 카메라에서 확인했다. 관련 JSON은 입력 fixture SHA-256과 시작·지연·추적·종료 상태만 보존하며 영상·좌표는 저장하지 않는다.

## 한계와 공개 상태

실제 사람의 인식 정확도·자연스러움·동작별 오판정은 검증하지 않았다. 이 Story는 정적 검수본의 진입 화면 연결이며 전체 웹 완성이나 출시 후보판 선언이 아니다. `웹캠 체험`의 우측은 중립 자세다. 동작별 올바른 시범·잘못된 부위 판정, 로그인·기록 저장은 별도 제품 통합 대상이다. Pages는 별도 승인을 받기 전까지 기존 공개본을 유지한다.

기존 성공 배포는 [실행 41945822637](https://github.com/HSU-OAS/bodyguard/actions/runs/41945822637), 커밋 b80f6408이다. 승인 후 기존 Pages 워크플로로 이 후보만 교체하고 이상이 있으면 기존 성공 실행을 재실행한다. 새 계정·시크릿·운영 DB·유료 서비스는 포함하지 않는다.

## 재현

저장소 루트에서 공개 빌드를 새 임시 폴더로 만들고 `node bodyguard/docs/review/figma-preview-entry-20261112/serve.cjs <빌드 출력>`으로 127.0.0.1 서버를 연다. 출력된 URL과 새 증거 폴더를 `browser-audit.cjs`에 전달한다. 가상 카메라 검수에는 별도 보존한 Y4M을 `native-inspection.cjs`에 전달한다. 실제 카메라를 사용하지 않으며 `BODYGUARD_FEMALE=1`로 여성 후보를 선택한다.
