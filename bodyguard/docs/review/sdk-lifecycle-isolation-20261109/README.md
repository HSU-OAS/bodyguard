# SDK 시작·첫 추론·종료 분리 시험

2026-11-09 · 한 노트북, 공개 녹화 영상 · 실제 사람·의학적 정확도 미검증

출시 활성화 및 최종 합격을 의미하지 않는 개발 후보다. 동일한 로컬 공개 스쿼트 영상과 제품 Worker·모델 세 개를 사용했다. 물리 카메라·외부 요청·쓰기 요청은 없으며 영상과 원시 관절 좌표는 보존하지 않았다. GPU/CPU 비교는 순서와 부하가 통제되지 않은 단일 장치의 짧은 시험이므로 인과관계나 전 기기 성능을 입증하지 않는다.

첫 계측 실행은 시험 도구의 Worker 문자열 치환 불일치로 추론 전에 중단됐다([원문](instrumentation-first.log.gz)). 첫 도구 버전의 정확한 파일 사본은 보존하지 못했다. 이 도구 오류를 제품 실패로 세지 않는다.

기존 GPU 우선 설정의 [첫 재시도](first-retry.json)는 세 모델이 초기화된 뒤 첫 추론이 5초 제한을 넘어 종료 확인도 기한을 넘겼다. 당시 추론 단계별 계측은 없어 어느 모델이 지연됐는지는 특정할 수 없다. 계측을 추가한 별도 [45프레임 실행](detect.json)은 처리 및 종료에 성공했다.

기존 설정의 별도 8프레임 3회([1](series-1.json), [2](series-2.json), [3](series-3.json)) 중 1·3번은 첫 추론 응답 기한을 넘겼다. 1번은 종료 확인도 기한을 넘겼으며 계측된 Worker에서는 이후 세 모델의 종료 함수가 반환됐다. 3번은 종료 확인이 제한 안에 완료됐다. 1번의 Worker 계측상 첫 프레임 신체 약 3.72초, 얼굴 약 1.05초, 손 약 5.11초로 누적 지연이 있었다. 별도 시계의 Worker와 부모 타임스탬프를 직접 빼지 않는다. 2번은 8프레임·종료가 성공했다.

시험 중에만 손 모델을 CPU 우선으로 바꾼 8프레임 3회([1](cpu-1.json), [2](cpu-2.json), [3](cpu-3.json))는 모두 정상 종료됐다. 이어 실제 후보 코드에 CPU 우선·GPU 재시도를 적용하고 본래의 45프레임 runner로 [아바타 없는 시험](candidate-no-avatar.json)과 [여성 아바타 연결 시험](candidate-avatar.json)을 각각 실행해 카메라 및 Worker 정리까지 정상 완료했다. 후자에서 아바타의 관절 커버리지는 45프레임 중 41프레임이다. 검출이나 커버리지는 실제 사람의 정확도를 뜻하지 않는다.

동일 손 모델의 다른 공개 손 영상에 대한 기존 [CPU/GPU 비교](../hand-video-delegates-20261109/README.md)는 모델 출력 간 차이만 확인했으며 사람의 정답이나 안전성을 입증하지 않는다. CPU 우선이 모든 기기에서 빠르거나 모든 종료 오류를 해결한다고 결론내리지 않는다. SDK·WASM·모델·사용자 좌표·진단 기준·5초 제한은 변경하지 않았고, 취소 시 fallback하지 않는다. CPU 초기화가 실패할 때만 GPU로 재시도한다. 나중에 실제 사람, 장시간·여러 기기와 과부하에서 추적·오판정·종료를 검증해야 한다.

각 JSON과 같은 이름의 압축 로그를 남겼다. 시험용 [GPU 계측 runner](runner-series.mjs) 및 [CPU 계측 runner](runner-cpu.mjs)는 저장된 집계에 대응하며 원본 소스는 실행 중 변하지 않았음을 각 JSON에서 확인한다. CPU 비교는 Worker 임시 번들 변환이고 제품 변경은 별도 커밋의 `workerNativeEngine.ts`다.

## 자동 검증 상태

관련 Worker 단위 3파일 66개, 변경 파일 Biome과 TypeScript 검사는 통과했다. 전체 Vitest 기본 실행은 130파일 중 6파일·6개 테스트가 실패했다([원문](vitest-full-failed.log.gz)). 병렬 수를 줄인 재실행에서도 별도의 로그인 화면 테스트 2개가 실패해 전체 결과가 나오기 전에 중단했다([중단 원문](vitest-serial-interrupted.log.gz)). 당시 다른 앱을 포함한 시스템 부하는 높았지만 실패 원인을 그것으로 단정하지 않는다. 전체 검사는 통과로 표시하지 않는다. 브라우저 시험 후 코드 주석 한 줄만 설명을 보다 신중하게 변경했으며 실행 코드는 바뀌지 않았다.

이후 부하가 낮아졌을 때 같은 낮은 동시성으로 다시 시작한 전체 검사에서도 로그인 화면 테스트 1개가 실패했다. 전체 종료 전에 중단했고([중단 원문](vitest-serial-retry-interrupted.log.gz)), 이 실행 역시 통과로 세지 않는다. 기존 실패와 같은 원인인지는 미확정이다.

이후 Vite production build와 기존 production guard는 통과했다([빌드](vite-build.log.gz) · [guard](production-guard.log.gz)). guard는 미연결 개발용 코칭 코드가 공개 번들에 들어가지 않았는지 검사한다. 이것을 전체 회귀 테스트나 배포의 성공으로 해석하지 않는다.

기존과 후보의 로그인 화면 파일을 따로 1회씩 실행했을 때 각각 23개가 통과했다([기존](login-base.log.gz), [후보](login-candidate.log.gz)). 최초 실패 6파일을 낮은 동시성으로 모아 재실행한 결과 5파일·77검사 통과, 로그인 후 복귀 1검사가 실패했다([원문](failed-files-isolated.log.gz)). 그 로그인 복귀 파일을 기존과 후보에서 각각 따로 실행한 6검사는 양쪽 모두 통과했다([기존](login-return-base.log.gz), [후보](login-return-candidate.log.gz)). 실행 순서와 부하가 같지 않아 이것만으로 실패 원인을 단정하지 않으며 전체 검사 실패도 그대로다.
