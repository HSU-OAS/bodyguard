# 수행 기록 계정 전환 보완 — 실제 흐름과 검증 경계

[S4.R8](../../stories/owned-records-read.md), 기준 main `9882224cf78575ecbee5a051f6293048494bd130`(PR141 merge), `codex/owned-records-read`. 기존 공개 웹의 기록 목록·상세·기간 삭제를 현재 화면의 로그인 계정과 실제 요청 세션에 함께 묶는 한 가지 목적이다. 새로운 화면 구조·데이터 수집·정자세 판정·아바타 공개는 아니다.

## 작동한 사용자 흐름

- 본인 수행 기록 → 기간 조회·페이지 이동 → 상세 → 선택 기간으로 돌아가기.
- 삭제 대상 확인 → 취소 또는 명시적 삭제 → 실제 서버 결과 표시. 새로 저장한 기록·다른 기간·다른 계정의 기록은 보존한다. 확인 만료·대상 변경·불확실한 응답은 성공으로 만들거나 자동 재시도하지 않는다.
- 목록·상세·삭제 대상 요청 중 실제 쿠키 계정 A→B→A 전환 → 서버403 → 화면에서 기록과 삭제 확인 제거 → **계정 다시 확인** → A의 기록으로 복구. B의 데이터나 삭제 대상은 표시하지 않는다. 기간 조회 버튼으로 계정 차단을 우회하지 않는다. 차단 안내로 키보드 초점을 옮긴다.

실제 Chrome155.0.8059.40·HTTP·PostgreSQL18.6에서 합성 계정/메일/수행 요약으로 검증한다. ABA 전환·응답 보류는 시험에서 제어하며 실제 사람 촬영·실제 메일 공급자·임상 정확도 시험이 아니다. 기존 제품 페이지를 사용하고 별도 가짜 성공 화면은 만들지 않았다.

## 실패 원본과 보완

1. 수정 전 실제 API/SQL의 신규8건이 실패했다. 다른 계정 쿠키와 이전 화면 계정 헤더가 붙은 목록·상세는200, 저장은201, 삭제 미리보기·확인은200으로 수락됐다. 올바른 CSRF를 가진 새 계정 요청에서도 기대 계정 검사가 빠져 있었다. 같은 transaction에서 현재 쿠키 소유자와 기대 계정·CSRF를 대조하도록 보완했다. 헤더는 소유자를 선택하지 않으며 기존 헤더 없는 호출도 현재 로그인 소유자만 사용한다.
2. 초기 전체 API 회귀는549통과/1실패였다. 시험용 읽기 전용 SQL oracle의 **전용 root/socket·0700 경로 계약**을 잘못 준비한 설정 문제다. 검사나 제품 코드를 낮추지 않고, 이번 실행의 PID/data 경로를 대조한 뒤 소유 DB만 정상 종료·동일 데이터 보존·정상 socket 경로 재실행했다. 기존 실패는 보존한다.
3. 초기 관련 클라이언트 시험은51통과/1실패, 이후64/1·67/1이었다. 기간 변경 시험이 인증 사전 확인 후 실제 조회가 시작하기 전에 빈 fixture의 resolver를 호출했다. 시작한 요청을 기다리도록 시험을 수정했고 timeout을 늘리거나 제품 오류를 숨기지 않았다. 이후 관련68건·전체frontend 회귀가 통과했다. 모의 네트워크/DOM 시험이며 실제 네트워크 지연 수치로 일반화하지 않는다.
4. 첫 initdb는 sandbox 공유 메모리 거부로 실패했으며 그 뒤 연결 없는 시험 실행도 실패했다. 초기화·실패 로그/XML을 보존하고 전용 경로에서 실제 클러스터를 준비했다. 첫 브라우저 명령의 잘못된 `--suite` 옵션도 실행 전 실패 로그로 보존했다. 정상 positional 실행은 별도 원본이다.
5. OpenAPI 생성 첫 실행은 sandbox uv cache 접근 거부로 실패했고 원문은 대화 도구 출력에 있다. 기존 잠금 의존성을 오프라인으로 사용한 원래 생성기로 성공했다. 첫 Ruff format check도 실패 후 formatter로 교정했다. 이 두 최초 도구 출력의 별도 로그 파일을 보존했다고 주장하지 않는다.
6. sandbox `pg_ctl status`는 실제 실행 중인 소유 서버를 없다고 보고했다. 새 start 시도는 기존 postmaster 잠금으로 거부됐으며 데이터는 삭제하지 않았다. escalation 상태 확인으로 실제 PID18195/data 경로를 대조한 다음 정상 종료했다. 이 상태/거부 원문은 도구 출력과 전용 PostgreSQL 로그에 있으며 SQL/auth 관련 서버 로그는 저장소 증거에 첨부하지 않는다.

## 최종 증거

최종 수치는 [실제 결과](verification.json), 원본/압축 byte·SHA256 및 source 대조는 [증거 목록](manifest.json)에 기록했다. 최초 실패·중간 통과·최종 결과를 섞지 않는다. 원본은 `/private/tmp/bodyguard-auth-test.ypDr3a`와 각각 별도 UTC 이름의 `frontend/test-results/records-*`에 보존한다.

- 실제 공개 기록 브라우저14흐름: 실패/skip/flaky/retry0. 합성 계정·기록이며 실제 HTTP/SQL이다. 관찰 context의 외부/모델/카메라 요청과 local/session storage0을 확인했고, 프로세스 전체 외부 통신0을 입증한 것으로 확대하지 않는다.
- 전체 frontend1865/103파일, 관련68, 전체 실제 API550: 실패/skip0. API 기존 경고3개·Biome 기존 info16개는 남아 있다.
- TypeScript·Biome·Ruff·format·mypy·정상 생성 타입·원래 고지 build·production guard·diff 통과. 실행 전후13개 source SHA가 동일하다. 공개 JS365040byte는 계정 연결 보완으로 바뀌었고 CSS31302byte/SHA는 기존과 동일하다. 이 변경을 임상 정확도나 성능 게이트 통과로 세지 않는다.
- 로그/JSON/XML·source gzip과 실제 화면7개 등61개 아티팩트734132byte를 원본과 다시 hash 대조했다. 선택하지 않은 실제 PNG도 원본 경로·SHA를 결과에 보존했다.
- PID20879/data/socket 경로를 실제 대조해 이번 소유 PostgreSQL만 종료했고 `postmaster.pid` 없음까지 확인했다. 데이터·로그·실패 원본과 다른 실행의 기존 파일은 보존했다. 종료 로그는 private 시험 폴더에 있다.

## 작성자 리뷰·병합 게이트

`testing-strategy`는 모의 수명/네트워크 → 실제 API/SQL → 실제 공개 웹의 순서로 검증하게 했다. `code-review`는 소유자 선택·CSRF·transaction rollback, 입력 snapshot·전체 요청 deadline·취소/늦은 JSON, 커밋된 authority 교체·이전 기록/삭제 확인 제거, 401/403/409·불확실한 삭제와 초점/기존 기간 흐름을 검토하게 했다. 독립 외부 리뷰·전문가 승인이 아니다.

최신 source13개의 SHA, 생성 타입, 원래 고지 빌드·production guard와 diff를 대조했다. 재현한 소유권 누락을 보완하고 차단 안내의 초점을 함께 검증했으며 이 좁은 diff에 미해결P1/P2는 없다. 새 개인정보 필드·DB migration·CI·계정·시크릿·운영·배포 변경은 없다. 아바타/참여자/Docker/공식 문의/Gmail·Google 공급자 보류·출시 적격 동작0·실제 보정/정자세/추천·기존 시작P2·전체1~6 미완료는 유지한다.

이 좁은 diff의 검증과 미해결P1/P2 없음, 최신 main/원격diff/HEAD/CLEAN/체크/리뷰를 충족한 뒤만 exact HEAD merge commit으로 병합한다. 원격 체크가 없다면 **체크 없음**을 명시한다. 문서 작성 시 PR 게이트는 대기 중이며 전체 출시 후보판이나 병합 완료를 주장하지 않는다.
