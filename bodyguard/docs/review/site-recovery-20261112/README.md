# 공개 검수본 끊김 보완 — 2026-11-12

## 범위와 실제 시험

기준선은 main 930b060e의 별도 Pages 검수 빌드다. 후보는 같은 GLB·포즈/얼굴 모델·기준을 유지하고 손가락 모델만 선택 실행한다. 동일 출처 로컬 HTTP에서 설치된 Chrome의 가상 카메라에 기존 사전 녹화 fixture를 공급해 실제 MediaPipe Worker와 WebGL을 실행했다. 실제 웹캠 사람 시험·정확도 검증·공개 배포는 하지 않았다. 영상과 관절 좌표는 이 폴더에 저장하지 않는다.

| 같은 입력에서 비교 | 기준선 | 후보 |
| --- | --- | --- |
| 원본 5fps 입력, 추론 중앙값 | 127.5ms | 60.0ms |
| 원본 5fps 입력, 추론 p95 | 333.1ms | 69.7ms |
| 30fps 시험 클록 입력, 추론 중앙값 | 156.9ms | 66.3ms |
| 30fps 시험 클록 입력, 추론 p95 | 247.6ms | 106.7ms |
| 30fps 시험 클록 입력, 15초 중 처리 수 | 79 | 138 |
| 30fps 시험 클록 입력, 브라우저 RAF 콜백 | 60.4fps | 60.3fps |

30fps 입력은 원본 Y4M의 픽셀 데이터를 바꾸지 않고 프레임 클록 헤더만 바꾼 사본이다. 실제 사람의 30fps 촬영이나 인식 정확도를 입증하지 않는다. 관찰 가능 표본은 60개 중 기준선 45개·후보 43개로 정확도 개선 근거가 아니다. 몸이 없거나 여러 몸으로 반환된 입력은 원래대로 보류했다. 기준선·후보의 종료는 카메라가 중지되고 자원 참조가 해제됐으며 페이지 오류가 없었다.

후보 초기화는 원본 입력에서 1326ms, 시험 클록 입력에서 1297ms였다. 이는 비교 한 회의 관측이며 모든 기기의 시간 보장이 아니다. 고부하 손가락 상세 모드는 별도로 검수하며 결과 JSON에 상세 모드와 머리 표시 여부를 기록한다. 첫 모델 프레임 전에 정면 맞추기를 요청하던 시점과 종료 후 남던 추적 표시를 보완한 최종본은 `final-details.json`에 구분한다.

## 회귀와 재현

- 기존 관찰·연속 렌더·Worker 프로토콜·네이티브 엔진 회귀: 4개 파일 78개 시험 통과.
- Vite 공개 검수본 빌드 통과. JS는 1640kB에서 855kB, Worker는 529kB에서 246kB로 축소됐다(압축 전).
- 픽셀 비율 1.5 상한은 공개 검수본 전용이다. GLB 원본과 리깅·변형 데이터는 변경하지 않는다.
- 저장소 루트에서 `node bodyguard/docs/review/site-recovery-20261112/benchmark.cjs <빌드 출력 절대 경로> <기존 Y4M 절대 경로> <새 결과 JSON> 15`로 실행한다. 상세 모드는 `BODYGUARD_DETAIL_HANDS=1`을 사용한다.
- fixture SHA-256·실제 처리 지연·표본 상태·정상 종료는 각 JSON에 있다. 생성한 시험 클록 사본과 카메라 영상은 커밋하지 않는다.

## 남은 문제
