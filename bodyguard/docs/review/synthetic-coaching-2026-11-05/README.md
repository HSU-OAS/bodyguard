# 합성 영상 기반 두 아바타 연결 확인

2026-11-05 로컬 개발 화면 `/dev/coaching?motion=neck-side`에서 수행했다. 기준 소스는 `2805d9df7263cd8735205efdb79c161ff89b4d94`다. 실제 사람이나 실제 웹캠 영상은 사용하지 않았다.

## 방법

- 저장소의 개발용 남성 목 동작 미리보기 영상으로 합성 카메라 입력을 만들었다. Chrome의 가짜 카메라를 사용하고, 계정 응답도 가상으로 제공했다.
- 시범 후보를 연 뒤 카메라 확인과 연속 입력을 시작하고, 사용자 측 아바타의 관찰 상태와 시범 후보 표시를 확인했다.
- [화면 캡처](two-avatar-synthetic.png)는 합성 입력을 사용한 실제 개발 화면이다. 표시된 아바타는 출시 승인된 모델이 아니다.

반복 스크립트는 [repeat-local.cjs](repeat-local.cjs)다. 개발 서버가 `127.0.0.1:5197`에서 실행 중이고 로컬 모델 파일이 준비된 상태에서 `frontend` 디렉터리 기준으로 실행한다. 영상은 마네킹 합성 입력이며 서버·사람의 카메라 데이터가 아니다.

```bash
ffmpeg -n -v error -i ../docs/review/motion-preview-content/media/male-neck-side.mp4 -vf fps=10 -pix_fmt yuv420p /private/tmp/bodyguard-synthetic-neck.y4m
NODE_PATH="$PWD/node_modules" node ../docs/review/synthetic-coaching-2026-11-05/repeat-local.cjs
```

## 결과

- 첫 시도는 45초 안에 카메라 분석 준비 완료 상태에 도달하지 못했다. 다음 시도에서는 [카메라 입력 확인 실패](preparation-failure.png)가 표시됐다. 원인은 특정하지 못했다.
- 별도 계측 시도에서는 작업자의 초기 결과 응답을 확인했지만, 그 시도의 최종 준비 상태는 확인하지 못했다.
- 이후 한 차례와 별도의 세 차례 반복에서 연속 입력 상태와 사용자 측 아바타 관찰 표시를 확인했다. 세 반복의 초기 프레임 응답은 각각 약 1,066ms, 1,032ms, 960ms였다. 이는 해당 합성 시험의 작업자 응답 시간이며 실제 노트북 사용자의 지연·프레임 속도 기준이 아니다.
- 현재 코칭 판정과 기록 저장은 이 화면에서 꺼져 있다. 오류 부위 표시, 권장 동작의 정확성, 실제 사람의 추적 정확도는 이 시험으로 검증하지 않았다.

## 남은 일

카메라 준비가 간헐적으로 실패한 원인을 재현·분석하고, 실제 참여자와 다양한 촬영 조건에서 정확도·성능을 검증한다. 두 항목 모두 출시 완료 기준으로 남는다.
