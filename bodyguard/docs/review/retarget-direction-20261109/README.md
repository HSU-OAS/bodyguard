# 공개 영상의 팔 방향 전달 확인

2026-11-09 · 개발 검수 · 실제 사람 웹캠 및 정확도 검증 아님

[TensorFlow 공개 스쿼트 영상](https://github.com/tensorflow/tfjs-models/blob/master/pose-detection/test_data/pose_squats.mp4)을 로컬 Chrome 가상 카메라에 넣고, 여성 아바타 후보의 실제 GLB와 같은 프레임에서 팔 방향이 어떻게 전달되는지 확인했다. 원본 MP4 SHA-256 `ea9151e447b301985d5d65666551ef863b369a2e0f3a71ddd58abef2e722f96a`, 가상 카메라 Y4M SHA-256 `1df697eccf5e050538de3a5720dae25d56ed62a4d118dbf94aa09f675aa6df53`이다. 입력 영상과 원시 관절 좌표는 저장소에 넣지 않았다.

테스트 중에만 스테이지에 관절 방향을 읽는 코드를 삽입했다. 30프레임 중 28프레임에서 아바타 관절 커버리지가 확인됐다. 숫자를 기록한 프레임에서는 화면의 사용자 아바타가 숨겨져 있었으며, 당시 내부 뼈 상태가 현재 SDK 입력으로 갱신됐는지 확인되지 않는다. JSON에는 팔 구간 약 2.17~6.48° 등이 남아 있지만 **이 값을 같은 프레임의 유효한 추적 오차나 정확도로 해석하지 않는다.** 아바타가 실제로 표시되고 그 프레임을 처리한 경우만 별도로 검증해야 한다.

[집계 결과](result.json) · [실제 아바타 후보 화면](avatar.png) · [원문 로그](run.log.gz) · [실행 runner](runner.mjs). 이 이미지에는 왼쪽 사용자 아바타가 보이지 않으며 오른쪽은 별도 어깨 동작의 준비 시범이다. 화면은 제품 UI나 최종 아바타가 아니며, 이 결과는 손·얼굴 추적과 실제 사용자의 정확도, SDK 간헐 종료 오류, 아바타 표면·관절 변형의 합격을 뜻하지 않는다. 제품 코드나 판정 기준은 변경하지 않았다.

runner는 원래 frontend의 `scripts/local-rig-direction-proof.mjs`에서 실행했으며 결과 JSON의 실행 전 SHA와 보존한 파일의 SHA가 일치한다. 재실행에는 동일한 공개 Y4M을 별도 임시 경로에 준비하고 runner를 frontend `scripts/`에 같은 이름으로 복사해야 한다. 소스 비디오 캡처 기능은 위 Y4M 해시에 고정되어 있고 캡처 이미지는 로컬 임시 폴더에만 남겼다.
