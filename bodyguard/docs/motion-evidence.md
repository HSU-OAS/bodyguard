## 실제 촬영 하네스: 완료 전 출시 목록은 0개

다음 Story에서 `#1`을 먼저 실제 노트북 웹캠으로 검증한다. 동일한 가짜 좌표로 “잘 된다”고 입증하지 않는다. 사용자는 영상을 저장·전송하지 않고 현장에서 브라우저 추론 결과와 사람이 관찰한 사건만 수기로 대조한다. 피험자·노트북 모델·브라우저·카메라 높이/거리·조명·옷·의자·날짜·관찰자를 적되 개인 식별 정보와 관절 좌표는 남기지 않는다.

현재 `pnpm dev`의 스켈레톤 데모 아래쪽에 **동작 촬영 검증 · 개발 전용** 패널을 추가했다. 관찰자가 연기한 상황을 고르고 `현재 프레임 기록`을 누르면 기존 `trustedJoints`·`framingHint` 경로로 필수 관절 가시성과 촬영 안내만 남긴다. 브라우저 메모리에서만 유지되며 새로고침하면 사라지고, production build에는 패널 문구가 포함되지 않는다. `촬영 범위 충족`은 동작 정확성·안전성·성공을 뜻하지 않는다. 이 하네스는 **관찰 가능성 시험**용이며 동작 판정 엔진의 대체물이 아니다.

2026-10-01 [S2.3 명세·하네스](stories/stage2-motion-validation.md)에서 관찰 도구를 보완한다. `/dev/measure` 전용이며 준비 취소·늦은 카메라/모델·재시작·이탈 정리, 복수 포즈 입력 보류, 프레임 시각·입력 유효성 검사가 대상이다. 기록은 최신 100개 요약에 한정한다. 1초 넘게 갱신되지 않은 입력을 현재 촬영 범위 충족으로 기록하지 않는다. 이는 개발용 신선도 검사일 뿐 검증된 동작 판정·임계값이 아니다. 실제 사람의 검출·동작 정확도는 S2.3b에 남는다.

1. 정상 좌·우·중앙 복귀, 작은 범위, 어깨 으쓱 동반, 몸통 옆 기울임, 머리 회전, 손으로 당기기, 통증/중단 자기보고를 별도 사건으로 연기한다. 통증은 카메라가 알아맞힌다고 주장하지 않는다.
2. 상반신만 보임 / 얼굴 일부만 보임 / 한쪽 어깨 가림 / 전신 보임 / 카메라 사선 / 역광 / 어두운 조명 / 한 프레임씩 일시 가림 / 두 사람 등장 / 카메라 권한 거부를 확인한다. 요구 부위보다 **많이 보이는 경우는 허용**하되, 필요한 부위가 빠지면 판정과 타이머를 멈춘다.
3. 각 시나리오에서 기준 동작의 시작·진행·복귀, 보상 움직임, 필수 관절 신뢰도를 나란히 확인한다. 하나라도 위험한 ‘성공’ 또는 잘못된 교정이 나오면 해당 규칙은 실시간 코칭에 넣지 않는다. 허용 오판정률·지연·반복 횟수는 실제 데이터로 결정한다.
4. `정상`, `오류`, `가림/화면 밖`, `다른 사람/복수 인물`, `추론 불안정`, `아바타 로드 실패`마다 다음 Story의 결정적 재생 픽스처를 만든다. **가림과 실패는 항상 성공·타이머 증가가 0**이어야 한다. 픽스처는 개발/테스트 전용이며 출시에 판정 우회 장치를 넣지 않는다.

촬영 결과가 나오기 전에는 #1도 **시범 애니메이션의 최종 각도·유지 시간·교정 문구를 확정하지 않는다**. 진단·치료·체형 교정 효과·‘올바른 관절 전체를 측정했다’는 표현을 사용하지 않는다.
