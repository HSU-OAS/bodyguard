## 용어

| 용어 | 뜻 |
|---|---|
| **기준선** | 사용자가 보정 화면에서 찍은 자신의 정자세 값. 모든 판정의 기준 |
| **지표** | 자세를 숫자로 나타낸 값. 목 전방, 어깨 좌우 기울기, 상체 전방 굴곡 3종 |
| **편차** | 지금 지표 값과 기준선의 차이 |
| **이탈** | 편차가 임계값을 넘은 상태가 일정 시간 이어진 것 |
| **측정 불가** | 관절이 안 보이거나 사람이 여럿이라 판정하지 않는 상태 |
| **가시성 (인식 확실도)** | MediaPipe가 관절마다 주는 0~1 점수. 그 관절이 가려지지 않고 정말 보인다고 얼마나 확신하는지. 화면에는 "인식 확실도"로 보여준다 |
| **화면 밖 관절** | 카메라 화면 밖에 있어 MediaPipe가 위치를 짐작한 관절. 가시성이 높게 나와도 쓰지 않는다 |
| **1분 요약** | 1분 동안의 지표 평균·이탈 시간 등을 묶은 기록. 서버에는 이것만 올라간다 |
| **뒤 탭** | 측정 중인 Bodyguard 탭이 다른 창이나 탭에 가려진 상태 |
| **유지형 / 반복형** | 자세를 N초 버티면 통과하는 스트레칭 / 동작을 N회 반복하면 통과하는 스트레칭 |

## 1. 제품 개요

성별·직업과 관계없이 스트레칭이 필요한 사람이 노트북 웹캠 하나로 신체 움직임을 확인하고, 추천받거나 동작을 직접 골라, 기준 동작과 내 움직임의 3D 아바타를 보며 코칭받고 기록을 남기는 웹 서비스다. 뷰티·미용은 첫 출시 이후 별도 범위다.
상세는 `product-brief.md`, 판단 기준은 `constitution.md`.

**구성 요소 3개** — 브라우저 앱(React), API 서버(FastAPI), DB(PostgreSQL)
→ 원문 7, 15, 46 · 스택과 버전은 ADR-0015

영상은 브라우저 밖으로 나가지 않는다. 서버에는 1분 요약만 올라간다. → 원문 8, 34
의학적 진단을 하지 않는다. → 원문 5, 8

## 2. 기능 요구사항

### 2.1 측정 (FR-M)

#### FR-M-01 측정 시작과 표시
웹을 켜 둔 동안만 잰다. 페이지를 닫으면 측정도 끝난다.
→ 원문 30

```
WHEN 사용자가 '측정 시작'을 누르면
THE SYSTEM SHALL 카메라를 켜고 측정을 시작한다

WHEN 측정 중이면
THE SYSTEM SHALL 화면에 '측정 중' 표시를 항상 띄운다

WHEN 사용자가 '측정 중지'를 누르거나 페이지를 닫으면
THE SYSTEM SHALL 카메라를 끄고 측정을 멈춘다
```

`[PO 제안]` Q-20 — 접속만으로는 카메라를 켜지 않는다. 시작 버튼으로 켠다.

#### FR-M-02 관절 좌표 추출 — 영상은 브라우저 안에서 끝난다
과목 PRD F-01.
→ 원문 2, 8, 18

```
WHEN 카메라 프레임이 들어오면
THE SYSTEM SHALL 브라우저 안에서 관절 33점을 추출하고 프레임을 바로 버린다

WHEN 관절 좌표로 지표를 계산하고 나면
THE SYSTEM SHALL 좌표를 저장하지 않고 버린다

WHEN 어떤 경우에도
THE SYSTEM SHALL 영상 프레임·이미지·관절 좌표를 서버로 보내지 않는다
```

#### FR-M-03 기준선 보정
체형과 카메라 위치가 사람마다 달라서, 남의 정자세가 아니라 **내 정자세**를 기준으로 삼는다. 과목 PRD F-02.

```
WHEN 사용자가 보정을 시작하면
THE SYSTEM SHALL 정자세 아바타와 체크리스트(등 붙이기·화면 정면·어깨 힘 빼기)를 보여준 뒤 3초 동안 지표를 모은다

WHEN 3초 동안 지표가 크게 흔들리면
THE SYSTEM SHALL 보정을 실패 처리하고 다시 찍게 한다

WHEN 보정 때 어깨 좌우 기울기가 수평에서 5도 이상 벗어나 있으면
THE SYSTEM SHALL 저장은 허용하되 "어깨가 기울어져 있어요"라고 알린다

WHEN 사용자가 설정에서 재보정을 실행하면
THE SYSTEM SHALL 새 기준선을 저장하고 이후 판정에 사용한다. 이전 기준선은 기록 해석을 위해 남긴다
```

> 한계: 보정 때 구부정하게 앉으면 그 자세가 기준이 된다. 절대 기준으로 확인할 수 있는 건 어깨 기울기뿐이다.

#### FR-M-04 자세 지표 3종 `[미정 Q-05]`
과목 PRD F-03. 목 전방, 어깨 좌우 기울기, 상체 전방 굴곡.
→ 원문 10

정면 웹캠에서는 목과 상체의 "옆에서 본 각도"가 그대로 나오지 않는다. 계산식은 `design.md` §5의 `[PO 제안]`이며 실측(M-3, M-4) 후 확정한다.
상체 지표는 노트북 웹캠에서 못 쓸 수도 있다. 그 경우 지표는 2개가 된다.

```
WHEN 관절이 추출되면
THE SYSTEM SHALL 지표별로 기준선 대비 편차를 계산한다

WHEN 지표 계산에 필요한 관절의 가시성이 기준 미만이면
THE SYSTEM SHALL 해당 지표를 '측정 불가'로 둔다. 추정값을 채우지 않는다
```

#### FR-M-05 판정과 표시
메인 화면은 자세를 계속 추적하다가 정자세가 되면 "좋음"을 보여준다.
판정은 3단계이고, 출시에선 확인 가능한 피드백을 **내 움직임 아바타**에 표시한다(FR-A-01). 스켈레톤은 개발 시제품이다.
→ 원문 13, 43

| 상태 | 뜻 | 사용자 아바타 피드백 |
|---|---|---|
| 좋음 | 편차가 주의 임계값 안 | 초록 |
| 주의 | 편차가 주의 임계값을 넘음 | 주황 |
| 이탈 | 편차가 이탈 임계값을 넘은 채 3초 이상 | 빨강 |
| 내부 판정 보류 | 관절 미검출·여러 명 | 해당 판정·타이머 중지, 필요한 경우 촬영 위치 안내 |

임계값은 팀이 정한 값을 모두에게 쓴다. 사용자가 민감도를 바꾸는 기능은 두지 않는다(원문 44).
색을 구분하기 어려운 사용자를 위해 상태 글자(좋음·주의·이탈)도 함께 보여준다 `[PO 제안]`.

```
WHEN 자세가 바뀌면
THE SYSTEM SHALL 1초 안에 화면의 지표 표시와 확인 가능한 아바타 피드백을 바꾼다

WHEN 편차가 임계값을 넘은 상태가 3초 이상 이어지면
THE SYSTEM SHALL 해당 지표를 '이탈'로 판정한다

WHEN 이탈 상태에서 편차가 임계값의 80% 안으로 돌아와 2초 이상 유지되면
THE SYSTEM SHALL 이탈을 해제한다
```

> 화면 피드백(1초)과 판정(3초)을 나눈 이유: 화면은 즉시 반응해야 하지만, 알림과 기록에 쓰는 판정이 순간 움직임에 흔들리면 안 된다.
> 임계값·지속 시간은 `[PO 제안]` Q-06.

#### FR-M-06 뒤 탭 측정
켜 둔 채 다른 창으로 가도 잰다.
→ 원문 31

```
WHEN 측정 중인 탭이 가려지면
THE SYSTEM SHALL 약 1초에 한 번 간격으로 측정을 이어간다

WHEN 탭이 다시 보이면
THE SYSTEM SHALL 원래 속도로 돌아간다

WHEN 브라우저가 뒤 탭 측정을 막으면
THE SYSTEM SHALL 가려져 있는 동안 측정을 멈추고, 다시 보일 때 이어서 잰다
```

> 되는지 먼저 확인해야 한다(M-1). 막히면 마지막 WHEN이 기본 동작이 되고, 가려진 동안 자세 이탈 알림은 오지 않는다.

#### FR-M-07 측정 불가 처리
과목 PRD 예외 1.

```
WHEN 관절이 5초 이상 검출되지 않으면
THE SYSTEM SHALL 조명·거리 안내를 띄우고 판정을 일시정지한다

WHEN 화면에 두 명 이상이 잡히면
THE SYSTEM SHALL "한 명만 화면에 나오게 해 주세요"를 띄우고 판정하지 않는다
```

`[PO 제안]` 두 명 처리.

필요한 관절이 화면 밖이면 부드럽게 안내해서 그 자세를 하도록 유도한다 (원문 50).

```
WHEN 지금 하는 일에 필요한 관절이 화면 밖이거나 잘 안 보이는 상태가 1.5초 이어지면
THE SYSTEM SHALL 그 자세를 하도록 부드럽게 안내한다

WHEN 필요 없는 관절(앉아 있을 때의 엉덩이·다리)이 화면 밖이면
THE SYSTEM SHALL 안내하지 않는다

WHEN 관절이 화면 밖에 있으면
THE SYSTEM SHALL 가시성 점수와 상관없이 그 관절을 그리지도, 판정에 쓰지도 않는다
```

| 하는 일 | 필요한 관절 | 안내 |
|---|---|---|
| 앉은 자세 측정 | 코·귀·어깨 | "머리와 어깨가 화면 안에 들어오게 앉아 주세요" |
| 전신이 필요한 동작 | 어깨·엉덩이·무릎·발목 | "일어나서 한 걸음 뒤로 물러나 주세요" |
| 사람이 안 보임 | — | "카메라 앞에 앉아 주세요" |

문구와 1.5초 기준은 `[PO 제안]`이다. 브라우저 알림이 아니라 화면 안에서 천천히 나타났다 사라진다.

#### FR-M-08 성능 저하
과목 PRD 예외 3.

```
WHEN 화면이 보이는 상태에서 측정 속도가 10초 이상 15fps 미만이면
THE SYSTEM SHALL 입력 해상도를 낮추고, 그래도 미달이면 사용자에게 알린다
```

### 2.2 두 3D 아바타 (FR-A)

출시 화면에는 사용자가 선택한 남성 또는 여성 외형의 **기준 동작 아바타**와 **내 움직임 아바타**를 나란히 띄운다. 첨부 참조 이미지의 얼굴 없는 흰색 인체 형태와 부드러운 관절 움직임이 시각 기준이다. 현재 스켈레톤·마네킹 데모는 개발용 시제품이며 출시 아바타가 아니다. 모델·리그·기준 애니메이션은 Blender에서 새로 제작한다.

#### FR-A-01 내 움직임과 피드백
내 움직임 아바타는 카메라로 확인 가능한 관절만 따라간다. 과목 PRD F-04의 "어긋난 부위를 색상으로 구분"은 실제로 판정 가능한 오류 부위에 적용한다.
기존 데모의 둥근 머리·점 눈·볼터치·표정 추적은 시제품 구현 기록이다 (원문 55·57, ADR-0017). 출시 아바타는 참조 이미지처럼 얼굴이 없는 인체 형태를 따른다. 얼굴 추론값을 사용할 경우에도 관찰·판정 가능성을 별도로 검증한다.
→ 원문 14, 43, 55, 57

```
WHEN 측정 중이면
THE SYSTEM SHALL 확인 가능한 내 움직임을 3D 아바타에 반영한다

WHEN 지표 상태가 바뀌면
THE SYSTEM SHALL 검증된 규칙으로 판정한 부위를 좋음·주의·이탈 색과 설명으로 안내한다

WHEN 필수 관절을 확인할 수 없으면
THE SYSTEM SHALL 그 동작의 통과 판정과 타이머를 멈추고 필요한 촬영 위치만 간결히 안내한다. 확인 불가 부위에 별도 색을 칠하지 않는다

WHEN 어느 지표에도 연결되지 않은 부위(팔 등)이면
THE SYSTEM SHALL 중립색으로 둔다
```

| 지표 | 칠하는 부위 |
|---|---|
| 목 전방 | 머리·목 (머리에 입히는 방법은 `[미정 Q-30]`) |
| 어깨 좌우 기울기 | 어깨선 |
| 상체 전방 굴곡 | 몸통(어깨~엉덩이) |

#### FR-A-02 기준 동작 아바타
측정 중에는 기준 자세를, 스트레칭 중에는 근거를 확인한 올바른 수행 과정을 보여준다.
→ 원문 3, 14, 16, 35 · 과목 PRD 예외 4

```
WHEN 측정 중이면
THE SYSTEM SHALL 사용자 아바타 옆에 기준 자세 아바타를 표시한다

WHEN 기준 아바타 또는 애니메이션 로드에 실패하면
THE SYSTEM SHALL 코칭을 시작하거나 성공 처리하지 않고 재시도 안내를 표시한다

WHEN 스트레칭을 시작하면
THE SYSTEM SHALL 해당 동작의 시작·중간·끝과 복귀를 자연스러운 애니메이션으로 보여준다
```

모델 에셋·라이선스와 동작별 리그 검증은 `[미정 Q-11]`. 기준 아바타에 사용자 판정 색을 칠하지 않는다.

#### FR-A-03 내 동작을 따라 움직이는 아바타 (첫 출시 필수)
출시에서는 시제품 스켈레톤 대신 선택한 외형의 아바타가 확인 가능한 움직임을 따라간다. 리그 관절이 많아도 단일 웹캠으로 볼 수 없는 회전을 정확한 측정값으로 주장하지 않는다.

```
WHEN 사용자가 아바타를 고르면
THE SYSTEM SHALL 확인 가능한 몸·손 관절을 그 아바타에 지연과 떨림을 억제해 반영한다

WHEN 필요한 관절이 가려지거나 화면 밖이면
THE SYSTEM SHALL 그 관절을 올바른 자세인 것처럼 보정하거나 통과 판정에 사용하지 않는다
```

정밀 리타게팅 방식과 카메라 관찰 범위는 `[미정 Q-28]`로 실측 후 결정한다. 개인 체형과 동일한 신체를 재구성한다는 약속은 하지 않는다.

#### FR-A-04 손가락과 손 제스처 (현재 데모)
손가락 21점을 스켈레톤 손목에 이어 그리고, 엄지척 같은 제스처를 알아보는 것은 현재 시제품 기능이다 (원문 53, 54, ADR-0016). 출시 아바타의 손 움직임·코칭에 필요한 범위는 동작별 촬영 검증으로 정한다.

```
WHEN 손이 화면에 보이면
THE SYSTEM SHALL 손가락 21점을 몸의 손목에 이어 2D·3D로 그린다

WHEN 손가락 모델이 붙은 손이면
THE SYSTEM SHALL 몸 모델이 주는 거친 손 점(엄지·검지·새끼 뿌리)을 그리지 않는다

WHEN 제스처(엄지척, 엄지 아래, 주먹, 편 손바닥, 검지 위로, 브이, 사랑해)를 60% 이상 확신하면
THE SYSTEM SHALL 어느 손의 어떤 제스처인지 보여준다
```

제스처를 제품에서 무엇에 쓸지는 `[미정 Q-29]`이다. 지금은 표시만 한다.

### 2.3 알림 (FR-N)

→ 원문 2, 32 · ADR-0010

#### FR-N-01 자세 이탈 알림
```
WHEN 이탈 상태가 5분 이어지면
THE SYSTEM SHALL 스트레칭을 권하는 알림을 띄운다

WHEN 자세 이탈 알림을 띄운 뒤 10분이 지나기 전이면
THE SYSTEM SHALL 같은 알림을 다시 띄우지 않는다
```

30초 미만 바로 앉은 것은 이탈이 끊긴 것으로 보지 않는다. 세는 방식은 `[PO 제안]` Q-07.

#### FR-N-02 오래 앉음 알림
```
WHEN 화면에 사람이 보이는 상태가 50분 이어지면
THE SYSTEM SHALL 자세와 상관없이 스트레칭을 권하는 알림을 띄운다

WHEN 사람이 3분 넘게 보이지 않거나, 스트레칭을 마치거나, 이 알림을 띄우면
THE SYSTEM SHALL 앉은 시간을 0부터 다시 센다
```

카메라는 앉았는지 섰는지 모른다. "보이면 앉아 있음"은 `[PO 제안]` Q-08.

#### FR-N-03 알림 기준 설정
```
WHEN 사용자가 설정에서 자세 이탈 시간(기본 5분)이나 오래 앉음 시간(기본 50분)을 바꾸면
THE SYSTEM SHALL 바뀐 값으로 알림을 판정한다

WHEN 사용자가 두 알림 중 하나를 끄면
THE SYSTEM SHALL 그 알림을 띄우지 않는다
```

설정에서 바꿀 수 있는 건 알림 시간, 켜기·끄기, 소리뿐이다. 판정 민감도(임계값)는 팀이 정한 값을 쓴다(원문 44).

#### FR-N-04 알림 방식 `[PO 제안]` Q-21
```
WHEN 알림 조건이 충족되면
THE SYSTEM SHALL 브라우저 알림과 화면 안 알림을 함께 띄운다

WHEN 사용자가 소리를 켜 두었으면
THE SYSTEM SHALL 알림음을 함께 낸다. 기본은 꺼짐이다
```

#### FR-N-05 알림 권한
```
WHEN 첫 측정 전이면
THE SYSTEM SHALL 왜 필요한지 설명한 뒤 브라우저 알림 권한을 요청한다

WHEN 사용자가 알림 권한을 거부하면
THE SYSTEM SHALL 화면 안 알림만 띄우고, 다른 창에서는 알림을 못 본다고 알린다
```

### 2.4 스트레칭 (FR-S)

→ 원문 2, 3, 4, 12, 13 · 과목 PRD F-05

#### FR-S-01 스트레칭 목록 `[PO 제안]` Q-09
아래 8개는 **검증 후보**이며 출시 목록이나 안전한 통과 기준이 아니다. 표의 각도·시간은 기존 시제품의 초기 가설로, 출처·올바른 수행법·주의점·실제 노트북 촬영을 확인하기 전에는 제품 판정에 사용하지 않는다. 각 후보는 `실시간 코칭 / 안내만 / 제외`로 분류한다.

| # | 동작 | 부위 | 방식 | 통과 조건 (정면 판정) |
|---|---|---|---|---|
| 1 | 목 옆으로 기울이기 (좌·우) | 목 | 유지 15초 × 양쪽 | 두 귀를 잇는 선이 25° 이상 기울고, 어깨 기울기는 5° 안 |
| 2 | 턱 당기기 | 목 | 반복 5회, 회당 3초 | 목 지표가 기준선보다 뒤쪽으로 일정 이상 이동 |
| 3 | 어깨 으쓱했다 내리기 | 어깨 | 반복 5회, 회당 3초 | 어깨 중점이 어깨 너비의 15% 이상 올라갔다가 돌아옴 |
| 4 | 팔 교차 어깨 늘이기 (좌·우) | 어깨 | 유지 15초 × 양쪽 | 손목이 몸 중심선을 넘어 반대쪽 어깨 바깥까지, 팔꿈치는 어깨 높이 근처 |
| 5 | 가슴 펴기 (W자) | 등·가슴 | 유지 15초 | 양 팔꿈치가 어깨 높이, 손목이 팔꿈치보다 위, 팔꿈치 간격이 어깨 너비의 1.5배 이상 |
| 6 | 팔 위로 뻗기 | 등 | 유지 10초 | 양 손목이 코보다 위, 팔꿈치 각도 150° 이상 |
| 7 | 옆구리 늘이기 (좌·우) | 허리 | 유지 15초 × 양쪽 | 양 손목이 머리보다 위, 어깨선이 15° 이상 기움 |
| 8 | 상체 비틀기 (좌·우) | 허리 | 유지 15초 × 양쪽 | 어깨 너비가 기준선보다 20% 이상 줄어듦 |

> 2번과 8번은 깊이 방향 움직임이라 정면 판정이 가장 불확실하다. M-4 결과가 나쁘면 다른 동작으로 바꾼다.
> 동작 선정과 유지 시간은 운동·재활 자료로 한 번 더 확인하는 게 좋다.

#### FR-S-02 수행 판정
버티기는 필요한 동작에만 쓴다(원문 13).

```
WHEN 유지형 동작에서 통과 조건이 충족되면
THE SYSTEM SHALL 유지 타이머를 시작하고 남은 시간을 보여준다

WHEN 유지 도중 통과 조건이 1초 넘게 깨지면
THE SYSTEM SHALL 타이머를 멈추고 조건이 다시 충족되면 이어서 센다

WHEN 반복형 동작에서 조건 충족 후 원위치 복귀가 감지되면
THE SYSTEM SHALL 반복 횟수를 1 올린다

WHEN 판정에 필요한 관절이 보이지 않으면
THE SYSTEM SHALL 타이머와 판정을 멈추고 "팔이 화면에 들어오게 해 주세요"처럼 필요한 촬영 위치만 알린다. 보이지 않은 구간을 성공으로 세지 않는다
```

#### FR-S-03 아바타 시범
```
WHEN 스트레칭이 시작되면
THE SYSTEM SHALL 기준 아바타가 검증된 수행 과정과 복귀를 보여주고, 내 아바타에는 확인 가능한 오류 부위의 수정 안내를 표시한다
```

시범 동작 데이터는 `[미정 Q-11]`. 근거와 실제 관찰 조건을 확인하지 못한 동작은 실시간 코칭 목록에 넣지 않는다.

#### FR-S-04 건너뛰기
과목 PRD 예외 5. 하지 않은 스트레칭은 한 것으로 치지 않는다.

```
WHEN 사용자가 스트레칭을 건너뛰면
THE SYSTEM SHALL 수행 처리하지 않고 '건너뜀'으로 기록한다
```

#### FR-S-05 시작 경로
```
WHEN 사용자가 알림을 누르면
THE SYSTEM SHALL 알림 종류에 맞는 스트레칭 세트를 바로 시작한다

WHEN 사용자가 스트레칭 화면에서 동작을 고르면
THE SYSTEM SHALL 알림과 상관없이 해당 동작을 시작한다
```

알림 종류별 세트 구성(자세 이탈이면 목·어깨 위주 등)은 `[PO 제안]`이며 Q-09와 함께 정한다.

#### FR-S-06 추천 또는 직접 선택 (첫 출시 필수)

```
WHEN 사용자가 동작을 직접 고르면
THE SYSTEM SHALL 출처·수행법·주의점과 촬영 범위를 확인한 동작 목록에서 선택하게 한다

WHEN 사용자가 추천받기를 고르면
THE SYSTEM SHALL 웹캠으로 관찰 가능한 정보와 사용자가 명시한 목적에 근거해 동작을 제안하고 그 이유를 설명한다

WHEN 추천에 필요한 정보가 부족하면
THE SYSTEM SHALL 신체 상태를 추측하거나 질환을 판단하지 않고 직접 선택 경로를 제공한다
```

추천 규칙과 출시 동작 수는 근거 조사·카메라 실측 후 정한다. 미용·마사지 동작은 첫 출시 목록에 넣지 않는다.

### 2.5 기록 (FR-R)

→ 원문 5, 16, 34 · 과목 PRD F-06~F-08 · ADR-0003

#### FR-R-01 1분 요약
```
WHEN 로그인한 사용자의 측정이 1분 단위로 끝날 때마다
THE SYSTEM SHALL 지표별 평균 편차·이탈 시간, 측정 시간, 측정 불가 시간, 사람이 보인 시간, 사용한 기준선을 1분 요약으로 만든다

WHEN 1분 요약을 만들고 나면
THE SYSTEM SHALL 그 1분의 개별 측정값을 버린다
```

#### FR-R-02 업로드 `[PO 제안]`
```
WHEN 1분 요약이 쌓이면
THE SYSTEM SHALL 몇 분 단위로 묶어 서버에 올린다

WHEN 서버에 연결할 수 없으면
THE SYSTEM SHALL 요약을 브라우저에 보관했다가 연결이 돌아오면 올린다

WHEN 같은 분의 요약이 두 번 올라오면
THE SYSTEM SHALL 하나만 남긴다
```

#### FR-R-03 대시보드
과목 PRD F-06.

```
WHEN 사용자가 대시보드를 열면
THE SYSTEM SHALL 지표별 이탈 비율과 평균 편차를 일·주 단위로 보여준다

WHEN 사용자가 대시보드를 열면
THE SYSTEM SHALL 스트레칭 수행·건너뜀 횟수와 알림 횟수를 함께 보여준다
```

#### FR-R-04 변화 탐지 `[PO 제안]` `[미정 Q-12]`
과목 PRD F-07. 평소 범위를 벗어난 날을 찾아 보여준다.
→ 원문 16

```
WHEN 측정 시간이 60분 이상인 날이 7일 쌓이지 않았으면
THE SYSTEM SHALL 변화 탐지를 하지 않고 "기록이 더 필요해요"를 보여준다

WHEN 어떤 날의 지표가 최근 14일의 평소 범위를 벗어나면
THE SYSTEM SHALL 대시보드에 그날을 표시한다

WHEN 변화를 표시할 때
THE SYSTEM SHALL "평소보다 목 이탈 비율이 높았던 날"처럼 측정값으로만 말한다. 원인이나 질환을 말하지 않는다
```

#### FR-R-05 측정 리포트 PDF `[PO 제안]` `[미정 Q-13]`
과목 PRD F-08. 진료나 상담 때 보여줄 수 있는 측정 기록이다.
→ 원문 5, 8, 16

```
WHEN 사용자가 기간을 골라 리포트를 요청하면
THE SYSTEM SHALL 해당 기간의 측정 리포트를 PDF로 만들어 내려받게 한다

WHEN 리포트를 만들면
THE SYSTEM SHALL 첫 장에 "본 리포트는 의료 진단이 아니며, 카메라 기반 자세 측정 기록입니다"를 넣는다
```

담을 내용 `[PO 제안]`: 기간과 측정 시간, 지표별 일별 추이, 이탈 비율, 스트레칭 수행 기록, 변화 탐지 결과, 기준선 보정 날짜, 측정 방법 설명(정면 웹캠·기준선 대비).
첫 장에는 LLM이 쓴 한 단락 요약을 넣는다(FR-R-07).

#### FR-R-06 보정 전 구간 표시
과목 PRD 예외 2.

```
WHEN 기준선 없이 측정된 구간이 있으면
THE SYSTEM SHALL 대시보드와 리포트에 '보정 전' 구간으로 표시한다
```

#### FR-R-07 리포트 자연어 요약 (LLM)
리포트 숫자를 읽기 쉬운 한 단락으로 정리한다. 상용 LLM API를 쓴다.
→ 원문 8(AI 기능 ②), 41 · ADR-0013

```
WHEN 리포트를 만들면
THE SYSTEM SHALL 서버에서 리포트 기간의 집계 숫자만 LLM API에 보내 한 단락 요약을 받는다

WHEN LLM API에 요청을 보낼 때
THE SYSTEM SHALL 이름·이메일·계정 ID를 보내지 않는다

WHEN 요약에 입력에 없는 숫자, 질환명, 진단·치료 표현이 들어 있으면
THE SYSTEM SHALL 요약을 버리고 요약 없이 리포트를 만든다

WHEN LLM API 호출이 실패하거나 10초 안에 응답이 없으면
THE SYSTEM SHALL 요약 없이 리포트를 만든다

WHEN 같은 사용자가 같은 기간의 리포트를 다시 요청하면
THE SYSTEM SHALL 저장해 둔 요약을 다시 쓴다
```

- 모델: 후보 모델을 같은 테스트 입력으로 비교해 검사를 통과하는 것 중 가장 싼 것을 쓴다(원문 41). 후보·결제·하루 한도는 `[미정 Q-27]`
- 요약은 측정값을 설명만 한다. 원인을 추정하거나 병원을 권하거나 질환을 말하지 않는다 (ADR-0008)
- 시간 제한 10초와 요약 재사용은 `[PO 제안]`
- 외부 AI로 숫자가 간다는 고지는 개인정보 동의(Q-26)와 함께 개발 막바지에 정한다

### 2.6 계정 (FR-U)

→ 원문 33, 42 · ADR-0006. FastAPI에서 직접 만든다.

#### FR-U-01 구글 로그인
```
WHEN 사용자가 구글 로그인을 누르면
THE SYSTEM SHALL 구글 계정으로 가입 또는 로그인시킨다
```

#### FR-U-02 이메일 가입·로그인
```
WHEN 사용자가 이메일과 비밀번호로 가입하면
THE SYSTEM SHALL 비밀번호를 해시로만 저장한다

WHEN 이미 구글로 가입한 이메일로 이메일 가입을 시도하면
THE SYSTEM SHALL 이미 가입된 이메일임을 알리고 구글 로그인을 안내한다
```

같은 이메일의 구글·이메일 계정을 합칠지는 `[PO 제안]` — 합치지 않고 안내만 한다.

#### FR-U-03 메일 인증과 비밀번호 재설정
메일 인증은 필수다. 팀 Gmail로 보내고 서버에서 코드를 대조한다.
→ 원문 42

```
WHEN 사용자가 이메일로 가입하면
THE SYSTEM SHALL 6자리 인증 코드를 메일로 보내고, 코드를 확인하기 전에는 가입을 끝내지 않는다

WHEN 인증 코드가 10분을 넘겼거나 5번 틀리면
THE SYSTEM SHALL 그 코드를 무효로 하고 재발송을 안내한다

WHEN 재발송을 요청한 지 60초가 지나지 않았으면
THE SYSTEM SHALL 재발송을 막고 남은 시간을 알린다

WHEN 사용자가 비밀번호 재설정을 요청하면
THE SYSTEM SHALL 가입 여부와 상관없이 같은 안내("메일을 보냈어요")를 보여주고, 가입된 이메일에만 재설정 메일을 보낸다

WHEN 비밀번호가 재설정되면
THE SYSTEM SHALL 재설정 토큰을 무효로 하고 기존 로그인을 모두 끊는다
```

수치(6자리, 10분, 5회, 60초)는 `[PO 제안]`이다. 같은 IP·이메일의 가입·재발송 요청 횟수도 제한한다 (design §13).

#### FR-U-04 로그인 없이 쓰는 범위 (CEO 결정)
```
WHEN 로그인하지 않은 사용자가 시작 화면을 열면
THE SYSTEM SHALL 서비스 설명과 공개 아바타 미리보기를 보여준다

WHEN 로그인하지 않은 사용자가 개인 신체 확인·추천·코칭·기록을 열면
THE SYSTEM SHALL 로그인을 요청하고, 로그인 후 원래 시작하려던 흐름으로 돌아가게 한다
```

#### FR-U-05 기록 삭제와 탈퇴 `[PO 제안]` Q-17
```
WHEN 사용자가 기간을 골라 기록 삭제를 요청하면
THE SYSTEM SHALL 해당 기간의 요약·스트레칭·알림 기록을 삭제한다

WHEN 사용자가 탈퇴하면
THE SYSTEM SHALL 계정과 모든 기록을 즉시 삭제한다
```

디자인은 CEO의 2026-10-05 결정에 따라 **화이트·블루의 차분하고 전문적인 웹**으로 통일한다. 백색 바탕·네이비 제목·청회색 본문, 블루 주 행동·선택·링크·키보드 초점이 기준이다. 삭제·오류의 적색과 실제 판정 부위의 의미 있는 색은 구분해 유지한다. 의학적인 분위기는 의료 자격·진단·검증 완료를 의미하지 않는다. 세부 기준과 실제 검증은 [웹 디자인 계약](web-design.md)을 따른다.

#### FR-V-02 카메라 영상은 보여주지 않는다
→ 원문 49

```
WHEN 측정 중이면
THE SYSTEM SHALL 카메라 영상을 화면에 보여주지 않고, 기준 동작과 내 움직임의 두 3D 아바타를 보여준다

WHEN 사용자가 처음 자리를 맞출 때
THE SYSTEM SHALL 영상 대신 아바타와 간결한 문구로 해당 동작에 필요한 부위가 화면 안에 들어왔는지 안내한다
```

카메라 영상은 개발 빌드의 디버그 화면(FR-V-03)에서만 볼 수 있다. 자리 안내 방식은 `[PO 제안]` Q-20.

#### FR-V-03 디버그 패널 `[PO 제안]`
정량 목표를 재려면 초기부터 필요하다.

```
WHEN 개발 빌드에서 디버그 패널을 열면
THE SYSTEM SHALL 카메라 영상 위 2D 스켈레톤, fps, 관절 가시성, 원시 지표 값, 상태 전이를 보여준다

WHEN 배포 빌드이면
THE SYSTEM SHALL 디버그 패널을 노출하지 않는다
```
