# BODYGUARD 개발 운영 규칙

2026-10-01 · CEO 사전 승인 · 기존 2026-09-29의 건별 Git 승인 규칙을 아래 범위에서 대체한다.

## 승인 선언 원문

> 합의한 1~6단계 출시 범위 내에서 Story 시작, 명세·하네스 작성, 구현·검증, 커밋·푸시·PR 생성, 리뷰 보완과 다음 Story 진행을 사전 승인합니다. 기존 PR 번호별 병합 승인 규칙을 변경하여, 필수 검증 통과·미해결 P1/P2 없음·최신 diff와 충돌 여부 확인을 충족한 PR은 병합도 사전 승인합니다. 단계별 완료 기준은 그대로 유지하고 결과를 보고하세요. 범위·안전·개인정보의 중요한 변경, 비용·계정·시크릿·운영 DB migration·배포·출시는 별도 승인을 받으세요.

## 실행과 권한

2026-10-05 CEO 우선순위 변경: 진행 중인 아바타 제작·검증과 결과 정리만 마무리하고 동일 부위의 새 사이클은 시작하지 않는다. 2단계 잔여 문제는 [필수 보완 목록](stage2-carryover.md)에 보존하고 3→4→5→6단계 구현 후 최종 통합·수정에서 해결한다. 완료 게이트와 아래 승인 경계는 그대로다. 이 순서 변경을 위해 재승인을 요청하지 않는다.

- [1~6단계 출시 계약](release-plan.md)의 완료 기준은 그대로다. 단계별 증거를 보고하며 조건을 못 채우면 완료 처리하지 않는다.
- 기존 범위 안의 기술 결정·리뷰 보완은 CTO 권장안으로 진행하고 이유·검증을 해당 Story에 남긴다. 근거 없는 자세 임계값이나 효과를 기술 기본값으로 확정할 수는 없다.
- 매 Story/독립 버그/디자인 보완은 최신 origin/main에서 새 codex/* 브랜치/작업트리로 시작한다. 원본 로컬의 미커밋 변경은 보존한다.
- 한 PR에는 하나의 응집된 목적만 담는다. main 직접 푸시 금지, merge commit 방식, 로컬·원격 브랜치 자동 삭제 금지다.
- Story 시작·명세·하네스·구현·로컬 검증·커밋·푸시·PR 생성·리뷰 보완·다음 Story 진행은 건별 CEO 승인을 다시 요청하지 않는다.
- PR 병합은 아래 게이트를 실제 충족한 경우에만 사전 승인된다. GitHub의 무조건 자동 병합 예약이나 admin 우회는 사용하지 않는다.
- 중요한 범위·안전·개인정보 변경, 비용·외부 계정 생성/연결·시크릿 주입·운영 DB migration·서버/배포·출시는 별도 승인이다. 코드 병합은 운영 변경 승인이 아니다.
- 별도 승인은 실행 전에 권장안·정확한 대상/범위·비용·위험·복구 계획을 묶어 요청한다. 외부 연결 대기 중에도 독립적인 승인 범위 작업은 계속하되 단계 게이트를 건너뛰지 않는다.

## 병합 게이트

1. 해당 Story의 수용 기준과 필수 검증이 실제 통과했다. 실패/skip/미실행/모의 시험을 별도로 기록한다.
2. 실제 diff를 보안·성능·정확성·유지보수 관점에서 재검토하고 미해결 P1/P2가 없다. 리뷰의 발견·보완·재검증 결과를 PR에 남긴다.
3. 병합 직전 최신 main, PR diff, 승인 범위, HEAD, 충돌/mergeable 상태와 체크 결과를 다시 확인한다. 안전하게 병합 가능한 CLEAN 상태여야 한다.
4. 체크가 없으면 **체크 없음**을 명시한다. CI 부재를 필수 로컬 검증 생략의 근거로 쓰지 않으며 실패한 체크를 우회하지 않는다.
5. exact HEAD 조건으로 merge commit 병합 후 main 포함과 변경 내용·브랜치 유지를 확인한다.

## Story 결과 기록

PR 본문은 Summary / Verification / Excluded로 작성한다. 검증에는 실제 명령·결과·커밋, 모의/실제 환경, 미실행 항목을 구분한다. Story별 보고에는 PR·병합 커밋·구현 범위·수용 기준 검증·남은 의존성을, 단계별 보고에는 출시 계약 게이트에 대한 실제 증거를 포함한다.

명세 표는 실행형 하네스가 아니다. 가짜 카메라·메일 fixture·공급자 mock을 실제 촬영/외부 연결 완료로 세지 않는다. 전문가 검토만 남은 상태는 1~6단계가 실제 통과했을 때만 선언한다.

## 운영 규칙 기록 시점의 기준선

PR #1~4 main 병합 확인, 당시 기준 main d14ae68. [1단계 준비 게이트](stage1-gate.md)는 계약·근거·촬영 계획·Blender 착수 기준을 충족했다. 이 시점의 다음 구현은 [S2.1 계정·세션 API](stories/stage2-account-api.md)였다. **현재 진행 상태·다음 Story는 [tasks.md](tasks.md)와 [2단계 계약](stories/stage2-first-flow.md)을 읽는다.** 기록 시점의 미완료 상태를 현재 상태로 사용하지 않는다.

이 문서 Story는 운영 권한·문서 정합화만 포함하며 제품 구현·외부 연결·운영 작업을 하지 않는다. 로컬 링크·이전 승인 대기 문구·diff 검사와 PR 재검토를 필수 검증으로 둔다.
