# UHI BODYGUARD — 10주차 기능 구현 리뷰

기준일: 2026-11-06 · 팀: UHI · 서비스 유형: 웹

## 프로젝트와 공개 테스트

BODYGUARD는 노트북 웹캠으로 사용자의 움직임을 확인하고, 추천받거나 직접 고른 스트레칭을 시범 아바타와 사용자 아바타로 비교하도록 개발 중인 웹 서비스다. 질환을 진단하거나 치료하지 않는다. 여성·남성 아바타를 제공할 계획이며, 뷰티·미용은 첫 출시 후에 다룬다.

- [공개 저장소](https://github.com/HSU-OAS/bodyguard) · [프로젝트 헌장](../README.md) · [화면 설계 Figma](https://www.figma.com/design/8f6TiE81S5Cu2bjgTuHFeZ/BODYGUARD-%C2%B7-UI-%EC%84%A4%EA%B3%84?node-id=0-1)
- [외부 테스트 URL](https://hsu-oas.github.io/bodyguard/): 웹캠 추종과 **검수 후보** 아바타를 확인하는 별도 시제품. 자세 판정, 스트레칭 시범, 로그인, 기록 저장 및 서버 API는 제공하지 않는다. 실제 사람별 추종 품질은 검증 중이다. [검수본 설명](../bodyguard/pages-preview/README.md)
- 제품의 AI 접근은 **딥러닝**으로 분류한다. 제품은 사전 학습된 MediaPipe 포즈 모델을 활용한다. 개발 보조 도구의 종류와 제품의 AI 접근은 구분한다. 공유표의 최신 입력 여부와 제출값은 [제출 안내](07_repository_submission.md)를 확인한다.

## 현재 요구사항과 범위

| 첫 출시 목표 | 현재 판단 |
| --- | --- |
| 신체 확인과 스트레칭 추천 | 구현과 동작별 근거·촬영 가능성 검증 진행 중. 개인별 추천의 완성은 아니다. |
| 동작 직접 선택과 미리보기 | 선택 화면과 후보 미리보기 개발. 검증되지 않은 동작은 출시용으로 제공하지 않는다. |
| 두 3D 아바타 코칭 | 내 움직임과 기준 시범의 비교·피드백을 목표로 개발 중. 외형·추종·오류 판정·실측 검증이 남았다. |
| 계정·기록·데이터 관리 | 회원·계정, 선택형 기본 정보, 기록 조회·삭제 등의 로컬 구현과 시험을 진행했다. 실제 메일·Google 로그인 공급자와 운영 적용은 별도다. |
| 뷰티·미용, 자세 알림, PDF, LLM 요약, 변화 탐지 | 첫 출시 이후로 이월. 이전 문서에 남은 내용은 과거 요구사항이다. |

기존 수업용 [요구사항 초안](03_prd.md)은 과거 버전을 보존한다. 현재 출시 우선순위와 안전·검증 조건은 [출시 계약](../bodyguard/docs/release-plan.md), 동작의 출처와 카메라 한계는 [동작 근거](../bodyguard/docs/motion-evidence.md)를 따른다.

## WBS 및 기능별 진행 상태

이 표의 상태는 10주차 리뷰를 위한 개발 현황이며, 출시 단계 통과나 발표일정을 뜻하지 않는다. 날짜와 담당자를 확인하지 못한 항목은 임의로 기입하지 않았다.

| 작업 | 상태 | 실제로 된 것 | 남은 일 / 다음 확인 |
| --- | --- | --- | --- |
| 요구사항·설계 | 진행 중 | 제품 범위, 동작별 자료, 시스템 설계, 화면 설계 정리 | 수업 초안과 상세 문서의 남은 충돌 정리. [설계](../bodyguard/docs/design.md) |
| GitHub·공개 테스트 | 부분 완료 | 공개 저장소·프로젝트 헌장·GitHub Pages 검수 URL 제공 | 검수 페이지와 전체 서비스의 차이를 계속 표시. 최종 배포는 별도 승인 |
| 회원·계정·기본 정보 | 로컬 구현·검증 | 로그인·계정 복구·탈퇴 구조, 선택형 기본 정보 저장·삭제 | 외부 메일·Google 공급자 연결, 운영 DB 적용 및 실제 운영 시험. [기본 정보 Story](../bodyguard/docs/stories/figma-optional-profile.md) |
| 동작 선택·추천 | 개발 중 | 동작 목록·일부 후보 미리보기·추천 흐름 | 동작별 근거·웹캠 관찰 가능성·사용자 흐름 검증 |
| 3D 아바타·시범 | 개발 중 | Blender 제작 남녀 후보와 동작 애니메이션, 브라우저 검수 | 합의한 최종 외형·리깅·변형·노트북 성능 검증. 추가 제작은 현재 보류 |
| 사용자 추종·피드백 | 개발 중 | 검수 페이지의 웹캠 입력과 아바타 추종 후보, 개발 환경의 코칭 구성 | 실제 사람·체형·조명·촬영 범위별 정확도, 오류 피드백·시범 연동. 출시 가능한 판정으로 주장하지 않음 |
| 기록·데이터 관리 | 로컬 구현·검증 | 계정별 기록 저장·조회·삭제와 일·주 집계 | 검증된 실제 코칭 결과와 전체 사용자 흐름 연결 |
| 운영·출시·보안 | 진행 중 | 로컬 보안·복원 시험, 오픈소스 검토 및 공개 검수 페이지 | 운영 HTTPS 서비스, 라이선스 고지·복구·보안 검증. 운영 서비스 배포는 별도 승인 |
| 실제 사용성·전문가 검토 | 미완료 | 합성 입력과 시험 계정 기반 개발 검증 기록 | 실제 참여자 시험은 현재 보류. 모든 출시 기준 충족 후 전문가가 완성된 웹을 검토 |

상세 작업 내역과 당시 증거는 [개발 작업 기록](../bodyguard/docs/tasks.md)과 [검증 기록](../bodyguard/docs/review/)을 참고한다. 문서의 과거 날짜에 적힌 상태를 오늘 완료 상태로 확대하지 않는다.

## 오픈소스와 프로젝트 공개 전략

- GitHub 공개 저장소에 소스, 프로젝트 헌장, 요구사항·설계, 테스트 및 일부 제작 에셋과 검증 기록을 관리한다.
- 프로젝트 코드는 [MIT 라이선스](../LICENSE)다. MediaPipe, Three.js, Blender 및 모델·3D 에셋은 각각의 라이선스와 배포 조건을 확인한다. 프로젝트의 MIT 고지만으로 외부 의존성의 조건을 대신하지 않는다.
- 브랜치와 PR 단위로 변경을 검토하며 main 직접 푸시는 하지 않는다. 테스트와 실패·한계를 기록한다. [운영 규칙](../bodyguard/docs/operating-rules.md)
- 외부 검수 페이지는 시제품 범위를 알리고 제공한다. 서비스 전체 공개·운영 배포, 개인정보 고지와 라이선스 완료는 별도의 출시 작업이다.

## 주요 이슈와 위험

1. **단일 웹캠의 관찰 한계:** 관절이 가려지거나 프레임 밖에 있으면 잘못된 성공 판정을 내리지 않도록 한다. 깊이·보이지 않는 관절·통증은 단정할 수 없다.
2. **아바타와 자세 기준:** 검수 후보는 최종 에셋이 아니다. 동작별 올바른 시범과 판정의 근거, 실제 사람 대상 정확도 검증이 필요하다.
3. **공개 테스트의 범위:** 외부 URL은 웹캠·후보 아바타 검수용이다. 전체 서비스·의학 진단·완성된 코칭 시연으로 설명하지 않는다.
4. **성능·호환성:** 15fps 이상, 피드백 지연 1초 이내, 육안 판정 대비 일치율 80% 이상은 발표 자료의 목표이며 달성 실측치가 아니다.
5. **개인정보·운영:** 영상과 원시 관절 좌표는 브라우저 밖으로 보내거나 저장하지 않는 설계다. 계정 정보와 기록의 저장·삭제, 보관·백업 정책과 외부 연결은 출시 전에 검토한다.
6. **라이선스:** 프로젝트 라이선스와 외부 코드·모델·에셋의 고지를 구분하고 미확인 항목은 출시 전에 해결한다. [라이선스 검토](../bodyguard/docs/stage5-license-inventory-runbook.md)

## 수업 리뷰에서 설명할 핵심

- 현재 보여주는 것은 웹캠 추종 **검수 시제품**이며, 실제 움직임 추종과 정확도는 환경에 따라 실패할 수 있다.
- 목표는 두 아바타로 시범과 사용자 동작을 비교하는 것이다. 완성된 올바른 판정이나 치료 효과를 주장하지 않는다.
- 웹캠 영상과 원시 좌표의 비저장·비전송을 원칙으로 한다. 계정과 수행 기록은 별도 관리 대상이다.
- [Playwright E2E 안내](06_e2e_test_guide.md)에서 가짜 카메라 시험과 실제 사람 검증의 차이를 설명할 수 있다.
