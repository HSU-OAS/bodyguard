# BODYGUARD 오픈소스 E2E 테스트 안내

기준일: 2026-11-06. 이 문서는 11주차 수업의 오픈소스 E2E 테스트 가이드·시연을 준비하기 위한 자료다. 교육 영상 시청이나 수업 참석을 완료했다는 기록이 아니다.

## E2E 테스트란?

사용자처럼 브라우저에서 버튼을 누르고 화면과 결과를 확인하는 자동화 테스트다. BODYGUARD는 오픈소스 [Playwright](https://playwright.dev/)를 사용해 브라우저를 실행하고, 웹캠 시작·중지 등의 흐름을 반복 확인한다. Vitest 단위 테스트, 서버·DB 테스트와 구분한다.

## 시연할 테스트

[측정 화면 E2E 코드](../bodyguard/frontend/e2e/demo.spec.ts)는 다음을 확인한다.

1. 개발용 측정 화면을 열고 측정 시작을 누른다.
2. **가짜 카메라**와 추론 루프가 시작되며, 사람이 보이지 않으면 촬영 안내가 나오는지 확인한다.
3. 중지 후 카메라 트랙이 종료되는지, 다시 시작하고 페이지를 떠날 때도 정리되는지 확인한다.

이는 카메라 자원 관리·화면 흐름을 확인하는 시험이다. 가짜 카메라에는 사람이 없으므로 실제 인체 추종 정확도, 올바른 스트레칭 여부, 실제 노트북 성능이나 의학적 타당성을 검증하지 않는다.

## 준비 및 실행

Node.js 24, pnpm 12, Chrome과 프로젝트 의존성이 필요하다. `pnpm dev`·빌드와 E2E의 자산 준비 스크립트는 필요한 MediaPipe 모델이 없으면 공식 저장소에서 내려받는다. 네트워크 연결이 필요할 수 있으며 설치·다운로드 전 [프런트엔드 안내](../bodyguard/frontend/README.md)를 확인한다.

```bash
cd bodyguard/frontend
pnpm install --frozen-lockfile
pnpm test:e2e
```

기본 [Playwright 설정](../bodyguard/frontend/playwright.config.ts)은 로컬 서버를 별도로 실행하고 Chrome의 가짜 카메라를 사용한다. 실패하면 터미널에 나온 테스트 이름·실패 이유와 환경을 확인한다. 테스트 시작 전 이미 사용 중인 다른 서버나 데이터를 종료하지 않는다.

계정·DB 통합 테스트는 별도의 격리 백엔드 하네스와 전용 시험 DB가 필요하다. 기본 명령으로 운영 계정이나 운영 DB를 연결하지 않는다. 자세한 조건은 [백엔드 안내](../bodyguard/backend/README.md)와 [계정 테스트 설정](../bodyguard/frontend/playwright.account.config.ts)을 확인한다.

## 실행 확인 — 2026-11-06

로컬 Chrome과 가짜 카메라를 사용해 `e2e/demo.spec.ts` **1건 통과**를 확인했다. 실제 사람 추종이나 계정 서버 시험은 아니다. 시험 중 백엔드가 실행되지 않아 `/api/v1/me` 연결 거부 로그가 있었으며, 기본 측정 테스트 자체는 이를 계정 기능 성공으로 간주하지 않는다.

검증 환경에서 기존 설치를 심볼릭 링크로 재사용했을 때 `pnpm test:e2e`는 의존성 디렉터리 조건 때문에 시작하지 못했다. 같은 기존 설치의 Playwright를 직접 호출해 아래 명령으로 재실행했다. 정상적인 새 설치 환경에서 위 `pnpm test:e2e` 명령의 성공을 이번 시험으로 보장하는 것은 아니다.

```bash
PATH="$PWD/node_modules/.bin:$PATH" ./node_modules/.bin/playwright test --config playwright.config.ts
```
